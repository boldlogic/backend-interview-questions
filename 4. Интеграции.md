### Kafka / RabbitMQ?
**Частота:** 14/98
**Темы:** #integration #messaging

**Эталон на собесе:**
Kafka лучше подходит для потока событий, высокой пропускной способности, повторного чтения и групп потребителей. RabbitMQ удобен как брокер задач и сообщений с обменниками, очередями и ключами маршрутизации.

**Подробности:**
- Kafka хранит журнал по разделам; группа потребителей делит разделы между обработчиками.
- RabbitMQ маршрутизирует сообщения через обменник в очередь.

### Kafka: topic, partition, offset, consumer group
**Частота:** 9/98
**Темы:** #integration #messaging #kafka

- **Topic** — логический канал/«тема», куда producer пишет события.
- **Partition** — часть топика, append-only log на диске; порядок сообщений гарантирован внутри партиции; сообщения с одним key попадают в одну партицию.
- **Offset** — позиция сообщения в партиции; consumer сам хранит offset и может перечитывать данные.
- **Consumer group** — группа consumer'ов делит партиции между участниками; одну партицию в момент времени читает один consumer из группы; если consumer'ов больше, чем партиций — лишние простаивают.

### Семантики доставки: at-most-once / at-least-once / exactly-once
**Частота:** 5/98
**Темы:** #integration #messaging

- **At-most-once** — сообщение доставлено не более одного раза; возможна потеря, дубликатов нет.
- **At-least-once** — доставка минимум один раз; возможны дубликаты, потерь нет (retry, повторная отправка).
- **Exactly-once** — обработка ровно один раз; дорого по ресурсам; 
 
на практике часто at-least-once + идемпотентность/дедупликация по ключу.

### Kafka producer: acks и idempotent producer
**Частота:** 2/98
**Темы:** #integration #messaging #kafka

**Эталон на собесе:**
- **acks=0** — fire-and-forget: producer не ждёт подтверждения от брокера.
- **acks=1** — leader записал сообщение в локальный log.
- **acks=all (-1)** — подтверждение от всех in-sync replicas; выше надёжность, выше latency.
- **Idempotent producer** (`enable.idempotence=true`) — PID + sequence number; брокер дедуплицирует повторные отправки в рамках сессии producer'а.

### Что такое синхронные и асинхронные вызовы?
**Частота:** 3/98
**Темы:** #integration #messaging

- **Синхронный** — клиент ждёт ответа от сервера и не продолжает работу, пока ответ не получен; когда нужен быстрый результат «здесь и сейчас».
- **Асинхронный** — клиент не блокируется; подходит для долгих или ресурсоёмких операций, когда мгновенный ответ не нужен.
- Реализация async: брокер сообщений, callback, polling статуса, фоновая goroutine после HTTP 202/OK.

### Выбор транспорта межсервисного взаимодействия: HTTP vs gRPC vs брокер
**Частота:** 1/98
**Темы:** #integration #architecture

- **HTTP/REST** — простота, широкая поддержка; синхронный вызов с низкой latency, когда нужен немедленный ответ.
- **gRPC** — строгий контракт из proto, codegen; синхронный RPC, типобезопасность, эффективнее JSON по сети.
- **Брокер (Kafka/RabbitMQ)** — eventual consistency, фоновая обработка; producer и consumer развязаны по нагрузке и темпу; надёжная доставка через очередь.
- Async можно построить и поверх HTTP (OK + polling/goroutine), но брокер удобнее при пиках, fan-out и гарантиях доставки.

### WSDL — описание веб-сервиса
**Частота:** 0/98
**Темы:** #integration

Язык описания веб сервиса. Перечисление функций, форматов, ответов и так далее.
Написан на XML.

WSDL (Web Services Description Language) — это язык описания веб-сервисов, который используется для определения структуры и функциональности веб-служб.
WSDL описывает, как взаимодействовать с веб-службой, включая:
- типы данных, которые используются в веб-службе;
- операции, которые можно выполнять с этими данными;
- форматы сообщений, которые используются для обмена данными между клиентом и сервером;
- расположение веб-службы (URL).
WSDL является основой для создания и использования веб-сервисов. Он позволяет разработчикам создавать приложения, которые могут взаимодействовать с другими приложениями через интернет. WSDL также используется для автоматического создания клиентских и серверных кода для веб-сервисов на различных языках программирования.
