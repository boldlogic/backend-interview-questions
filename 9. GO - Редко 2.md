## Где в памяти размещается массив, а где слайс?
**Частота:** 1/84
**Темы:** #go/memory #go/slice #go/array
- [ ] Скорректировано
- [x] последний повтор ✅ 2026-06-27

**Эталон на собесе:**
- **Массив**: размещение на стеке или в куче решает **escape analysis** — если массив не «убегает» из функции, часто на стеке.
- **Слайс**: заголовок (ptr, len, cap) может быть на стеке; **базовый массив** — на куче, если slice возвращается, сохраняется в heap-struct или capacity большой.
- До Go 1.25: маленький slice без escape иногда с буфером в кадре; при return — копия данных на кучу.

## Операции и параметры канала
**Частота:** 1/84
**Темы:** #go/channel
- [ ] Скорректировано
- [ ] последний повтор

**Что ожидают на собесе:**
Основные операции с каналами:
- создание (`make`);
- отправка (`<-`);
- получение (`<-`);
- закрытие (`close`);
- чтение через `range`;
- ожидание нескольких каналов через `select`.
Дополнительно можно получить текущую длину буфера (`len`) и его емкость (`cap`) для буферизированных каналов.
**Эталон на собесе:**
- `make(chan T)` / `make(chan T, n)` — создание небуферизованного или буферизованного канала.
- Отправка `ch <- v`, получение `<-ch` или `v := <-ch`; `close(ch)` — закрытие (обычно отправителем).
- `for v := range ch` — чтение до закрытия; `select` — мультиплексирование нескольких каналов.
- `len(ch)`, `cap(ch)` — текущая заполненность и ёмкость буфера (для buffered).
У канала есть три основные характеристики:
- **тип элементов** (`chan int`, `chan User`);
- **направление** (`chan`, `<-chan`, `chan<-`);
- **емкость буфера** — небуферизированный (`cap == 0`) или буферизированный (`cap > 0`).

## Системные вызовы (syscall) в Go?
**Частота:** 1/84
**Темы:** #go/scheduler #go/runtime
- [ ] Скорректировано
- [ ] последний повтор

Системный вызов — переход из user mode в kernel mode: файловый I/O, часть сетевых операций, таймеры и т.д. Для потока ОС это дорогое переключение контекста.
В Go горутина на **блокирующем** syscall паркуется: связанный M может остаться в kernel, а P (логический CPU) передаётся другому M, чтобы другие G продолжали работу. После возврата из syscall G попадает в run queue (часто через global queue).
Сетевой I/O часто идёт через **netpoller** без долгой блокировки M на каждую операцию.


**Подробности:**
- После syscall: Memory arenas (runtime после syscall).
- События парковки G: канал, mutex, syscall, netpoll, GC safepoint, preemption.

## Структуры: порядок полей и выравнивание
**Частота:** 1/84
**Темы:** #go/types #go/memory
- [ ] Скорректировано
- [x] последний повтор ✅ 2026-06-27

Struct — именованный набор полей. 
Размер и alignment зависят от порядка полей (padding). 
Оптимизация: от большего alignment к меньшему уменьшает размер struct.

Процессор быстрее работает с данными, расположенными по определенным границам памяти.
Компилятор выравнивает поля структуры по требованиям архитектуры, добавляя padding между полями при необходимости. Неправильный порядок полей может увеличить размер структуры. Поэтому обычно поля располагают от самых больших по размеру к самым маленьким, чтобы уменьшить количество padding и снизить потребление памяти.

## Что если GOMAXPROCS=1 и goroutine блокируется?
**Частота:** 1/84
**Темы:** #go/scheduler #go/data-race
- [ ] Скорректировано
- [x] последний повтор ✅ 2026-06-26
При `GOMAXPROCS=1` все горутины на одном процессоре — параллелизма нет, но конкурентность есть. Блокирующий syscall/network может парковать горутину; netpoller и другие горутины продолжают работу.

**Подробности:**
- Один P — G исполняются по очереди на одном CPU, но тысячи G могут существовать одновременно.
- Block на канал/mutex: G паркуется, другая runnable G берёт P.
- Netpoller на одном P: сетевые G ждут readiness, CPU-G продолжают крутиться.
- Blocking syscall может отнять M; runtime создаст новый M для P, если нужно.
-`-race `ловит unsynchronized memory access даже при` GOMAXPROCS=1 `.
- Логические гонки (lost update без гонка данных) `-race` не найдёт.
- CPU-heavy G после 1.14 вытесняются sysmon, но не мгновенно — возможны короткие «монопольные» участки.

## Что используется для неблокирующего чтения из канала?
**Частота:** 1/84
**Темы:** #go/select #go/channel
- [ ] Скорректировано

` select { case v := <-ch: ...; default: ... При этом, }` не блокируется, если канал не готов. На практике для «только свежих» метрик часто используют канал cap=1 и drain старого значения.

- select с default даёт non-blocking операции; без default горутина блокируется.

## Что такое context switching и как горутины решают эту проблему
**Частота:** 1/84
**Темы:** #go/scheduler #go/goroutine
- [ ] Скорректировано
- [ ] последний повтор
**Что ожидают на собесе:**
- context switching это остановка выпол нения одного процесса и переключение на другой процесс
- с сохра нением стейта (стека, текущей инструкции) выгруженного процесса и загрузкой стейта нового процесса.
- Либо переход из user mode в kernel mode (syscall).

## Что такое массив? / Для чего можно использовать массивы в Golang?
**Частота:** 2/84
**Темы:** #go/array #go/types
- [ ] Скорректировано
- [x] последний повтор ✅ 2026-07-03
**Что ожидают на собесе:**
> [!summary] Собес: как отвечать
> Массив - это последовательность элементов одного типа и постоянной длины. Размер массива - составная часть его типа и задается во время компиляции.
- Многомерный `[M][N]T `— M элементов типа `[N]T `; пример:`[4][7]int `.
- Непрерывный блок N × sizeof(T), **доступ по индексу O(1)**; для `[M][N]T `— построчно. 
- доступ по индексу O(1), константная сложность потому что можно вычислить адрес 
- Без инициализации каждый элемент — нулевое значение своего типа.
- value type: при присваивании и передаче в функцию копируются все элементы. Мутация параметра `[N]T `внутри функции снаружи не видна; чтобы менять исходное значение, параметр объявляют`*[N]T `.
- Два массива одного типа `[N]T `можно сравнивать оператором == , если сравним тип T — тогда же`[N]T `годится ключом map. Срав нение двух значений одного`[N]T ` через == поэлементное, слева направо

- Значение `len(a)` подставляется компилятором как константа.
- Типы `[3]int `и`[5]int` несовместимы: ни присвоить одно другому, ни сравнить между собой нельзя.
- Размер можно вывести из литерала (`[...]int{10, 20}`), задать явно или указать только нужные индексы (`[7]int{2: 3, 6: 11}`).
- Пустой массив `[0]int ` допустим.
- Обращение по индексу-константе в не диапазона — ошибка компиляции; по переменному индексу в не `[0, N) `— паника.
- В `for range` по массиву переменная итерации — копия элемента, не ссылка на ячейку. Для изме нения на месте обходят по индексу или берут указатель на элемент явно.
- Копирование struct с полем-массивом включает весь массив.
```go
var a [5]int
b := [3]int{1, 2, 3}
c := [...]int{10, 20}
d := [7]int{6: 11, 2: 3}
```

использовать когда
- Когда **заранее известна фиксированная длина** и не планируется resize — массив на стеке/в struct без лишних аллокаций.
- Пример: фиксированный буфер, `[N]byte` под hash/crypto, embed в struct, stack-friendly hot path.

## ` sync.Cond`
**Частота:** 0/84
**Темы:** #go/sync
- [ ] Скорректировано
- [ ] последний повтор

**Эталон на собесе:**
Условная переменная:`Wait` освобождает mutex и спит до `Signal`/`Broadcast`.

**Подробности:**
- Cond + mutex: ждём изме нения общее состояние, не передачу владение.
- На практике часто канал; если Cond — цикл for против ложное пробуждение.
sync.Cond:
- работает только вместе с Locker (обычно Mutex);
- Wait() освобождает Mutex и засыпает;
- после пробуждения снова захватывает Mutex;
- Signal() будит одну горутину;
- Broadcast() будит все;
- Wait() всегда вызывают в цикле for, проверяя условие.
