# Currency hub

## Условие

У нас в компании есть потребность продавать во всех доступных валютах. Для этого необходимо, чтобы пользователь мог выбирать свою валюту, а мы могли её пересчитать на лету.
Для этого были куплены две подписки: на блумберг и на yahoo. В обеих, мы получаем по запросу текущий курс для выбранной пары.

Для остальных сервисов островка необходимо предоставить сервис, где:
1. Есть аналогичный API, чтобы получить текущий курс по валютной паре
2. Есть API для получения исторического курса

## Решение

0. Подумает сколько всего валютных пар, насколько большое будет хранение.
1. Какой набор компонент будет?
    - плохо: под каждого поставщика отдельный сервис
    - норм: разделил чтение и запись, запись по расписанию
2. Как обеспечить отказоустойчивость?
    - см. на разделение
3. Как будем поступать, если курс для пары расходиться между поставщиками?
    - плохо: какая-то ручная работа
    - сойдёт: выбор доверенного поставщика
    - сойдёт: какой-то понятный матан (среднее между двумя, перцентиль между больше)
4. Как внешним сервисам обрабатывать ошибки сервиса?
    - плохо: просто упасть
    - норм: какая-то логика когда падать можно, а как можно фоллбечить
