# Матчинг

## Условие

У нас есть сервис, который занимается матчингом отелей. Он берёт отели от всех поставщиков и пытается найти похожие, чтобы их объединить. Давай попробуем спроектировать этот сервис.  

На вход сервис получает ссылку на S3 с csv, где лежит следующая таблица:
```csv
id,provider_id,provider_hotel_id,name,address,location,hotel_kind,description
1,1,100,Cosmos Hotel,"Prospekt Mira, 150, Moscow, Russia","55.8223851,37.6442661",hotel,Best ever hotel
```
Объём записей - ~50млн отелей.

На выход: массив сгрупированных id одинаковых отелей
```json
[
  [1, 124, 34234],
  [432, 43253, 12312],
  [1444],
  ....
]
```

Из описанного нам интересно:

* как выглядит схема данных данного сервиса
* общие шаги алгоритма без деталей реализации

## Решение

Мы не ждём от кандидата, что он там расскажет про кластеризацию / машин лёрнинг и всё остальное, но есть ряд вещей, который нам интересны.

В проектирование:
1. Историчность данных.
2. Нормализация (в схеме или по логике или и там, и там?)
3. Смотрим на количество сервисов:
    - здесь мнение что монолит хорошо
    - в целом, норм если человек предложит такое делать на airflow с помощью DAGов

В логике работы сервиса:
1. Как будет осуществляться загрузка такого количества данных?
2. Как будет устроена работа с сессиями?
3. Реалтайм / не реалтайм
