### A/B тестирование: дизайн эксперимента
**Частота:** 2/117
**Темы:** #analytics #ab-test

**Эталон на собесе:**
**A/B** — сравнение вариантов (A control / B treatment) на случайных когортах.
- Гипотеза, метрика успеха (primary), MDE, мощность, уровень значимости (α).
- Сплит: user-id hash / cookie; независимость, без peeking без коррекции.
- Длительность: до набора выборки; CUPED/стратификация — продвинуто. Не путать с feature flag rollout без статистики.

### Apache Airflow: DAG, operators, scheduling
**Частота:** 2/117
**Темы:** #data-engineering #airflow

**Эталон на собесе:**
**Airflow** — оркестратор batch/ETL пайплайнов (не compute-движок).
- **DAG** — направленный ациклический граф задач; schedule_interval / timetable.
- **Operators** (Bash, Python, SparkSubmit, sensors) — единицы работы; **task** instance в run.
- Scheduler + executor (Celery/K8s/Local); retries, SLAs, XCom для мелких данных; тяжёлые данные — в S3/БД, не в XCom.

### Apache Spark: RDD/DataFrame, jobs
**Частота:** 1/117
**Темы:** #data-engineering #spark

**Эталон на собесе:**
**Spark** — in-memory (по возможности) distributed compute: batch + streaming (Structured Streaming).
- **RDD** — низкоуровневый иммутабельный распределённый набор; transformations (lazy) / actions.
- **DataFrame/Dataset** — табличный API + Catalyst optimizer; основной путь в prod.
- Job → stages → tasks; shuffle дорогой; partition’ы и persist/cache — ключ к perf.

### Hadoop: HDFS, YARN, экосистема
**Частота:** 1/117
**Темы:** #data-engineering #hadoop

**Эталон на собесе:**
**Hadoop** — экосистема распределённой обработки больших данных.
- **HDFS** — распределённая ФС: блоки на DataNode, NameNode хранит метаданные; репликация (обычно 3).
- **YARN** — планировщик ресурсов (ResourceManager / NodeManager), поверх него крутятся Spark/MapReduce.
- Типичный Data Lake: сырые данные в HDFS/S3-совместимом storage; MapReduce — legacy batch; сейчас чаще Spark поверх HDFS/object storage.

### RAG: retrieval-augmented generation
**Частота:** 1/117
**Темы:** #ml #nlp #llm

**Эталон на собесе:**
**RAG** — LLM отвечает с опорой на **извлечённый** внешний контекст (документы), а не только на веса модели.
- Pipeline: chunking → embeddings → vector store → retrieval (top-k) → prompt + context → generation.
- Зачем: актуальные/приватные знания, меньше галлюцинаций по фактам корпуса; нужны оценка retrieval и groundedness.
- Альтернативы/дополнения: fine-tuning, tool use, hybrid search (BM25 + vector).
