### asyncio / Event loop
**Частота:** 26/61
**Темы:** #python #concurrency #asyncio


**Эталон на собесе:**
Асинхронность в Python — конкурентность в **одном потоке**: крутится event loop, который планирует корутины/таски. `async def` возвращает корутину; на `await` текущая корутина приостанавливается, loop берёт следующую готовую; когда I/O готов — возврат.

Подходит для **I/O-bound** (сеть, БД, ожидание ответа). Набор параллельных HTTP: и threading + sync-клиент, и `asyncio.gather` дадут ~время самого медленного ответа, но механизмы разные (потоки vs переключение корутин).

Блокирующий sync/CPU-код внутри корутины **останавливает весь loop**. Вынос: `asyncio.to_thread` / `run_in_executor`, отдельный воркер. Потоки нужны, когда библиотека только sync.

Связка с GIL: async не даёт параллельных вычислений на ядрах; выигрыш — в ожидании I/O без лишних потоков.

### GIL в Python
**Частота:** 21/61
**Темы:** #python #concurrency


**Эталон на собесе:**
GIL (Global Interpreter Lock) в CPython: в один момент Python-байткод в процессе исполняет **только один поток**. На I/O GIL обычно отпускается — threading помогает на сетевых/файловых ожиданиях. На чистом CPU несколько потоков в одном процессе почти не ускоряют.

Зачем: упрощение модели памяти/refcount. GIL **не отменяет** data race: между байткодами потоки чередуются; shared state — mutex/semaphore.

Выбор: **CPU-bound** → multiprocessing (свой GIL на процесс); **I/O-bound** → threading или asyncio. Async: один поток, конкуренция за GIL между потоками не мешает; мешает блокирующий CPU внутри loop.

### Python декораторы
**Частота:** 20/61
**Темы:** #python


**Эталон на собесе:**
Декоратор — callable, принимает функцию/класс и возвращает обёртку: поведение до/после без правки исходника. `@d` ≡ `f = d(f)`; фабрика с параметрами — вложенные вызовы.

### Context managers (with / contextlib)
**Частота:** 13/61
**Темы:** #python


**Эталон на собесе:**
Контекстный менеджер — вход/выход из блока `with`: `__enter__` / `__exit__` (в т.ч. при исключении). Смысл — **гарантированное** освобождение ресурса (файл, соединение, lock).

Свой CM: (1) класс с `__enter__`/`__exit__`; (2) `@contextmanager` — setup до `yield`, teardown после; (3) async — `__aenter__`/`__aexit__`, `async with`. `__exit__` получает тип/значение/traceback; может подавить исключение (truthy return).

### Встроенные типы Python
**Частота:** 11/61
**Темы:** #python

**По литературе:**
Златопольский («Основы программирования на языке Python», 2-е изд., 2018; CPython 3.6):

Базовые типы переменных: **int**, **float**, **bool** (`True`/`False`), **str** (в т.ч. пустая `''`). Тип задаёт допустимые значения, операции и способ хранения в памяти.

**Список** — структура для группы значений под одним именем; элементы с индексами с 0; `len(a)`; элементы могут быть разных типов (в отличие от типичного «массива» в других ЯП). Методы вроде `append()`; срезы; `+` и `*` для списков.

**Словарь** — пары ключ→значение; ключ — **неизменяемый** тип (число, строка или **кортеж**); доступ по ключу в `[]`; ключ уникален; проверка `in` перед обращением (иначе ошибка). В редакции книги словарь описан как **неупорядоченный** набор (порядок при выводе не обязан совпадать с порядком записи).


**Эталон на собесе:**
Изменяемые: list, dict, set (иногда bytearray). Неизменяемые: int, float, bool, str, tuple, bytes, frozenset, NoneType, range. Изменение «на месте» vs новый объект.

List — динамический массив; tuple — фиксированный размер, компактнее. Set — уникальность и быстрый membership через хэш-таблицу. Dict — пары ключ→значение. В tuple можно положить list: кортеж неизменяем как контейнер ссылок, но list внутри менять можно.

### multiprocessing / gunicorn workers
**Частота:** 5/61
**Темы:** #python #concurrency


**Эталон на собесе:**
Multiprocessing — несколько **процессов**, у каждого свой GIL и память → реальный параллелизм на CPU. Данные между процессами — через IPC/сериализацию, не «общая память как у потоков».

В вебе: gunicorn/uvicorn поднимают воркеры-процессы между nginx и приложением, чтобы масштабировать нагрузку и не упираться в один GIL. Тяжёлый CPU из async-ручки — в отдельный процесс/пул, иначе блокируется event loop.

### *args / **kwargs
**Частота:** 2/61
**Темы:** #python


**Подробности:**
`*args` собирает лишние позиционные аргументы в **tuple**; `**kwargs` — лишние именованные в **dict**.

На определении: `def f(a, *args, b=1, **kwargs)`. На вызове распаковка: `f(*seq)`, `f(**mapping)`.

С 3.8+ полезны `/` (только positional) и `*` (только keyword) в сигнатуре. `*args`/`**kwargs` часто в обёртках, декораторах, прокси к другому API — но для публичных функций лучше явные параметры (читаемость, type hints, IDE).

### Truthiness и `__bool__`
**Частота:** 1/61
**Темы:** #python

**По литературе:**
Златопольский: результат сравнения — `True`/`False` (гл. 5). При чтении файла: `readline()` в конце файла возвращает **пустую строку**, которая воспринимается как ложное логическое значение (`False`) — на этом строят цикл чтения. Протокол `__bool__` в источнике **не** разбирается.


**Эталон на собесе:**
В bool-контексте ложны: `0`, пустые контейнеры, `None` и т.п.; истинны ненулевые/непустые. Для своего класса — dunder `__bool__`.

### Python: `__call__`
**Частота:** 1/61
**Темы:** #python


**Подробности:**
Если у класса есть `__call__`, экземпляры вызываются как функции: `obj(*args, **kwargs)` → `type(obj).__call__(obj, …)`.

Зачем: stateful callable (кэш, счётчик, конфиг внутри объекта), объекты-стратегии, лёгкие «функции с полями» без замыкания. Отличие от обычной функции — есть атрибуты/методы экземпляра между вызовами.

### Python: `len()` и `__len__`
**Частота:** 1/61
**Темы:** #python

**По литературе:**
Златопольский: `len()` — длина строки, размер списка, число пар в словаре. Дандер `__len__` в источнике **не** разбирается.


**Подробности:**
`len(x)` вызывает `type(x).__len__(x)` и требует неотрицательный `int` (иначе TypeError). Для своих коллекций реализуют `__len__`; пустой объект с `__len__ == 0` также falsy через протокол truthiness (если нет `__bool__`).

### Обмен значений без временной переменной
**Частота:** 1/61
**Темы:** #python

**По литературе:**
Златопольский, гл. 4: наивный `a = b; b = a` не работает — нужна третья переменная (`c = a; a = b; b = c`). В Python дополнительно: **`a, b = b, a`** (множественное присваивание).


**Подробности:**
Идиома Python: `a, b = b, a` — правая часть сначала упаковывается в tuple, затем распаковка (временный tuple создаёт runtime, отдельной переменной в коде нет).

Без сахарa (учебные ограничения): через сумму/XOR для int (`a^=b; b^=a; a^=b`) — хрупко и не для произвольных объектов. Для объектов правильнее tuple-swap или явная третья ссылка.

### Текстовый vs бинарный режим файлов
**Частота:** 1/61
**Темы:** #python #io

**По литературе:**
Златопольский, гл. 15 — только **текстовые** файлы: этапы open → операции → `close()`; `open(имя, режим)`. Режимы: `'r'` (чтение, по умолчанию в Windows), `'w'` (запись, существующий файл затирается), `'a'` (добавление в конец), `'r+'` (чтение и запись). Запись чисел — через `str()`. Бинарный режим (`'rb'`/`'wb'` и т.п.) в источнике **не** разбирается.


**Подробности:**
Текстовый (`'r'`/`'w'`/`'a'`, часто с `encoding='utf-8'`): читаете/пишете **str**, ОС/интерпретатор делают decode/encode и нормализацию переводов строк (`\\n`).

Бинарный (`'rb'`/`'wb'`/`'ab'`): **bytes**, без текстовой перекодировки — картинки, protobuf, gzip, точные байты. Путать режимы нельзя: в text нельзя писать bytes (и наоборот) без явного encode/decode.

С 3.x default encoding платформозависим — в проде для text всегда указывают `encoding`. Удобнее `with open(...) as f`.

### DRF ListAPIView vs APIView
**Частота:** 1/61
**Темы:** #python #django #drf


**Подробности:**
`APIView` — базовый class-based view DRF: сами пишете `get`/`post`/…, полный контроль request/response, permissions, throttle.

`ListAPIView` (из generics) — готовый **GET-список**: queryset + serializer_class, пагинация, фильтры «из коробки»; меньше кода для CRUD-list. Рядом: `RetrieveAPIView`, `ListCreateAPIView`, … ViewSet/ModelViewSet — ещё выше абстракция (routing через router).

Правило выбора: кастомная ручка / нестандартный контракт → `APIView` (или `@api_view`); типичный list/retrieve/create → generics / ViewSet.

### Free-threading / no-GIL (Python 3.13+)
**Частота:** 1/61
**Темы:** #python #gil #concurrency


**Эталон на собесе:**
В 3.13 обсуждают/включают **free-threading**: GIL можно отключать. Тогда настоящая многопоточность на CPU требует явных примитивов синхронизации. Выше риск race вокруг объектов/GC; накладные на stop-the-world растут с числом потоков. Практическая позиция: для прода многие остаются на модели с GIL + asyncio; multiprocessing по-прежнему даёт свой GIL на процесс.

### Функция vs метод
**Частота:** 1/61
**Темы:** #python #oop


**Подробности:**
**Функция** — callable, не привязанный к экземпляру (`def` на уровне модуля, `lambda`, `staticmethod` по сути тоже «функция у класса»).

**Метод** — функция, связанная с объектом: при доступе `obj.method` дескриптор возвращает bound method, первый аргумент `self` подставляется автоматически. У `classmethod` вместо экземпляра подставляется класс (`cls`).

Проверка: `type(obj.method)` — `method`; после `Class.method` без инстанса — `function` (для обычного def).

### concurrent.futures / Future
**Частота:** 1/61
**Темы:** #python #concurrency


**Эталон на собесе:**
**Future** — контейнер будущего результата (значение или исключение). В asyncio task планируется в loop; Future/результат — исход после завершения.

Связка async↔blocking: sync-код из корутины — через executor (`run_in_executor` / `to_thread`): в пуле потоков (`ThreadPoolExecutor` для I/O/blocking sync) или процессов (`ProcessPoolExecutor` для CPU). Loop не крутит тяжёлый sync сам — отдаёт в executor и ждёт Future.

### type() vs isinstance
**Частота:** 1/61
**Темы:** #python


**Подробности:**
`type(x) is C` / `type(x) == C` — точный класс объекта, **без** учёта наследников.

`isinstance(x, C)` (и `isinstance(x, (A, B))`) — True и для подклассов; с 3.10+ удобен union в аннотациях, для runtime часто `isinstance(x, A | B)` (3.10+) или tuple.

Для полиморфизма и duck typing почти всегда нужен `isinstance` (или Protocol). `type(x) is C` — когда важно запретить подклассы (редко) или отладить точный тип. `isinstance` работает и с ABC/virtual subclasses.

### Флаги интерпретатора Python (-O и др.)
**Частота:** 1/61
**Темы:** #python


**Подробности:**
`-O` — оптимизация bytecode: убираются `assert` и код под `if __debug__:`; пишутся `.pyo`-подобные оптимизированные pyc (в 3.x — тег opt в `__pycache__`). `-OO` — ещё выкидывает docstrings.

Другие частые: `-u` unbuffered stdout/stderr; `-B` не писать `.pyc`; `-I` isolated (игнор PYTHONPATH/user site); `-m pkg` запуск модуля; `-c code`. Для прода `assert` не должен быть механизмом безопасности — как раз из‑за `-O`.
