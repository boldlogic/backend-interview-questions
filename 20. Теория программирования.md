### Хэш-таблица (map / dict)
**Частота:** 41/92
**Темы:** #theory #data-structures #hashmap

Хэш-таблица: ключ → хэш → бакет/слот. Средний доступ **O(1)**, при плохих коллизиях деградация до O(n).

Общее:
- ключ должен быть хэшируемым и сравнимым на равенство;
- коллизии решают цепочками или открытой адресацией;
- при росте — rehash / эвакуация (средняя стоимость амортизируется);
- **не потокобезопасна** без внешней синхронизации.

**Go:** `map` — бакеты/Swiss map, load factor, нельзя брать `&m[k]`, concurrent map write = fatal.  
**Python:** `dict` — хэш-таблица; ключи — hashable (immutable по смыслу); порядок вставки сохраняется (CPython 3.7+).

### Гонки данных, дедлоки и синхронизация
**Частота:** 32/92
**Темы:** #theory #concurrency #sync

**Race (гонка данных)** — несколько потоков/горутин пишут/читают общую память без синхронизации; результат зависит от порядка.

**Deadlock** — взаимное ожидание блокировок (A ждёт B, B ждёт A). Профилактика: единый порядок захвата lock, таймауты, избегать nested lock без нужды.

**Livelock** — формально не «стоят на lock», но прогресса нет (взаимные уступки/retry без backoff).

Общие примитивы: mutex / RW-lock, атомики, каналы/очереди как способ убрать shared mutable state.

**Go:** `-race`, `sync.Mutex`/`RWMutex`, каналы.  
**Python:** `threading.Lock`, GIL не отменяет логические гонки на уровне данных приложения.

### Массив и динамический список (array / slice / list)
**Частота:** 28/92
**Темы:** #theory #data-structures #arrays

**Массив** — фиксированная длина, непрерывная память, доступ по индексу O(1).  
**Динамический список** — растущая коллекция поверх массива (amortized append), хранит длину/ёмкость.

Общее:
- индексируемость vs множество/хэш-таблица;
- копирование «всего буфера» vs копирование заголовка/ссылки;
- выход за границы — ошибка runtime.

**Go:** массив `[n]T` vs слайс `[]T` (ptr+len+cap).  
**Python:** `list` — динамический массив ссылок; `tuple` — фиксированная неизменяемая последовательность.

### Память: стек, куча и GC
**Частота:** 14/92
**Темы:** #theory #memory #gc

**Стек** — кадры вызовов, быстро выделяется/освобождается, ограничен.  
**Куча** — объекты с временем жизни дольше кадра / «убежавшие» из scope; обслуживает **GC**.

Утечки: достижимые, но ненужные объекты (кэш без TTL, «забытые» задачи/горутины/потоки).

**Go:** escape analysis (stack vs heap), GC, pprof heap.  
**Python (CPython):** reference counting + цикл-детектор; `gc` модуль; циклы ссылок.

### Интерфейсы и полиморфизм
**Частота:** 11/92
**Темы:** #theory #oop #interfaces

Интерфейс описывает **поведение** (набор операций), а не конкретную структуру данных. Полиморфизм: один контракт — много реализаций.

Зачем: слабая связанность, тестирование (подмены), DI.

**Go:** неявная реализация интерфейса; маленькие интерфейсы; value interface = (тип, данные).  
**Python:** duck typing / `Protocol` (typing); ABC при явных контрактах.

### Асимптотическая сложность (Big-O)
**Частота:** 10/92
**Темы:** #theory #complexity #algorithms

Big-O — рост числа операций/памяти от размера входа n (обычно worst case). Константы отбрасывают.

Классы: O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ)…

Примеры: доступ по индексу/ключу хэш-таблицы ≈ O(1); полный обход ≈ O(n); эффективная сортировка ≈ O(n log n).

### Итераторы и ленивые последовательности
**Частота:** 10/117
**Темы:** #theory #iterators

**Итератор** — объект обхода: «следующий элемент» / Stop.  
**Итерируемое** — то, из чего получают итератор.

**Ленивая последовательность / генератор** — значения по запросу, без полной материализации в памяти.

**Python:** `__iter__` / `__next__`, generator functions (`yield`).  
**Go:** обычно `for range`; ленивость — через каналы/кастомный API, не как синтаксис генераторов.

### Изменяемость и семантика копирования
**Частота:** 9/117
**Темы:** #theory #types #memory

**Immutable** — значение нельзя изменить на месте; «изменение» = новое значение.  
**Mutable** — объект меняется in-place; алиасы видят одну и ту же мутацию.

Связано с: передача по значению vs по ссылке; безопасность как ключ хэш-таблицы; гонки при shared mutable state.

**Python:** `str`/`tuple`/`frozenset` immutable; `list`/`dict`/`set` mutable; `==` vs `is`.  
**Go:** передача копирует значение; slice/map/channel — заголовок со ссылкой на общую структуру; value vs pointer receiver.

### Множество (set)
**Частота:** 9/92
**Темы:** #theory #data-structures #set

Множество — уникальные элементы, без (гарантированного) порядка индексов; проверка принадлежности в среднем O(1) на хэш-реализации.

Операции: add / remove / contains; union / intersection / difference.

**Go:** отдельного set нет → `map[T]struct{}`.  
**Python:** встроенный `set` / `frozenset` (immutable, hashable).

### Конкурентность vs параллелизм
**Частота:** 8/92
**Темы:** #theory #concurrency

**Конкурентность** — много задач в одном интервале времени (чередование / ожидание I/O).  
**Параллелизм** — одновременное исполнение на нескольких ядрах CPU.

На одном ядре возможна конкурентность без параллелизма. Асинхронность (не блокировать вызывающего) ≠ параллелизм.

**Go:** горутины + scheduler; `GOMAXPROCS`.  
**Python:** `threading` (часто I/O; GIL на CPU bytecode), `multiprocessing` (процессы), `asyncio` (кооперативная конкурентность в одном потоке).

### Равенство значений vs идентичность
**Частота:** 3/117
**Темы:** #theory #types

**Равенство** — одинаковое содержимое / семантика `==`.  
**Идентичность** — один и тот же объект в памяти.

**Python:** `==` vs `is` (и interning мелких int/str — ловушка).  
**Go:** `==` для comparable типов; для reference-like структур сравнивают содержимое/`reflect`/указатели осознанно; map/slice не comparable целиком.
