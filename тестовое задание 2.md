## 2. Схема хранения заказов

Упрощенная схема хранения заказов. Нужно проанализировать схему и найти узкие места.

### Users (пользователи)

| Название поля | Описание |
| --- | --- |
| id | Уникальный идентификатор покупателя |
| name | ФИО покупателя или никнейм |
| email | Адрес электронной почты для входа и уведомлений |

### Orders (заказы)

| Название поля | Описание |
| --- | --- |
| id | Уникальный номер заказа |
| user_id | Уникальный идентификатор покупателя |
| total | Итоговая сумма к оплате |
| status | Текущий статус заказа |

### OrderItems (Позиции заказа)

| Название поля | Описание |
| --- | --- |
| id | Уникальный идентификатор строки заказа |
| order_id | Уникальный номер заказа |
| product_name | Наименование товара |
| price | Цена за единицу товара |
| quantity | Количество единиц товара |

Добавим условие: заказ может содержать один и тот же товар в нескольких позициях (например, доставка в разные адреса или разные сроки).

## 4. REST API — Система управления задачами

### Предусловие

Необходимо спроектировать REST API для Системы управления задачами. Система позволяет пользователям создавать, редактировать, удалять и просматривать задачи, а также назначать задачи пользователям.

### 1. Пользователи

| Id пользователя | Имя | Email | Роль |
| --- | --- | --- | --- |
| 1323 | User_1 | user_1@mail.ru | администратор |
| 1324 | User_1 | user_1@mail.ru | обычный пользователь |

Администраторы могут управлять всеми задачами, обычные пользователи — только своими.

### 2. Задачи

| Id задачи | Название | Статус | Дата создания | Дата завершения |
| --- | --- | --- | --- | --- |
| 57 | Task_1 | Новая | 01.02.25 | |
| 58 | Task_1 | В работе | 28.01.25 | |

Задачи могут быть назначены только на пользователей, не администраторов.

### Задание

Для следующих задач написать какие методы будут использоваться, составить список и описание параметров запроса, список возможных ошибок:

1. Назначить задачу на пользователя.
2. Получить список своих задач для обычного пользователя.
