# Создание и использование горутин

Человек не может выполнять несколько работ одновременно. Но если есть группа людей, то вполне можно разбить весь объём работ на части и поручить каждому человеку свой «участок». Например, каменщики могут работать одновременно, выкладывая каждый свою стену. Или программисты при создании большого сервиса могут каждый писать небольшую его часть. Но может ли то же самое компьютер?

Самый главный компонент компьютера — это процессор, на него возложены все вычисления. Процессор имеет несколько ядер, которые непосредственно эти вычисления и выполняют. Все ядра работают независимо друг от друга — это как группа людей, каждый из которых делает своё дело. Но ядер не так много, а количество программ, которые выполняются на компьютере очень большое. То есть нельзя к каждой программе привязать отдельное ядро. Чтобы управлять выполнением программ существует операционная система (ОС). При запуске программы ОС создаёт отдельный процесс — это сама программа и сопутствующие ресурсы. Процесс хранит код программы, но не может его выполнить. За работу отвечают потоки выполнения. Каждый поток имеет доступ к родительскому процессу и содержит собственные ресурсы. По сути, поток — это единица выполнения кода на уровне ОС.

Таким образом, имеется множество потоков и несколько ядер. Выполнением N потоков на M ядрах руководит планировщик операционной системы. Он берёт поток, загружает в память его **контекст** (ресурсы, дескрипторы, состояние регистров) и отправляет его на выполнение ядру. Через какой-то промежуток времени планировщик сохраняет контекст потока, прекращает его выполнение и загружает следующий поток.

Так как потоков очень много, а ядер мало, то планировщик меняет потоки выполнения очень часто. Из-за этого создаётся впечатление, что сотня программ и сервисов работает параллельно. А на самом деле они выполняются по очереди — как если бы каменщик бегал от стены к стене и клал в каждую понемногу камней. В примере с человеком это звучит глупо. Но компьютер работает значительно быстрее, так что на взгляд пользователя это действительно выглядит как непрерывная работа.

![](https://code.s3.yandex.net/go/go1F/38.%D0%9C%D0%BD%D0%BE%D0%B3%D0%BE%D0%BF%D0%BE%D1%82%D0%BE%D1%87%D0%BD%D0%BE%D1%81%D1%82%D1%8C.%D0%A1%D0%BE%D0%B7%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5_%D0%B8_%D0%B8%D1%81%D0%BF%D0%BE%D0%BB%D1%8C%D0%B7%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5_%D0%B3%D0%BE%D1%80%D1%83%D1%82%D0%B8%D0%BD.1.png)

Вроде бы всё звучит хорошо: процесс может создавать множество потоков, а за их выполнение отвечает ОС. Проблема в том, что операцию переключения потоков нельзя назвать быстрой, так как контекст потока не маленький, и нужно один выгрузить, а другой загрузить. Чем больше потоков, тем чаще они переключаются, и тем больше времени будет уходить на их переключение. Поэтому некоторые современные языки программирования предлагают использовать легковесные потоки (англ. green threads). Они имеют меньший контекст, поэтому переключение между такими потоками происходит быстрее.

К сожалению, операционная система ничего не знает о легковесных потоках. Поэтому за их переключение отвечает среда выполнения программы, которая в свою очередь, своя для каждого языка. У Go тоже есть свои легковесные потоки — горутины.

## Горутины

**Горутина** (англ. goroutine) — это легковесный поток в среде выполнения Go. Среда выполнения Go может руководить работой множества горутин на нескольких потоках операционной системы и быстро переключаться с выполнения одной горутины на другую благодаря их маленькому размеру.

При запуске программы создаётся процесс с новым потоком ОС и запускается горутина с функцией `main()`. Новая горутина создаётся с помощью ключевого слова `go`, после которого указывается вызов функции. Горутина может вызываться только из какой-нибудь функции или метода. При этом запускается код вызываемой функции и продолжает выполняться код после `go`. Среда выполнения сама решает, на каком из доступных ей потоков выполнять горутину.

```
func Do() {
    // ...
}

func main() {
    // создаём горутину в которой будет выполняться функция Do() 
    go Do()
    // не ожидаем завершения Do(), а продолжаем выполнять код ниже
    // ...
} 
```

Пора переходить к практике. В примере ниже описываются две функции `tik()` и `tok()`, которые в `main()` вызываются как горутины. Если запустить программу, она выведет последовательность, в которой чередуются `.` и `o`. Это показывает, что обе функции выполняются одновременно.

```
package main

import (
    "fmt"
    "time"
)

func tik() {
    for i := 0; i < 30; i++ {
        fmt.Print(".")
        time.Sleep(time.Millisecond)
    }
}

func tok() {
    for i := 0; i < 30; i++ {
        fmt.Print("o")
        time.Sleep(time.Millisecond)
    }
}

func main() {
    go tik()
    go tok()
    time.Sleep(100 * time.Millisecond)
}
```

Обратите внимание на вызов `time.Sleep()` в функции `main()`. Выше уже было сказано, что после запуска горутины код основной функции продолжает выполняться дальше. Если убрать эту задержку, то программа закончит работу раньше, чем начнут выполняться созданные горутины, и вы не увидите результатов их работы.

При вызове горутины можно передавать параметры, как при вызове обычной функции. Например, вот так:

```
package main

import (
    "fmt"
    "time"
)

func tak(s string) {
    for i := 0; i < 30; i++ {
        fmt.Print(s)
        time.Sleep(time.Millisecond)
    }
}

func main() {
    go tak(".")
    go tak("o")
    time.Sleep(100 * time.Millisecond)
}
```

Программа работает как раньше, но код уменьшился на одну функцию.

При запуске горутин используют не только вызов существующей функции, но и вызов анонимных функций:

```
package main

import (
    "fmt"
    "time"
)

func main() {
    for _, v := range []string{".", "o"} {
        // для горутины используется анонимная функция
        go func(s string) {
            for i := 0; i < 30; i++ {
                fmt.Print(s)
                time.Sleep(time.Millisecond)
            }
        }(v) // передаём параметр в анонимную функцию
    }
    time.Sleep(100 * time.Millisecond)
}
```
Программа переделана так, что горутины вызываются в цикле. Почему бы и нет, так тоже можно делать.

## В каких случаях используют горутины

Горутины используют там, где можно или нужно распараллелить работу. Пусть не напрямую, но вы уже сталкивались с горутинами, когда знакомились с HTTP сервером. Там на каждый запрос создаётся своя горутина, в рамках которой запускается соответствующий обработчик. Это даёт возможность выдерживать одновременную работу сервера со множеством пользователей. Работа с большими данными и искусственным интеллектом также невозможна без многопоточности.

Если рассматривать более приближенные к повседневности задачи, то представьте, что нужно изменить размер у тысячи фотографий. Так как обработка одной фотографии никак не зависит от работы с другими изображениями, можно создать несколько горутин, которые будут получать на обработку очередное фото. Или представьте, что имеется список клиентов и шаблон дополнительного соглашения. Для каждого клиента нужно создать свой документ, подставив в шаблон нужные параметры и реквизиты. Здесь также можно использовать горутины, так как клиенты не зависят друг от друга.

Попробуйте применить горутины сами.

## Квиз 1/2

Имеется двумерный массив, состоящий из 4 строк по 1000 элементов — `data[4][1000]`. Элементы каждой из 4 строк нужно последовательно инициализировать значениями от 0 до 999. Добавьте в код запуск четырёх горутин, каждая из которых будет инициализировать элементы одной строки. В функцию горутины нужно передавать индекс строки, которую она должна инициализировать.

```
package main

import (
    "fmt"
    "time"
)

const Count = 1000
const Lines = 4

var data [Lines][Count]int

func main() {
    // вставьте сюда код с запуском четырёх горутин
    // ...

    time.Sleep(100 * time.Millisecond)
    // проверим как заполнен массив
    sum := 0
    for i := 0; i < Lines; i++ {
        for j := 0; j < Count; j++ {
            sum += data[i][j]
        }
    }
    fmt.Println(sum)
}
```

Вполне возможно, что при решении предыдущей задачи у вас была мысль написать код следующим образом:

```
for i := 0; i < Lines; i++ {
    go func() {
        for j := 0; j < Count; j++ {
            data[i][j] = j
        }
    }()
} 
```

Но так делать не нужно — при вызове горутин в циклах не используйте внутри горутин переменную цикла. Так как цикл не останавливается при запуске горутины, переменная `i` изменится с 0 до `Lines` очень быстро. С большой долей вероятности во всех четырёх горутинах будет инициализироваться только последняя строка или возникнет паника из-за выхода за границу массива.

Кроме этого, есть ещё несколько моментов, которые нужно учитывать при работе с горутинами.

## Возможные проблемы

Может возникнуть иллюзия, что чем больше горутин — тем быстрее работа программы, но это не так. Всегда помните, что количество ядер ограничено, а планировщики (системный или среды выполнения) — не волшебники. Хоть горутины и переключаются быстрее, чем системные потоки, на это тоже уходит определённое время. Пoэтому ориентируйтесь на количество ядер процессора. Четыре горутины могут работать эффективнее двадцати.

Вторая проблема связана с одновременным изменением общих данных — её ещё называют состоянием гонки (англ. _race condition_). Можно продемонстрировать к чему это приводит сразу на конкретном примере. Посмотрите на программу и предположите, что она выведет — а потом запустите её.

```
package main

import (
    "fmt"
    "time"
)

func main() {
    sum := 0

	for i := 0; i < 10; i++ {
//запускаем 10 горутин
		go func() {
//внутри горутины проходим 100000 раз
            for j := 0; j < 100000; j++ {
                sum++
            }
        }()
    }
    time.Sleep(2 * time.Millisecond)
    fmt.Println(sum)
}
```

Как правило, вместо ожидаемого миллиона в результате получается случайное число от 450 до 900 тысяч. Если у вас всё таки «выпал» миллион, то БИНГО — вы выиграли в лотерею.

Дело в том, что одна операция в языке во время компиляции превращается в несколько операций в машинных кодах, которые и выполняются процессором. Если несколько горутин будут одновременно выполнять один и тот же код на разных ядрах и изменять одну и ту же область памяти, то выйдет непонятно что. Например, обе горутины возьмут из памяти текущее значение переменной и увеличат его на единицу, а потом запишут обратно новое значение. Вроде бы две горутины увеличили значение переменной, а в реальности оно изменилось только на единицу.

![](https://code.s3.yandex.net/go/go1F/38.%D0%9C%D0%BD%D0%BE%D0%B3%D0%BE%D0%BF%D0%BE%D1%82%D0%BE%D1%87%D0%BD%D0%BE%D1%81%D1%82%D1%8C.%D0%A1%D0%BE%D0%B7%D0%B4%D0%B0%D0%BD%D0%B8%D0%B5_%D0%B8_%D0%B8%D1%81%D0%BF%D0%BE%D0%BB%D1%8C%D0%B7%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D0%B5_%D0%B3%D0%BE%D1%80%D1%83%D1%82%D0%B8%D0%BD.2.png)

Если все горутины только читают общие данные, то никаких проблем нет. Но если хотя бы одна горутина вносит в них изменения, то в этот момент нужно останавливать все другие операции с данными (как чтения, так и записи). Для этого в Go существуют специальные инструменты, которые могут обеспечить синхронизацию доступа. Об этом вы узнаете в следующих уроках.

## Подводя итог

Планировщик ОС отвечает за выполнение N потоков на M ядрах. Переключение между потоками занимает какое-то время. В среде выполнения некоторых языков есть легковесные потоки, которые имеют меньший размер и быстрее переключаются в потоке выполнения ОС. В Go это горутины.

Горутины запускаются с помощью ключевого слова `go`, после которого идёт вызов функции. В качестве горутины может запускаться анонимная функция.

Слишком много горутин может привести к ухудшению производительности. При создании горутин лучше ориентироваться на количество ядер процессора.

Горутины могут одновременно читать общие данные. Если хотя бы одна горутина изменяет общие данные, то другие горутины в этот момент не должны читать или изменять их.

В следующих уроках вы научитесь лучше использовать горутины, в том числе когда они работают с общими данными.
