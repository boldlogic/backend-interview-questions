# Инструмент pprof

Работая над реальным проектом, вы рано или поздно столкнётесь с тем, что сервис не справляется с нагрузкой, например не может обработать ожидаемое количество запросов. Такого рода проблемы можно решить горизонтальным или вертикальным масштабированием.

Горизонтальное масштабирование — это создание новых серверов (хостов), что актуально для распределённых приложений. Вертикальное масштабирование подразумевает увеличение производительности отдельных компонентов системы (памяти, процессора) для повышения общей производительности приложения.

А что, если масштабирование не решит проблему? Может, в самом сервисе есть какое-то узкое место? Чтобы ответить на эти вопросы, вам понадобится выполнить профилирование кода.

Профилирование — это сбор характеристик программы, таких как:

- время выполнения фрагментов кода,
- количество и время выделений памяти,
- объём выделяемой памяти,
- число кеш-промахов,
- количество вызовов отдельных функций,
- количество активных горутин.

Инструменты профилирования называются профилировщиками. В стандартной библиотеке Go есть встроенный профилировщик — `pprof`. Его и рассмотрим в этом уроке.

Для генерации картинок и просмотра графов в UI-режиме вам понадобится утилита `graphviz`. Как её установить, можно прочитать [здесь](https://graphviz.org/download/). Обратите внимание на инструкцию, если у вас возникнут ошибки просмотра графов.

## Дерево вызовов (Call Graph)

Напишем простое приложение с полезной нагрузкой и проанализируем его работу с помощью профилировщика `pprof`.

Сначала импортируем пакет `pprof` в приложение, чтобы он зарегистрировал стандартные обработчики:

```
import _ "net/http/pprof"
```

Инструмент `pprof` регистрирует обработчики при инициализации пакета в функции `init`.

Работать с `pprof` и просматривать результаты профилирования можно в веб-интерфейсе. Но `pprof` не запускает HTTP-сервер самостоятельно, он только регистрирует обработчик на адрес `/debug/pprof/`. Поэтому если приложение не использует HTTP-сервер для собственных нужд, то его нужно добавить и запустить специально для `pprof`. Это делается в последней строке кода:

```go
package main

import (
    "net/http"
    _ "net/http/pprof" // подключаем пакет pprof
)

const (
    addr    = ":8080"  // адрес сервера
    maxSize = 10000000 // будем растить слайс до 10 миллионов элементов
)

func foo() {
    // полезная нагрузка
    for {
        var s []int
        for i := 0; i < maxSize; i++ {
            s = append(s, i)
        }
    }
}

func main() {
    go foo()                       // запускаем полезную нагрузку в фоне
    http.ListenAndServe(addr, nil) // запускаем сервер
}
```

Скопируйте этот код в файл `main.go` и запустите программу командой `go run`:

```go
go run main.go
```

Теперь зайдите в браузер и скопируйте в адресную строку URL: `http://127.0.0.1:8080/debug/pprof/`. Вы увидите главную страницу `pprof`:

Здесь вы можете посмотреть профили приложения. Например, нажав на `goroutine`, вы увидите, какие горутины запущены в данный момент и какие вызовы этому предшествовали.

Проанализируем CPU-профиль приложения, чтобы понять, на какие вызовы уходит больше всего процессорного времени. Сейчас `pprof` показывает только текущие данные исполнения программы. Следовательно, нужно записать статистику за определённое время — допустим, за 30 секунд. Для этого откроем новое окно консоли и запустим команду `go tool pprof`:

```go
go tool pprof -http=":9090" -seconds=30 http://localhost:8080/debug/pprof/profile
```

Параметр `-http=[host]:[port]` указывает адрес сервера `pprof` для просмотра отчёта в браузере. В данном случае откроется страница с адресом `http://localhost:9090/`.

Последний аргумент вызова — это источник профиля. Источником может быть как файл, так и URL `http://localhost:8080/debug/pprof/profile`. Чтобы URL оставался доступным, не останавливайте выполнение предыдущей команды `go run main.go`, не закрывайте консоль, блокированную этой командой, а запускайте `go tool pprof` в другом окне терминала.

Если вы всё сделали правильно, через 30 секунд в браузере откроется вкладка с деревом вызовов.

Каждый блок дерева описывает:

- имя пакета,
- имя функции,
- время работы функции в секундах и процентах (относительно времени сбора профиля) без учёта внутренних вызовов,
- общее время работы функции в секундах и процентах.

Смотреть на общий план графа не очень удобно, тем более что вам нужна только полезная нагрузка — функция `foo`. Нажмите на блок этой функции — он выделится синим. Затем в левом верхнем углу выберите `REFINE` → `Show from`. Вы увидите дерево вызовов с корнем в виде блока `main foo`:

Посмотрим внимательнее на эту часть дерева:

- Функция `foo` исполнялась за время профилирования примерно 19 секунд, что составляет около 35% общего времени выполнения программы.
- Из этих 19 секунд 15 секунд ушло на рост слайса.
- Из 15 секунд роста слайса 13 секунд ушло на отработку функции `memmove` пакета `runtime`.

Таким образом, больше всего времени приложение потратило на копирование памяти при релокациях слайса.

## Flame Graph

Если вы нажмёте на `VIEW` в левом верхнем углу экрана, то увидите, что дерево вызовов, или `Graph`, — это лишь одно из представлений профиля работы приложения. Вам могут быть интересны такие представления:

Остановимся подробнее на `Flame Graph`. График представляет собой диаграмму выполнения программы в виде стека вызовов на каждом уровне.

Нажмите `REFINE` → `Reset` для сброса настроек и `VIEW` → `Flame Graph` для переключения на график. Вы увидите следующее:

При работе с `pprof` график `Flame Graph` отображается сверху вниз:

- На верхнем уровне — `root`, время исполнения всей программы.
- На следующем уровне — запущенные горутины.
- Ниже — функции в порядке вызова. Длина блоков указывает на время их выполнения.

Порядок блоков слева направо и их цвета не имеют значения.

Если вы нажмёте на блок `main.foo`, то увидите, что график динамически изменился. Теперь показываются только функции, исполняемые в горутине `main.foo`.

На графике видно, что основную часть времени занимает операция `runtime.growslice`. Рост слайса происходит при вызове `append`:

```go
var s []int
for i := 0; i < maxSize; i++ {
    s = append(s, i)
}
```

Также видно, что в операции `runtime.growslice` больше всего времени уходит на `memmove`-копирование. Встроенная функция `append` прибавляет элементы к слайсу до тех пор, пока хватает `capacity`, то есть размера памяти, выделенной для слайса массива. Когда массив заполняется, `append` делает новую аллокацию большего размера по новому адресу в памяти и копирует туда данные из оригинального массива. Это и есть `memmove`-копирование.

## Профиль выделяемой памяти

Для просмотра профиля CPU вы вводили в консоль строку:

```go
go tool pprof -http=":9090" -seconds=30 http://localhost:8080/debug/pprof/profile
```

Чтобы посмотреть профиль выделяемой памяти, замените `profile` на `heap`:

```go
go tool pprof -http=":9090" -seconds=30 http://localhost:8080/debug/pprof/heap
```

Как уже отмечалось, `go tool pprof` может использовать в качестве источника как файл, так и URL. Если команда выше возвращает ошибки, вы можете сначала сохранить данные в файл и потом анализировать:

```go
curl -sK -v http://localhost:8080/debug/pprof/heap > heap.out
go tool pprof -http=":9090" -seconds=30 heap.out
```

Можно просматривать этот профиль как в виде `Graph`, так и в виде `Flame Graph`. Во `Flame Graph` величина блоков теперь будет указывать не на время работы, а на размер выделяемой памяти в куче.

В меню `SAMPLE` появились варианты анализа:

- `alloc_objects` — количество объектов, созданных с момента запуска программы;
- `alloc_space` — количество памяти, выделенное с момента запуска программы;
- `inuse_objects` — используемое количество объектов;
- `inuse_space` — используемая память.

## Консольный режим

Утилита `pprof` предлагает и более привычный для разработчиков режим, чем UI-представление, — консольный. Для работы в консольном режиме достаточно запустить `go tool pprof`:

```go
go tool pprof -seconds=30 http://localhost:8080/debug/pprof/profile
```

Утилита сняла профиль работы программы за 30 секунд. Теперь можно вводить команды для просмотра профиля. Вывести весь список команд и опций можно с помощью `help`.

Запустим команду `list foo`, чтобы узнать время выполнения функции `foo` (используем профиль немодифицированной функции, в которой `append` делает промежуточные аллокации и копирования памяти при нехватке). Команда выведет в консоль следующее:

```go

         .          .     12:
         .          .     13:// полезная нагрузка
         .          .     14:func foo() {
         .          .     15:   for {
         .          .     16:           var s []int
     1.92s      1.92s     17:           for i := 0; i < maxSize; i++ {

         .          .     19:           }

         .          .     23:func main() {
```

Функция `foo` выполнялась 20 секунд. Больше всего времени заняла операция `s = append(s, i)`.

Теперь командой `top foo` выведем список вызовов, на которые ушло больше всего времени:

Больше времени ушло на копирование данных при релокации слайса `runtime.memmove`. Командой `web` можно открыть страницу с деревом вызовов.

Аналогично профилирование делается и по другим параметрам:

- `allocs` — информация обо всех выделениях памяти. Этот режим, в отличие от `heap`, отображает общее количество байт, выделенных с момента запуска программы.
- `block` — трассировка стека, которая привела к блокировке примитивов синхронизации.
- `goroutine` — трассировка стека всех текущих горутин.
- `mutex` — трассировка стека держателей конкурирующих мьютексов.

Поэкспериментируйте с консольным режимом `pprof` и посмотрите, какую информацию вы можете получить, вводя различные команды.

## Работа с журналами профилирования

Профилировщик может работать не только с запущенными приложениями, но и с сохранёнными файлами профилей. Рассмотрим, как утилита `pprof` помогает работать с профилями, которые созданы бенчмарками.

Запуская бенчмарки, вы можете записывать профили их выполнения с помощью флагов: `-cpuprofile=cpu.out` и `-memprofile=mem.out`. Запустите бенчмарк-тест из предыдущего урока:

```go
go test -bench=. -cpuprofile=cpu.out
```

После окончания работы бенчмарка создадутся два файла:

- файл-профиль `cpu.out`,
- исполняемый файл c именем тестируемого пакета и расширением `test` (например, `bench.test`).

Обычно `go test` уничтожает исполняемый файл, но при запуске с параметрами `-cpuprofile` или `-memprofile` этот файл не удаляется. Дело в том, что в журнал профилирования не включаются имена функций. Вместо этого функции идентифицируются по адресам, поэтому для `pprof` лучше указать соответствующий исполняемый файл.

Можно запустить профилировщик, указав исполняемый файл и CPU-профиль в параметре:

```go
# консольный режим
go tool pprof bench.test cpu.out
```

```go
# открыть журнал профилирования в браузере
go tool pprof -http=":9090" bench.test cpu.out
```

Часто бывают ситуации, когда анализировать журнал профилирования нужно на другом компьютере. Вы уже знаете, как работать с журналом независимо от запущенного приложения. Теперь рассмотрим, как создавать нужные профили.

Вернёмся к примеру этого урока и запустим его:

```go
package main
import (
    "net/http"
    _ "net/http/pprof" // подключаем пакет pprof
)
const (
    addr    = ":8080"  // адрес сервера
    maxSize = 10000000 // будем растить слайс до 10 миллионов элементов
)
func foo() {
    // полезная нагрузка
    for {
        var s []int
        for i := 0; i < maxSize; i++ {
            s = append(s, i)
        }
    }
}
func main() {
    go foo()                       // запускаем полезную нагрузку в фоне
    http.ListenAndServe(addr, nil) // запускаем сервер
}
```

После этого используем команду `curl`, чтобы отправить запрос и сохранить журнал профилирования в файл средствами командной строки:

```
curl http://127.0.0.1:8080/debug/pprof/profile > profile.debug.out
```

Если вы собираете данные профайлинга на продакшен-сервисах, то доступ к адресам профайлера должен быть скрыт от пользователей, так как эти запросы влияют на производительность сервиса.

Вы можете перенести полученный файл `profile.debug.out` на другой компьютер или поделиться им с другим разработчиком.

```go
go tool pprof -http=":9090" profile.debug.out
```

Рассмотрим ещё один способ создать журналы профилирования `cpu` и `mem`. Для этого используем пакет `runtime/pprof` стандартной библиотеки. Переделаем функцию `main` из примера следующим образом:

```go
func main() {
    // создаём файл журнала профилирования cpu
    fcpu, err := os.Create(`cpu.profile`)
    if err != nil {
        panic(err)
    }
    defer fcpu.Close()
    if err := pprof.StartCPUProfile(fcpu); err != nil {
        panic(err)
    }
    defer pprof.StopCPUProfile()

    go foo()
    time.Sleep(10 * time.Second)

    // создаём файл журнала профилирования памяти
    fmem, err := os.Create(`mem.profile`)
    if err != nil {
        panic(err)
    }
    defer fmem.Close()
    runtime.GC() // получаем статистику по использованию памяти
    if err := pprof.WriteHeapProfile(fmem); err != nil {
        panic(err)
    }
}
```

Если запустить эту программу, она отработает 10 секунд и создаст файлы `cpu.profile` и `mem.profile`, которые можно загрузить в `pprof`. В примере эти файлы будут создаваться при каждом запуске. На практике используются флаги командной строки для записи конкретного журнала профилирования.

Использование пакета `runtime/pprof` даёт возможность профилировать большой кусок кода или выполнение отдельной функции.

- Варианты кода, одинаково корректные, могут показывать разное время выполнения, разные характеристики использования оперативной памяти и CPU в работе.
- Профилирование делает динамический анализ работающего приложения.
- Профилирование выявляет ресурсоёмкие участки кода, узкие места.
- Профилирование — необходимая составляющая оптимизации кода.
- Для Go утилита `pprof` предоставляет полноценный инструментарий сбора и анализа метрик кода в работе.
