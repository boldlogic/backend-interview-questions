# Профилирование

Как правило, сложные проекты на одном из этапов развития начинают работать медленнее. Проблема скорости особенно актуальна для сервисов, у которых быстро растёт количество пользователей и запросов. Тема «Профилирование» посвящена инструментам для поиска узких мест в производительности, работе с памятью и горутинами. Эти знания пригодятся вам как на собеседованиях, так и в повседневной работе программиста.

В этой теме вы научитесь:

- анализировать производительность кода средствами пакета `testing`;
- выбирать оптимальный алгоритм реализации;
- добавлять свои метрики при проверке производительности;
- пользоваться встроенным профилировщиком `pprof`;
- применять `pprof` для анализа профилей CPU и выделяемой памяти;
- сохранять профили в файл и анализировать их отдельно.

## Бенчмарки

Иногда нужно проанализировать код с точки зрения производительности, чтобы, например, сравнить скорость работы нескольких реализаций одной и той же логики. Для этого обычно используют тесты производительности, именуемые **бенчмарками (benchmarks)**.

Прежде чем подробно рассказать о бенчмарках в Go, разберём особенности CPU-bound и I/O-bound операций и способы оптимизации кода.

## Особенности CPU-bound и I/O-bound операций

Стоит разделять вычислительные задачи на две категории — в зависимости от того, какие ресурсы расходует программа и что влияет на скорость её выполнения:

- операции ввода-вывода (I/O-bound),
- процессорные операции (CPU-bound).

Благодаря горутинам и каналам на Go удобно писать многопоточные приложения, которые больше зависят от операций ввода-вывода. Как видно из таблицы, скорость выполнения таких программ часто связана с эффективным использованием ресурсов и процессорного времени.

Но важно помнить, что горутины тоже расходуют ресурсы. Каждая горутина занимает около 4 килобайт, не считая сопутствующих выполнению кода затрат памяти (переменные, счётчики и так далее). Поэтому с ростом нагрузки на сервер процессу потребуется больше памяти, чтобы обрабатывать приходящие запросы. Оперативную память можно достаточно легко увеличить. А вот вычислительную мощность процессора нарастить так просто не получится. Повысить скорость выполнения CPU-bound задач можно за счёт покупки более мощного оборудования, но предел будет достигнут значительно быстрее, чем при наращивании оперативной памяти для ускорения I/O-bound задач.

Чтобы эффективнее использовать ресурсы оборудования, нужно провести анализ и оптимизацию функций, которые требуют больших вычислительных затрат. Для этого в Go используют встроенные инструменты — профилировщик и бенчмарки. Инструментарий для реализации бенчмарков вы можете найти в пакете `testing` стандартной библиотеки.

Перед тем как перейти к практике, напомним, что не стоит увлекаться преждевременной оптимизацией. Нагрузка, при которой может потребоваться наращивать пропускную способность сервера (наиболее частый случай), в большинстве случаев должна измеряться тысячами запросов в секунду и выше. В противном случае это может быть пустой тратой времени.

## Бенчмаркинг

Предположим, что требуется узнать, сколько времени выполняется функция. Для примера возьмём функцию вычисления чисел Фибоначчи, реализованную через рекурсию:

```go
package main

func FiboRecursive(n int) int {
    if n <= 1 {
        return n
    }
    return FiboRecursive(n-2) + FiboRecursive(n-1)
}
```

Поместим её в файл `fibonacci.go`.

Время выполнения любого куска кода нефиксированно и зависит от разных факторов: количества работающих процессов, размера свободной памяти и др. Поэтому для получения статистически верных результатов нужно запустить функцию несколько раз, замерить время выполнения в каждом случае и вычислить усреднённое значение. Чем больше раз запустим функцию, тем точнее данные получим.

Важно понимать, что время выполнения функции относительно — оно меняется не только от запуска к запуску, но и от машины к машине. Поэтому эти данные представляют интерес только как срезы во времени, по мере того как меняется реализация тестируемой функции.

В Go такие данные можно получить, выполнив **бенчмаркинг** — оценку того, сколько ресурсов затрачивает кусок кода в процессе выполнения.

Бенчмарк — это функция со следующей сигнатурой:

```go
func BenchmarkXxx(b *testing.B)
```

Бенчмарки, как и юнит-тесты, должны располагаться в файлах с суффиксом `_test.go`. Для примера создадим файл `fibonacci_test.go` и поместим туда функцию:

```go
package main

import "testing"

func BenchmarkFibo(b *testing.B) {
    for i := 0; i < b.N; i++ {
        FiboRecursive(20)
    }
}
```

По аналогии с юнит-тестами ход выполнения бенчмарков контролируется типом `testing.B`. Его единственным экспортируемым полем выступает целочисленное `N`. Значение определяется так: на каждой итерации цикла проверяется, прошло ли время `t` с момента запуска бенчмарка (по умолчанию 1 секунда). Если нет, то `N` увеличивается и цикл переходит на следующую итерацию. `N` зависит от времени предыдущего вычисления и меняется нелинейно. Например, последовательность значений `N` может быть 2, 10, 50.

Обратите внимание, что параметры в тестируемых функциях не должны зависеть от `i` или `b.N`:

```go
for i := 0; i < b.N; i++ {
    // так неправильно
    FiboRecursive(i) // или FiboRecursive(b.N)
}
```

Чтобы запустить бенчмарк, воспользуемся утилитой `go test`:

```go
go test -bench .
```

Флаг `-bench` указывает утилите, что вместе с тестами в пакете надо выполнить бенчмарки, удовлетворяющие переданному регулярному выражению. В данном случае запустятся все бенчмарки пакета.

Код выведет:

```
BenchmarkFibo-4     27408    43246 ns/op
```

Первое число показывает, сколько раз успела выполниться функция за отведённое время. Второе число — это усреднённое время, которое потребовалось для однократного выполнения функции. Суффикс в имени функции (`-4`) отражает заданное значение `GOMAXPROCS`.

Если требуется узнать, сколько памяти потребляет функция и сколько аллокаций происходит в процессе выполнения, можно использовать флаг `-benchmem`. Запустим бенчмарки с этим флагом командой `go test -bench . -benchmem`:

```
BenchmarkFibo-4     27734    42116 ns/op    0 B/op    0 allocs/op
```

Среднее время выполнения функции изменилось, хотя её реализацию не меняли. Это связано с неодинаковым процессорным временем, которое отводится под тесты от запуска к запуску.

Количество потребляемой памяти и произведённых аллокаций рассчитывается без погрешности и всегда представляет собой целое число. Здесь это 0, так как в процессе работы функция не запрашивает память.

Добавим в файл `fibonacci.go` новую функцию `FiboOptimized`, которая будет хранить вычисленные числа Фибоначчи в слайсе:

```go
func FiboOptimized(n int) int {
    if n <= 1 {
        return n
    }
    fibo := make([]int, n+1)
    fibo[1] = 1
    for i := 2; i <= n; i++ {
        fibo[i] = fibo[i-2] + fibo[i-1]
    }
    return fibo[n]
}
```

Можем добавить отдельную функцию-бенчмарк для функции `FiboOptimized`, а можем разделить имеющийся бенчмарк на два — методом `b.Run`. Вот как будет выглядеть файл `fibonacci_test.go` с переделанным бенчмарком:

```go
package main

import "testing"

func BenchmarkFibo(b *testing.B) {
    count := 20
    b.Run("recursive", func(b *testing.B) {
        for i := 0; i < b.N; i++ {
            FiboRecursive(count)
        }
    })
    b.Run("optimized", func(b *testing.B) {
        for i := 0; i < b.N; i++ {
            FiboOptimized(count)
        }
    })
}
```

Запустим получившийся бенчмарк командой `go test -bench . -benchmem`. Посмотрите, во сколько раз `FiboOptimized` выполняется быстрее, чем `FiboRecursive`:

```
BenchmarkFibo/recursive-4       28410    41792 ns/op      0 B/op    0 allocs/op
BenchmarkFibo/optimized-4    12514520    81.42 ns/op    176 B/op    1 allocs/op
```

## Управление таймером

Иногда перед выполнением бенчмарка требуются подготовительные действия, которые могут повлиять на чистоту результата. Утилита `go test` не умеет различать, какие операции в теле цикла функции-бенчмарка нужно учитывать при расчёте процессорного времени, а какие нет.

Поэтому для точного подсчёта времени у `testing.B` есть методы, которые:

- останавливают подсчёт — `b.StopTimer()`;
- возобновляют его — `b.StartTimer()`.

Для примера напишем бенчмарк сортировки с помощью функции `sort.Slice`. В этом бенчмарке нужно подготовить слайс — добавить в него элементы со случайными значениями:

```go
func BenchmarkSortSlice(b *testing.B) {
    rand.Seed(time.Now().UnixNano())

    for i := 0; i < b.N; i++ {
        slice := make([]int, 10000)
        // предзаполняем слайс
        for i := 0; i < len(slice); i++ {
            slice[i] = rand.Intn(1000)
        }

        // сортируем
        sort.Slice(slice, func(i, j int) bool {
            return slice[i] < slice[j]
        })
    }
}
```

Запустим бенчмарк:

```
BenchmarkSortSlice-4    792   1458367 ns/op    81976 B/op   3 allocs/op
```

Теперь вычтем из результата время, которое код затрачивает на генерацию и добавление тестовых данных в сортируемый слайс. Для этого нужно остановить таймер перед подготовительным действием и возобновить после действия:

```go
func BenchmarkSortSlice(b *testing.B) {
    rand.Seed(time.Now().UnixNano())

    for i := 0; i < b.N; i++ {
        b.StopTimer() // останавливаем таймер
        slice := make([]int, 10000)
        for i := 0; i < len(slice); i++ {
            slice[i] = rand.Intn(1000)
        }
        b.StartTimer() // возобновляем таймер

        // сортируем
        sort.Slice(slice, func(i, j int) bool {
            return slice[i] < slice[j]
        })
    }
}
```

Запустим и убедимся, что манипуляции с таймером повлияли на результат:

```
BenchmarkSortSlice-4   952   1203942 ns/op    56 B/op    2 allocs/op
```

Также можно сбросить счётчики операций и отведений памяти функцией `b.ResetTimer()`. Например, когда нужно вычесть время выполнения действий в начале бенчмарка, достаточно после них вызвать эту функцию.

Пакет `testing` позволяет добавлять свои метрики. Предположим, что надо вычислить количество определённых действий за один проход цикла.

Посчитаем, сколько раз в среднем вызывается функция сравнения при сортировке слайса. Для этого добавим целочисленный счётчик `cmps` и воспользуемся функцией `testing.B.ReportMetric(n float64, unit string)`. Она допишет метрику в отчёт бенчмарка.

```go
func BenchmarkSortSlice(b *testing.B) {
    rand.Seed(time.Now().UnixNano())
    slice := make([]int, 10000)
    b.ResetTimer() // сбрасываем счётчик, чтобы инициализация слайса не посчиталась

    var cmps int64
    for i := 0; i < b.N; i++ {
        b.StopTimer() // останавливаем таймер
        for i := 0; i < len(slice); i++ {
            slice[i] = rand.Intn(1000)
        }
        b.StartTimer() // возобновляем таймер

        sort.Slice(slice, func(i, j int) bool {
            cmps++ // увеличиваем счётчик
            return slice[i] < slice[j]
        })
    }

    // добавляем метрику
    b.ReportMetric(float64(cmps)/float64(b.N), "compares/op")
}
```

Код выведет:

```
BenchmarkSortSlice-4  916  1219124 ns/op  124691 compares/op  56 B/op  2 allocs/op
```

Теперь результат содержит новую метрику: `124691 compares/op`.
