# Go: интерфейсы

## Шпаргалка

1. Interface = именованный **набор методов**.
2. Реализация **неявная** — совпал набор методов, тип подходит.
3. Маленькие `-er` интерфейсы.
4. `T` и `*T` — **разные** наборы методов.
5. Значение interface = `(динамический тип, data)`.

---

## Определение и контракт

Интерфейс описывает **поведение**, не структуру данных. Тип реализует интерфейс, если его набор методов содержит все методы интерфейса — объявление `implements` не нужно.

```go
type Stringer interface {
    String() string
}
```

Имена параметров в interface можно опустить; в документации их лучше оставлять для читаемости.

**Композиция интерфейсов** — встраивание других interface:

```go
type ReadWriter interface {
    Reader
    Writer
}
```

---

## Набор методов (method set)

Набор методов типа `T` — методы с receiver `(T)`. Набор `*T` — методы с receiver `(T)` **и** `(*T)`.

| Методы типа | Реализует interface с |
|-------------|------------------------|
| только `(T) M()` | `T` и `*T` |
| есть `(*T) M()` | только `*T` |

Поэтому `*bytes.Buffer` реализует `io.Writer`, а `bytes.Buffer` (value) — нет, если `Write` объявлен на pointer.

---

## Значение interface: type + data

Переменная interface хранит пару указателей: **динамический тип** (itab/descriptor) и **data** (указатель на конкретное значение). Разные конкретные типы — разный размер data; interface унифицирует их.

При передаче interface в функцию копируется пара указателей; data часто указывает на исходный объект — мутация через методы interface видна снаружи.

## Typed nil vs nil interface

```go
var p *MyError = nil
var e error = p
fmt.Println(e == nil) // false
```

Interface **равен nil** только когда **и** type, **и** data — nil. Typed nil pointer кладёт type info в interface → `!= nil`.

Уточнение для функций, возвращающих error:

```go
return nil, nil             // (T, error): error == nil
return nil, (*MyError)(nil) // error interface с typed nil — не nil!
```

Для «нет ошибки» из `(T, error)` возвращают `nil` error без обёртки typed pointer в interface.

## Приведение типов

`any` (Go 1.18+) = `interface{}`.

```go
i := v.(int)       // panic, если тип не совпал
i, ok := v.(int)   // ok == false без panic

switch x := v.(type) {
case int:
    ...
case Stringer:
    ...
}
```

Type assertion — не преобразование типа: меняется представление динамического типа, не само значение.

**Сравнение interface** через `==`: динамический тип должен быть comparable и совпасть; сравниваются underlying values. Сравнивать interface с concrete nil осторожно.

## Generics vs interfaces

| | Interfaces | Generics |
|---|------------|----------|
| Полиморфизм | по **поведению**, во время выполнения | по **type parameters**, на этапе компиляции |
| Когда | алгоритмы над разным поведением (`io.Copy`) | контейнеры, функции над comparable/ordered |
| `any` | любой тип | constraint верхней границы |

**Constraints:** `any` — любой тип; `comparable` — типы с `==` / `!=` (ключ map, `slices.Contains`); `constraints.Ordered` — для `<`, `>`.

Generics не заменяют interfaces для полиморфизма объектов. Generics уменьшают потребность в `any` + type switch + reflect для обобщённых алгоритмов.

## Стандартная библиотека

Частые границы между слоями: [`error`](https://pkg.go.dev/builtin#error), [`fmt.Stringer`](https://pkg.go.dev/fmt#Stringer), [`io.Reader`](https://pkg.go.dev/io#Reader) / [`io.Writer`](https://pkg.go.dev/io#Writer) — потоки байт; [`io.Copy`](https://pkg.go.dev/io#Copy) копирует из Reader в Writer.

---

## На практике

- Принимать интерфейсы, возвращать конкретные типы — параметры через interface, результат struct или именованный тип.
- Маленькие интерфейсы объявлять **у потребителя**, не у автора типа.
- Проверка реализации на этапе компиляции: `var _ Client = (*MockClient)(nil)`.
- Интерфейс >5–10 методов — повод разбить.
- Не использовать `any`, где хватает generics или конкретного типа.
