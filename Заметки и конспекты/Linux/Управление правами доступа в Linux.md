# Типы прав доступа к файлам

Linux изначально разрабатывалась как многопользовательская операционная система. А если в системе со множеством пользователей не разграничить права доступа на различные действия, то будет полная анархия — кто-то что-то удалит случайно, кто-то специально, кто-то что-то не так поймёт — и нужных файлов потом будет просто не найти. Поэтому организация прав доступа в Linux — очень важная вещь, с которой придется часто сталкиваться программисту в процессе работы.

## Пользователи и группы

Прежде чем говорить о правах, стоит понять, кому эти права даются. Получают их пользователи — люди, которые пользуются компьютером. С точки зрения системы, пользователь (юзер, англ. _user_) имеет уникальный логин — имя и соответствующий ему идентификатор. Один и тот же человек может создать множество пользователей в системе и работать под тем или иным именем в зависимости от выполняемых задач. Все программы тоже выполняются от имени определённого пользователя. Linux не допускает к себе анонимных личностей — вы всегда будете работать под каким-то пользователем. Чтобы узнать имя, под которым вы сейчас работаете, выполните команду `id`.

Скопировать код

BASH

```
ak@ak-desktop:~$ id
uid=1000(ak) gid=1000(ak) groups=1000(ak),4(adm),24(cdrom),27(sudo),
30(dip),46(plugdev),114(lpadmin),134(sambashare) 
```

Консоль ответит вам тремя параметрами:

- `uid` — уникальный идентификатор пользователя — 1000. В скобках указано имя пользователя — в данном случае, ak;
- `gid` — идентификатор группы пользователя с указанием имени.
- `groups` — идентификаторы и имена групп, которым принадлежит пользователь.

Здесь появилось новое понятие — **группа**. Это множество из одного или нескольких пользователей, объединённых по каким-то критериям. Пользователь может одновременно присутствовать в нескольких группах.

В жизни есть множество аналогов групп. Например, в ООО «Ромашка» есть:

- бухгалтеры, devops, разработчики, тестировщики, 1с-программисты;
- Васины поклонницы;
- те, у кого есть ключ от сейфа начальника;
- те, кому дует, и те, кому жарко.

Делить людей на группы можно бесконечно. В системе тоже может существовать множество групп, а один и тот же пользователь может состоять в нескольких из них.

Среди пользователей обязательно есть суперпользователь. По умолчанию в Linux это пользователь с именем `root`. Он имеет доступ буквально ко всему и обладает всеми существующими в системе правами. Также он может выполнять специальные операции по управлению системой. Запустите `id root`, чтобы посмотреть информацию о нём:

Скопировать код

BASH

```
ak@ak-desktop:~$ id root
uid=0(root) gid=0(root) groups=0(root) 
```

Его идентификатор и идентификатор одноимённой группы равны 0. В целях безопасности под этим пользователем никто не работает постоянно. Это помогает избежать случайных или необдуманных действий, которые могут привести систему в нерабочее состояние или уничтожить важную информацию.

Если нужно выполнить действие, которое может сделать только суперпользователь, следует использовать команду `sudo`. Для запуска программы от имени суперпользователя используется такой синтаксис: `sudo программа параметры`. Следует использовать `sudo` только в случае реальной необходимости — например, когда нужно создать нового пользователя.

Чтобы понять, как работают права доступа, вам понадобится создать ещё одного пользователя командой `adduser`. Эта команда запросит пароль и дополнительную информацию: можно их указать, а можно не указывать. Команда `adduser` создаст пользователя с нужным именем и его поддиректорию в директории `/home`. Так как добавлять пользователей может только суперпользователь, не забудьте указать слева `sudo`. В примере создаётся пользователь `margo`, но вы можете указать другое имя.

Скопировать код

BASH

```
ak@ak-desktop:~$ sudo adduser margo
[sudo] password for ak:         
Adding user `margo' ...
Adding new group `margo' (1001) ...
Adding new user `margo' (1001) with group `margo' ...
Creating home directory `/home/margo' ...
Copying files from `/etc/skel' ...
New password: 
Retype new password: 
passwd: password updated successfully
Changing the user information for margo
Enter the new value, or press ENTER for the default
    Full Name []: 
    Room Number []: 
    Work Phone []: 
    Home Phone []: 
    Other []: 
Is the information correct? [Y/n] Y 
```

Самостоятельно добавьте ещё одного пользователя с именем **bob** — `sudo adduser bob`. Чтобы не запутаться, или не указывайте пароль, или укажите тот же, что задали для margo.

Чтобы сменить пользователя, воспользуйтесь командой `su -l [username]`, где `username` — имя пользователя. Флаг `-l` указывает на то, что нужно обновить все переменные окружения и домашний каталог — это важно для правильной работы системы. Также можно использовать укороченную запись `su - [username]`.

Смените пользователя в системе на `bob` — учтите, что система запросит пароль. И посмотрите информацию о двух новых пользователях:

Скопировать код

BASH

```
ak@ak-desktop:~$ su - bob
Password: 
bob@ak-desktop:~$ id margo
uid=1001(margo) gid=1001(margo) groups=1001(margo)
bob@ak-desktop:~$ id bob
uid=1002(bob) gid=1002(bob) groups=1002(bob) 
```

Обратите внимание, что вместе с каждым пользователем создалась одноимённая группа. После создания пользователь состоит только в своей собственной группе.

Директорию `/home/margo` вы будете использовать для экспериментов. После завершения темы вы сможете удалить пользователей командой `sudo deluser --remove-all-files <имя удаляемого пользователя>`. Опция `--remove-all-files` приводит к удалению всех файлов пользователя.

Всех пользователей можно посмотреть в файле `/etc/passwd`. Вот информация о `margo`:

Скопировать код

BASH

```
bob@ak-desktop:~$ grep margo /etc/passwd
margo:x:1001:1001:,,,:/home/margo:/bin/bash 
```

Вот что здесь указано:

- Имя пользователя.
- Наличие зашифрованного пароля — отмечено символом `x`.
- 1001 — это `uid` и `gid`.
- Домашняя директория и командная оболочка.

На вашей системе эти идентификаторы могут иметь совсем другие значения.

Информация о группах хранится в файле `/etc/group`:

Скопировать код

BASH

```
bob@ak-desktop:~$ grep margo /etc/group
margo:x:1001: 
```

Здесь указано имя группы, наличие пароля и идентификатор `gid`.

Теперь пора переходить к правам доступа.

## Права доступа к файлам

Существует три вида доступа к файлам и директориям. С точки зрения ОС, директория — это тоже файл, но с определёнными свойствами. Поэтому папки имеют такие же виды прав доступа, что и файлы. Вот какие бывают виды доступа и что они значат для файлов и для директорий:

|Доступ|Для файлов|Для директорий|
|---|---|---|
|**Чтение** (англ. _read_)|Можно прочесть файл|Можно получить список файлов и поддиректорий|
|**Запись** (англ. _write_)|Можно изменить содержимое файла|Можно создавать и удалять файлы, а также менять права доступа|
|**Выполнение** (англ. _execute_)|Можно выполнить (запустить) файл|Можно войти в каталог и сделать его текущим|

Если каких-то прав нет — соответствующие операции проводить будет нельзя. Например, если есть права только на чтение файла, то невозможно его изменить.

Структура прав доступа в Linux выглядит следующим образом:

![](https://code.s3.yandex.net/go/go1F/41.%D0%A3%D0%BF%D1%80%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5_%D0%BF%D1%80%D0%B0%D0%B2%D0%B0%D0%BC%D0%B8_%D0%B4%D0%BE%D1%81%D1%82%D1%83%D0%BF%D0%B0.%D0%A2%D0%B8%D0%BF%D1%8B_%D0%BF%D1%80%D0%B0%D0%B2_%D0%B4%D0%BE%D1%81%D1%82%D1%83%D0%BF%D0%B0.1.png)

Пока может быть непонятно, но сейчас вы узнаете о значении каждой буквы и цифры.

Для каждого файла и директории задаются права доступа для трёх категорий.

- **Владелец** (англ. _owner_) — пользователь, который установлен владельцем. Как правило, это тот, кто создал файл или директорию.
- **Группа** (англ. _group_) — группа пользователей, которая привязана к файлу или директории. Чаще всего это группа владельца.
- **Остальные** (англ. _others_) — остальные пользователи системы.

Все права доступа хранятся в двоичном виде, но при выводе информации или установке прав используются символьные сокращения: **r** — чтение, **w** — запись, **x** — запуск. Если прав нет, то указывается **-**.

В три символа умещаются права только для одной категории. Так как у файлов и директорий определены права для трёх категорий, понадобится девять символов. В начале идут права для владельца, потом для группы, в конце — для остальных юзеров.

Кроме символьной записи существует ещё числовая. Для хранения всех состояний хватит трёх бит — старший бит для чтения, средний — для записи и младший для выполнения.

- `100` — чтение (4 в десятичном виде);
- `010` — запись (2 в десятичном виде);
- `001` — выполнение (1 в десятичном виде);

Для хранения прав для трёх категорий необходимо 9 бит. Можно представлять полученное число в десятичном виде, но максимально возможное значение для одной категории равно 7 (4 + 2 + 1), поэтому удобнее перейти на восьмеричную систему счисления. В этом случае получается число из трех цифр, каждая из которых соответствует владельцу, группе и остальным пользователям. В Go числа в восьмеричной системе начинаются с нуля - вы уже сталкивались при создании файлов или директорий с параметрами подобными `0644` или `0755`. Это как раз указываются права доступа в восьмеричном виде.

Вот несколько примеров символьной и числовой записи для одной категории пользователей:

- `---` (0) — права отсутствуют;
- `--x` (1 = 0+0+1) — права только выполнение;
- `r--` (4 = 4+0+0) — права только на чтение;
- `r-x` (5 = 4+0+1) — права на чтение и запуск;
- `rw-` (6 = 4+2+0) — права только на чтение и запись;
- `rwx` (7 = 4+2+1) — имеются все права.

Для категорий тоже есть символьные сокращения: **u** — владелец (юзер), **g** — группа, **o** — остальные пользователи. Если нужно применить операцию для всех пользователей, используют символ **a**. Эти обозначения используются при установке прав из командной строки.

#### Права на практике

Проверим, как соотносится эта информация с практикой. Переключитесь в терминале на пользователя margo. Если вы вдруг забыли пароль, пользователя придется пересоздать заново — способы сбросить и восстановить пароль есть, но вы пока не будете их изучать.

Так как домашние директории могут создаваться с разными правами доступа, следует выполнить команду установки определённых прав на домашную директорию. Команду `chmod` вы изучите в следующем уроке, поэтому пока просто используйте `chmod 755 ~` — это внесет единообразие для успешного выполнения последующих команд.

Скопировать код

BASH

```
bob@ak-desktop:~$ su - margo
Password: 
margo@ak-desktop:~$ chmod 755 ~ 
```

Выполните команду `ls -la`:

Скопировать код

BASH

```
margo@ak-desktop:~$ ls -la
total 36
drwxr-xr-x 4 margo margo 4096 Jan 10 14:05 .
drwxr-xr-x 5 root  root  4096 Jan 10 13:36 ..
-rw-r--r-- 1 margo margo  220 Jan 10 12:52 .bash_logout
-rw-r--r-- 1 margo margo 3771 Jan 10 12:52 .bashrc
drwx------ 2 margo margo 4096 Jan 10 14:05 .cache
drwxr-xr-x 5 margo margo 4096 Jan 10 12:52 .config
-rw-r--r-- 1 margo margo   22 Jan 10 12:52 .gtkrc-2.0
-rw-r--r-- 1 margo margo  516 Jan 10 12:52 .gtkrc-xfce
-rw-r--r-- 1 margo margo  807 Jan 10 12:52 .profile 
```

Первая строка `drwxr-xr-x 4 margo margo 4096 Jan 10 14:05 .` содержит информацию о директории `/home/margo`. Первым символом идёт тип файла: `d` означает директорию, а `-` — обычный файл. Далее идут права доступа. Для владельца `margo` установлены все права `rwx`, для группы `margo` и для остальных юзеров имеются права только на чтение и выполнение - `r-x`. По логике, посмотреть содержимое этой директории может и другой пользователь. Проверим это.

Откройте второй терминал, смените там пользователя на `bob` и запросите содержимое `/home/margo` - `ls -la /home/margo`. Вы должны увидеть точно такой же список, так как `bob` относится к категории «остальные» и имеет права на чтение и выполнение домашней директории Марго.

Если попробовать создать какой-нибудь файл, вы получите `Permission denied`, что означает «доступ запрещен». Потому что у Боба нет прав на запись.

Скопировать код

BASH

```
bob@ak-desktop:~$ cd /home/margo
bob@ak-desktop:/home/margo$ touch test.txt
touch: cannot touch 'test.txt': Permission denied 
```

У Марго проблем с созданием файла не будет. Перейдите на терминал с `margo` и создайте файл `hello.sh`:

Скопировать код

BASH

```
margo@ak-desktop:~$ touch hello.sh 
```

Вставьте в созданный файл такой текст с помощью любого текстового редактора:

Скопировать код

BASH

```
#!/bin/bash

echo "привет" 
```

В первой строке указывается командная оболочка, с помощью которой будет запущен этот скрипт. Однако запуск `./hello.sh` возвратит ошибку доступа. Это произошло потому, что по умолчанию файл создался без прав на запуск. А вот запуск скрипта с помощью `/bin/bash` пройдёт успешно — командной оболочке достаточно прав на чтение, чтобы выполнить скрипт. Это важно помнить — отсутствие прав на запуск работает для исполняемых файлов, но не защищает от запуска скриптов.

Скопировать код

BASH

```
margo@ak-desktop:~$ nano hello.sh
margo@ak-desktop:~$ cat hello.sh
#!/bin/bash

echo "привет"
margo@ak-desktop:~$ ./hello.sh
-bash: ./hello.sh: Permission denied
margo@ak-desktop:~$ ls -l hello.sh
-rw-rw-r-- 1 margo margo 33 Jan 10 14:47 hello.sh
margo@ak-desktop:~$ /bin/bash hello.sh
привет 
```

Про изменение прав доступа вы узнаете в следующем уроке. Пока выполните команду `chmod 775 hello.sh`, которая даст права на запуск `hello.sh` для всех пользователей. После этого запуск скрипта пройдёт успешно.

Скопировать код

BASH

```
margo@ak-desktop:~$ chmod 775 hello.sh
margo@ak-desktop:~$ ls -l hello.sh
-rwxrwxr-x 1 margo margo 33 Jan 10 14:47 hello.sh
margo@ak-desktop:~$ ./hello.sh
привет 
```

Сейчас попробуйте запустить этот скрипт от имени Боба. Раз установлены права на запуск для всех пользователей, то скрипт должен выполниться и под пользователем `bob`:

Скопировать код

BASH

```
bob@ak-desktop:/home/margo$ ./hello.sh
привет 
```

Скрипт выполнился, но отредактировать или удалить его `bob` по прежнему не сможет, так как для остальных пользователей не установлены права на запись для этого файла и директории `/home/margo`.

## Расширенные права

Представьте себе сервер, на котором работает множество программ, поддерживающих бизнес-процессы компании. Там всем управляют админы, а прочие пользователи сильно ограничены в правах. Одно из приложений работает с важными файлами и отвечает за создание и отправку бухгалтерских отчётов. Получается, что группе бухгалтеров нужны права на запуск этого приложения — и ещё понадобятся права на чтение и запись тех самых важных файлов. Однако это нежелательно — секретной информации там нет, но есть риск случайного удаления или порчи файлов. А этого хотелось бы избежать, но стандартными средствами сделать так не получится.

Для решения задач совместной работы были придуманы расширенные права, для которых отведены дополнительные биты. Они устанавливаются специальными флагами:

**Флаг SUID** (сокр. _set user id_) — если он установлен при запуске, программа будет запущена от имени владельца. Этот флаг как раз помогает решить только что описанную проблему. При наличии SUID пользователь не имеет прав, например, на чтение и запуск, но запущенная программа будет работать с правами, которые имеются у её владельца. Если владельцем указан `root`, то программа будет выполняться с правами суперпользователя.

**Флаг SGID** (сокр. _set group id_) — этот флаг может быть установлен как для файла, так и для директории. В случае с файлом, флаг работает аналогично SUID, только программа получает права не владельца, а группы. Если SGID указан для каталога, то все создаваемые в нём файлы будут иметь группу директории, а не пользователя. Зачем это нужно? Например, имеется папка, в которой пользователи сохраняют свои файлы. Если эта директория имеет такой флаг, то у всех создаваемых файлов будет одна и та же группа. Соответственно, все пользователи этой группы будут иметь доступ к этим файлам. Таким образом, получилось организовать общую папку для определённого круга лиц.

**Sticky-bit** — этот флаг устанавливается для директорий, которые необходимо сделать общими, но с некоторыми ограничениями. Если Sticky-bit установлен, то пользователи могут создавать и делать что угодно со своими файлами, а также читать и выполнять файлы других пользователей. На удаление или изменение чужих файлов прав нет.

Пора перейти к примерам с Go. Для этого можно посмотреть на код, который создаёт директорию и файл с определёнными правами, а затем выводит информацию о правах доступа созданного файла. Сохраните код на компьютере и запустить пример. Можете поэкспериментировать и указывать разные права доступа к директории и файлу.

Скопировать код

GO

```
package main

import (
    "fmt"
    "log"
    "os"
    "path/filepath"
)

func main() {
    // получаем временную диркеторию
    tempDir := os.TempDir()
    dir := filepath.Join(tempDir, "margo")
    // создаём директорию
    // не забываем про ведущий ноль для прав доступа
    if err := os.Mkdir(dir, 0755); err != nil {
        log.Fatal(err)
    }
    defer os.RemoveAll(dir)

    filename := filepath.Join(dir, "readme.txt")
    // создаём файл
    // остальные пользователи не имеют никаких прав доступа
    if err := os.WriteFile(filename, []byte("привет"), 0660); err != nil {
        log.Fatal(err)
    }

    // Выводим идентификаторы текущего пользователя и группы
    fmt.Printf("UID: %d, GID: %d\n", os.Getuid(), os.Getgid())
    fmt.Println("Файл:", filename)

    // получаем информацию о файле
    fi, err := os.Stat(filename)
    if err != nil {
        log.Fatal(err)
    }

    // выводим права доступа в числовом виде
    fmt.Printf("Права доступа %s: 0%o\n", fi.Name(), fi.Mode().Perm())
    // выводим значения расширенных прав
    fmt.Printf("SUID: %d, SGID: %d, StickyBit: %d\n", fi.Mode()&os.ModeSetuid,
        fi.Mode()&os.ModeSetgid, fi.Mode()&os.ModeSticky)
} 
```

## Что в итоге

Есть три вида доступа: чтение, запись и выполнение. Для каждого файла и директории хранится информация о правах доступа для трёх категорий пользователей: владелец, группа, остальные.

Для представления прав доступа в читаемом виде используется символьная или числовая запись в восьмеричной системе счисления: чтение - r(4), запись - w(2), выполнение - x(1). Например, `rwxr-xr-x` соответствует `755` в восьмеричном представлении.

Существуют расширенные права: SUID, SGID, Sticky-bit. Они позволяют организовать совместную работу пользователей — запуск программ с правами владельца или группы, создание общих папок.

# Изменение прав доступа и владения файлами

Благодаря прошлому уроку, а, возможно, некоторые знали это и раньше, вы уже разбираетесь в правах доступа к файлам и директориям в Linux. Знаете, что есть три вида доступа — чтение, запись, выполнение — и три категории пользователей, для которых устанавливаются права, — владелец, группа и остальные. Теперь вы можете объяснить, что общего и в чём отличие `rwxrw--r--` и `774`.

Права доступа — параметр непостоянный. Периодически возникают причины, из-за которых их требуется изменить. В прошлом уроке вы создали скрипт и сразу понадобилось указать для него права на выполнение. В этом уроке будут рассмотрены команды, которые изменяют права доступа для файлов и директорий, а также команды, меняющие категории пользователей, например владельца или группы.

## Команда chmod

Для установки или изменения прав доступа для файлов и директорий в Linux используется команда **chmod**. Она имеет такой синтаксис: `chmod [опции] <права> <файл(ы)>`. Стоит отметить опцию `-v` — она выводит полную информацию об изменениях, и опцию `-R`, которая рекурсивно устанавливает права для всех файлов и поддиректорий внутри директории.

Команда `chmod` может как полностью устанавливать новые права, так и изменять определённые права для отдельных категорий пользователей. Права можно указывать в символьном или числовом виде. При установке всех прав удобнее использовать числовую запись, так как она короче, например `chmod 744 file.txt`. Программа сразу ожидает число в восьмеричном виде, поэтому ноль слева указывать не нужно.

Если необходимо изменить права у нескольких файлов, то можно перечислить их через пробел или использовать маску с символами `*` (любое количество символов, включая 0) и `?` (любой символ). Также можно указывать абсолютный или относительный путь к файлам.

Примеры вызовов:

- `chmod 755 file1.txt file2.txt` — смена прав доступа у двух файлов;
- `chmod -R 644 *.go` — установка прав доступа у всех файлов с расширением `.go` в текущей директории и всех поддиректориях;
- `chmod 660 /home/u/backup/backup??.gz` — изменение прав у файлов вида backup01.gz, backupaa.gz.

Только что с помощью `chmod` были установлены права сразу для всех пользователей, но эта команда также позволяет изменять отдельные права для конкретных категорий юзеров. Для этого права указываются в формате `[ugoa][+-=][rwx]`. На самом деле синтаксис более сложный, но этого варианта хватит, чтобы реализовать основные потребности.

В начале указываются категории пользователей: **u** — владелец, **g** - группа, **o** - остальные. Можно указывать несколько категорий, например, **ugo** эквивалентно **a** — все пользователи. Далее идёт описание действий: **+** - добавить право доступа, **-** — убрать его, **=** — присвоить права доступа. Остаётся указать права доступа в символьном виде.

Вот примеры запросов:

- `ug+w` — добавить право на запись для владельца и группы;
- `-x` или `a-x` — убрать право на выполнение для всех пользователей;
- `o=rx` — установить для остальных пользователей права только на чтение и запуск;
- `go-rw` — убрать права на чтение и запись для группы и остальных пользователей.

Выборочно изменять права доступа удобно, когда необходимо частично изменить права у множества файлов, которые имеют самые разные текущие комбинации прав. Например, с помощью `chmod o-w *` можно убрать только права на запись у остальных пользователей для всех файлов и папок в текущей директории. Все остальные права останутся без изменений.

Возможности команды `chmod` не ограничиваются только управлением тремя видами доступа. С её помощью можно устанавливать и расширенные права.

#### Как изменить расширенные права

Вы уже знакомы по прошлому уроку с расширенными правами SUID, SGID и Sticky-Bit. Их можно установить и убрать с помощью команды `chmod`. **t** отвечает за флаг Sticky-bit, **s** в комбинации с **u** относится к флагу SUID, а с **g** — к флагу SGID. Примеры:

- `u+s` устанавливает флаг SUID;
- `g+s` устанавливает флаг SGID;
- `+t` устанавливает флаг Sticky-bit;
- `u-s` убирает флаг SUID.

Установите права на запись для остальных пользователей и флаг Sticky-Bit для директории `scripts`.

total 12

drwxr-xr-x 6 margo margo 4096 Jan 10 17:31 ..

## Смена владельца и группы

Управлять доступом к файлам можно не только меняя права, но и изменяя владельца и группу у файлов и директорий. Для этого нужно воспользоваться командой **chown**. У неё есть аналогичные опции `-v` и `-R`, как у `chmod`. Только вместо прав следует указать имя нового владельца, группу, или их комбинацию через двоеточие. Если нужно изменить только группу, то перед ней ставится двоеточие.

- `chown bob hello.sh` меняет владельца у скрипта `hello.sh` на пользователя bob;
- `chown -R anna:buh *.pdf` pекурсивно устанавливает владельца (anna) и группу (buh) у всех pdf-файлов в текущей директории и поддиректориях.
- `chown :admin myapp` устанавливает группу (admin) у приложения.

Пришло время вспомнить про юзера `margo`. Сделайте текущей директорию `scripts` и попробуйте внести изменения в созданный недавно файл `readme.txt`. ## Изменение прав в Go

В пакете `os` стандартной библиотеки Go существуют функции для управления правами доступа и категориями пользователей. Запомнить их легко, так как они имеют такие же названия, как и рассмотренные выше команды.

Скопировать код

GO

```
func Chmod(name string, mode FileMode) error
func Chown(name string, uid, gid int) error 
```

Основные отличия состоят в том, что они принимают только числовые значения и идентификаторы, а также работают только с одним файлом или директорией. Вы не можете в параметре передать "file1.pdf file2.png" или маску подобно "*.txt", чтобы применить операцию для множества файлов. Кроме этого, `chmod` не может изменять отдельные права для отдельных категорий.

Пример программы, которая изменяет права доступа к файлу:

Скопировать код

GO

```
package main

import (
    "fmt"
    "log"
    "os"
)

func main() {
    fname := "/home/margo/scripts/readme.txt"
    err := os.Chmod(fname, 0777)
    if err != nil {
        log.Fatal(err)
    }
    fi, err := os.Stat(fname)
    if err != nil {
        log.Fatal(err)
    }
    fmt.Printf("Права доступа: 0%o\n", fi.Mode().Perm())
} 
```

Так как у `readme.txt` сейчас владелец `margo`, то запуск под другим пользователем приведёт к ошибке — права доступа распространяются на работу всех приложений.

Скопировать код

TXT

```
ak@ak-desktop:~/.../go-chmod$ go run main.go
2024/01/10 17:48:26 chmod /home/margo/scripts/readme.txt: operation not permitted
exit status 1 
```

Следует скомпилировать программу и перед запуском переключиться на пользователя `margo`.

Скопировать код

TXT

```
ak@ak-desktop:~/.../go-chmod$ go build
ak@ak-desktop:~/.../go-chmod$ su margo
Password: 
margo@ak-desktop:/home/ak/.../go-chmod$ ./go-chmod
Права доступа: 0777 
```

Работа с правами доступа и категориями пользователей на Go достаточно проста. Нужно только следить, чтобы пользователь, который запускает программу, имел права на выполнение соответствующих действий.

## Квиз 2/2

Отметьте верные утверждения.

Неправильный ответ

Изменить права доступа для владельца файла может только суперпользователь.

Права доступа для владельца может изменить владелец файла.

Правильный ответ

`chown margo file.txt` меняет владельца файла `file.txt`.

У файла будет новый владелец `margo`.

Неправильный ответ

Вызов `os.Chown("readme.txt", "margo", "margo")` изменит владельца и группу файла.

Второй и третий аргументы должны содержать числовые идентификаторы, а не строки.

Правильный ответ

Команда `chown :buh *.txt` эквивалентна `chgrp buh *.txt`.

`chown :group` меняет только группу, как и `chgrp group`.

Тоже правильный ответ

`chgrp -v sudo script.sh` изменит группу на `sudo` у файла `script.sh`.

`chgrp` изменяет группу для файлов или директорий.

## Подводим итоги

Команда `chmod` используется для установки прав доступа к файлам и директориям, а также для изменения отдельных прав у различных категорий пользователей.

Команда `chown` может изменять как владельца, так и группу файла или директории. Для запуска требуются права суперпользователя.

Команда `chgrp` аналогична `chown`, но служит для изменения только группы у файлов и директорий.

Пакет `os` стандартной библиотеки Go содержит функцию `Chmod()` — для установки прав доступа и функцию `Chown()` — для изменения владельца и группы.
