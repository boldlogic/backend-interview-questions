Вы только начали изучать многопоточность в Go, а уже узнали много важных вещей: научились создавать горутины, познакомились с типом `sync.WaitGroup`, разобрались зачем нужны примитивы синхронизации и изучили один из них — мьютекс. Сейчас пришла очередь познакомится ещё с одним механизмом для синхронизации горутин — **каналами** (англ. channels). Каналы — это инструмент не только синхронизации, но и обмена данными между горутинами.

Пример задачи, где могут пригодиться каналы — обработка фотографий. Одна горутина изменяет их размер, другая — увеличивает яркость, третья — чёткость. Изображение передаётся от одной горутины к другой. При этом нужно как-то избежать состояния гонки и точно знать, что изображение прошло все этапы обработки. Это не так просто, даже если использовать мьютексы. А вот каналы решают подобные задачи просто и элегантно.

## Как создать канал

Для определения канала в Go существует тип `chan`. По каналу можно и передавать, и получать данные, поэтому кроме ключевого слова `chan` необходимо указать тип данных, которые будут по нему передаваться. Всё вместе это выглядит так:

```
// определяем канал, который может передавать числа типа int
var ch chan int

// этот канал оперирует со строками
var chs chan string 

// определяем канал для передачи структур типа MyType
var cht chan MyType 
```

У каналов есть кое-что общее со слайсами:
- нулевое значение для каналов равно `nil`. Если просто определить переменную типа `chan`, она будет равна `nil` и непригодна для использования;
- чтобы начать работать с каналом, его нужно создать через функцию `make()`, указав в скобках `chan` и тип данных;
- для каналов можно вызвать функции `len()` и `cap()`, но об этом в следующем уроке.

Вот как создать канал с помощью функции `make()`:
```
// сразу определяем переменные и создаём каналы
ch := make(chan int)
chs := make(chan string)
cht := make(chan MyType) 
```

Канал может равняться `nil`, может быть рабочим, а ещё у него есть третье состояние — его можно закрыть. Канал закрывается функцией `close()`. Запись в закрытый канал приведёт к панике, а вот чтение из закрытого канала ничем не ограничивается и не блокируется. Каналы закрывать не нужно, если нет уверенности, что туда не будут записываться данные. Неиспользуемый канал автоматически закрывается, и сборщик мусора освобождает занимаемую этим каналом память. Если же в канал пишет только один «писатель», то лучше, чтобы он закрыл его после окончания записи, это позволит избежать многих проблем.
## Как записать и прочитать значения

Чтобы записать значение в канал или прочитать данные, используют оператор `<-`. Разница состоит только в том, что стоит справа, а что — слева от этого оператора.

Оператор `ch <- v` отправляет значение `v` в канал `ch`.

Для операции чтения может быть несколько вариантов:

- оператор `<- ch` просто забирает значение из канала. Его используют, когда нужна только синхронизация. Ещё его можно комбинировать с командой `return`: `return <- ch`. Можно указывать его и в параметрах функций;
- оператор `v := <- ch` присваивает значение из канала новой переменной `v`. У неё будет тот же тип, который был указан при создании канала;
- оператор `v = <- ch` присваивает значение из канала уже существующей переменной `v`. Если тип `v` отличается от типа значений канала, будет ошибка компиляции;
- операторы `v, ok := <- ch` и `v, ok = <- ch` позволяют дополнительно узнать, закрыт канал или нет. Если канал закрыт, переменная `ok` будет равна `false`, если открыт — `true`.

Механизм работы каналов делает их мощным инструментом по синхронизации и обмена данными между горутинами. Этот механизм можно описать в виде набора правил. Запомните их, они гораздо проще таблицы умножения:

- Запись в канал произойдёт, только когда другая горутина начнёт чтение из канала. До этого момента горутина будет находится в ожидании;
- Чтение из канала произойдёт, только когда другая горутина что-то запишет в канал. В противном случае, горутина будет стоять в ожидании;
- Чтение и запись в канал равный `nil` приведёт к блокировке. Выполнение текущей горутины остановится;
- Запись в закрытый канал приведёт к панике, а при чтении из такого канала возвращается нулевое значение его типа. Например, для канала `chan int` будут возвращаться нули, для канала `chan string` — пустые строки.

Лучше понять, как это всё работает, поможет такая аналогия. Представьте большое министерство, где все заняты каким-то делом. Чиновник готовит пакет документов, их нужно передать в другой отдел через окно. Он идёт с готовыми документами и ждёт, когда человек с другой стороны возьмёт у него этот пакет. От кого брать и кому отдавать пакет — роли не играет. Чиновников много, и они могут скапливаться с обеих сторон. Одним нужно отдать пакеты, а другим — взять их. Очередей никаких нет, в часы пик все толпятся и стараются быстрее передать или получить документы. В данной модели служащие — это горутины, пакет — это передаваемые данные, а окно — это канал.

Пример ниже демонстрирует простейшее использование канала. Функция `hello()` записывает строку в канал с определённой задержкой — она видна при запуске программы.

```
package main

import (
    "fmt"
    "time"
)

var ch chan string

func hello() {
    time.Sleep(1500 * time.Millisecond)
    ch <- "Привет, гофер!"
}

func main() {
//создаем канал
    ch = make(chan string)
// запускаем в горутине функцию hello
    go hello()

    fmt.Println("Ждём строку для печати")
    s := <-ch
    fmt.Println(s)
}
```

## Каналы на практике

Вы познакомились с правилами создания каналов и работы с ними. Сейчас будет пример кода, где есть:

- горутина, которая отправляет числа в канал;
- горутина, которая берёт из канала число, умножает его на 2 и передаёт в другой канал;
- цикл, в котором читаются и выводятся числа из результирующего канала.

Из примера видно, что с каналами можно работать, как с обычными переменными, и передавать их в параметрах функций. Также заметьте, что после отправки и обработки всех чисел соответствующие каналы закрываются, а циклы прекращают работу в этом случае. Для такой проверки используется выражение `v, ok := <-ch`. В противном случае программа завершится с ошибкой из-за бесполезного ожидания.

Изучите и запустите код.

```
package main

import (
    "fmt"
)

func do(in, out chan int) {
    defer close(out) // закрываем канал по окончании работы функции
    for {
        // получаем числа из канала
        v, ok := <-in
        if !ok {
            break
        }
        // отправляем результат в другой канал
        out <- 2 * v
    }
}

func main() {
    chIn := make(chan int)
    chOut := make(chan int)

    // запускаем горутину, которая преобразует числа
    go do(chIn, chOut)

    // горутина, которая отправляет числа на обработку
    go func() {
        // закрываем канал после отправки всех чисел
        defer close(chIn)

        for i := 0; i <= 50; i++ {
            chIn <- i
        }
    }()
    // в цикле читаем числа из результирующего канала
    for {
        v, ok := <-chOut
        if !ok {
            break
        }
        fmt.Print(v, " ")
    }
}
```

## Конструкция for ... range

Помните, в начале урока было сравнение каналов и слайсов? Кроме всего прочего, для чтения каналов можно использовать цикл `for ... range`, как будто идёт перебор элементов слайса.

```
for v := range ch {
    // тело цикла
} 
```

Цикл будет читать данные из канала до тех пор, пока канал не закроется. Этот код эквивалентен уже знакомому вам коду.

```
for {
    v, ok := <-ch
    if !ok {
        break
    }
    // тело цикла
} 
```

## Конструкция select

Вы изучили варианты, когда горутина читала данные только из одного канала. В Go есть конструкция `select`, которая позволяет работать с несколькими каналами. Это касается не только чтения, но и записи в канал. Ниже показан `select` с несколькими вариантами условий.

```
select {
case x := <-ch1:
    // блок выполнится, если раньше всего прочитается значение из канала ch1
case y := <-ch2:
    // блок выполнится, если раньше всего прочитается значение из канала ch2
case ch3 <- z:
    // блок выполнится, если раньше отправится значение в канал ch3
default:
    // опциональный блок
    // выполняется когда не сработало ни одно из условий
} 
```

Конcтрукция `select` перебирает все условия `case`. Если срабатывает один из вариантов, выполняется соответствующий блок и конструкция `select` завершает работу. Проверка вариантов идёт в случайном порядке. Например, если возможно выполнение двух условий `case`, выполнится всё равно одно. И не факт, что это именно то условие, которое описано раньше. Если ни один из блоков `case` невозможно выполнить, будет выполнен код секции `default` и управление перейдёт к следующему после `select` коду. Если `default` отсутствует, то `select` встаёт в режим ожидания до тех пор, пока не будет выполнен один из блоков `case`.

Если нужно постоянно проводить проверки условий `case`, то `select` помещают в цикл.

В примере ниже две горутины отправляют числа каждая в свой канал, а `select` читает и печатает данные из обоих каналов. В программе используется цикл с ограниченным количеством итераций, так как с циклом без условий программа будет выполняться до тех пор, пока её не прервут.

```
package main

import (
    "fmt"
    "time"
)

func main() {

    ch1 := make(chan int)
    ch2 := make(chan int)

    go func() {
        for {
            ch1 <- 0
            time.Sleep(50 * time.Millisecond)
        }
    }()
    go func() {
        for {
            ch2 <- 1
            time.Sleep(50 * time.Millisecond)
        }
    }()
    var v int
    for i := 0; i < 50; i++ {
        select {
        case v = <-ch1:
            fmt.Print(v, " ")
        case v = <-ch2:
            fmt.Print(v, " ")
        }
    }
}
```

Внутри секций конструкции `select` можно использовать оператор `break`, который обеспечивает выход из `select`. Есть несколько решений на случай, если нужно прервать цикл с `select`:

- выход из функции с использованием return;
- изменение условия, которое указано в цикле;
- применение `break` с указанием метки цикла.

Вот пример выхода с использованием `break` и меткой цикла.

```
loop: // метка цикла
    for {
        select {
        case x := <- ch:
            // ...
        case <-quit: 
            break loop // выходим из цикла
        }
    } 
```

Конструкция `select` может принимать данные из нескольких каналов, но представьте, что какой-то канал закроется. В этом случае чтение никак не блокируется и возвращаются нулевые значения, поэтому ситуацию с закрытием канала следует обязательно учесть.
```
for {
    select {
    case v, ok := <- ch:
        if !ok {
            // ...
        }
    // ...
    }
    // ...
} 
```

Если условие `case` с чтением из закрытого канала всё время будет получать управление, то `case` с чтением из канала равного `nil` игнорируется. Поэтому в случаях, когда никто больше не читает из канала, возможен такой вариант:


```
for {
    select {
    // этот вариант будет игнорироваться, если ch равен nil
    case v, ok := <-ch:
        if !ok {
            ch = nil // после этого данный case будет пропускаться
            continue
        }
        // ...
    }
} 
```

## Квиз 3/3

Допишите в программе тело функции `generator()`. Она должна писать в канал `ch` числа. Каждое следующее число `val` отличается от предыдущего на увеличивающуюся на 1 переменную `dif`. Выход из функции происходит, если операция чтения из канала `done` будет удачной. Таким образом, в функции нужно реализовать в цикле с помощью `select` запись в один канал и чтение из другого. Ниже приведены первые элементы ожидаемой последовательности чисел.

```
0   // dif = 0, val = 0
1   // dif = 1, val = (0 + 1)
3   // dif = 2, val = (1 + 2)
6   // dif = 3, val = (3 + 3)
10  // dif = 4, val = (6 + 4)
... 
```

```
package main

import (
	"fmt"
	 "time"
)

func generator(ch chan int, done chan struct{}) {
	val := 0
	dif := 0
	time.Sleep(1500 * time.Millisecond)
	for {
		select {
		case _, ok := <-done: ///Если канал закрыт, чтение никак не блокируется, и возвращает нулевые значения
			if !ok {
				done = nil // делаем нил
				return     // выходим из цикла
			}
		case ch <- (val + dif):
			val += dif
			dif++
		}
	}
}

func main() {
    // канал для получения значений
    ch := make(chan int)
    // канал для оповещения о конце работы, тип значений не важен
    done := make(chan struct{})

    go func() {
        // достаточно закрыть канал, чтобы из него прочиталось значение
        // это удобно, если его слушают несколько горутин
        defer close(done)

        for i := 0; i < 15; i++ {
            fmt.Print(<-ch, " ")
        }
    }()

    generator(ch, done)
}
```

## Что в итоге

Каналы — механизм для синхронизации и обмена данными между горутинами. Через канал можно передавать данные определённого типа. Перед началом работы с каналом его необходимо создать функцией `make()`.

Для записи в канал используется операция `ch <- v`, а для чтения — операции `<- ch`, `v := <- ch` и `v, ok := <- ch`. Запись или чтение из канала произойдёт, только когда другая горутина прочитает или что-то запишет в канал.

Канал может быть равен `nil` и может быть закрыт функцией `close()`. Чтение и запись в нулевой канал блокируется. Запись в закрытый канал вызывает панику, а при чтении из закрытого канала горутина всегда будет получать нулевое значение определённого в канале типа.

Конструкция `for ... range` для канала будет получать значения до его закрытия.

Конструкция `select` служит для одновременной работы с несколькими каналами.

Изучение каналов не закончено. В следующем уроке вы познакомитесь и научитесь работать с буферизированными каналами.
