# Go: ошибки

## Шпаргалка

1. Последний return — `error`; `nil` = успех, остальные значения не использовать.
2. Sentinel: `var ErrX = errors.New("...")`; сравнение — `errors.Is`, не `==` на обёрнутой.
3. Контекст: `fmt.Errorf("pkg op: %w", err)` — для цепочки только `%w`, не `%v`.
4. Типизированная ошибка — `errors.As` в цепочке; type switch без unwrap хуже.
5. Текст ошибки — строчная буква; префикс пакета или операции.
6. Ожидаемые сбои — `return error`, не panic.

---

## Интерфейс и идиома `(T, error)`

`error` — интерфейс с методом `Error() string`. Благодаря множественному return ошибки — обычный контракт функции.

Паттерн **ранний выход**: при `err != nil` сразу return, без лишних `else`.

```go
func ReadConfig(path string) (*Config, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return nil, fmt.Errorf("config: read %s: %w", path, err)
    }
    var cfg Config
    if err := json.Unmarshal(data, &cfg); err != nil {
        return nil, fmt.Errorf("config: parse: %w", err)
    }
    return &cfg, nil
}
```

**«Нет ошибки»** из `(T, error)` — `return v, nil`. Не `return v, (*MyError)(nil)` — typed nil в `error` не равен nil.

## Sentinel-ошибки

`errors.New("text")` каждый раз создаёт новое значение — для сравнения неудобно. На уровне пакета объявляют **sentinel**:

```go
var ErrNotFound = errors.New("user: not found")
```

Текст — с префиксом пакета/операции, строчной буквы (ошибки часто объединяют в цепочку).

Пакет возвращает **свои** sentinel-ошибки — часть публичного контракта. Проброс «сырых» ошибок из зависимостей наружу связывает вызывающий код с чужими типами.

## Обёртывание и цепочка (Go 1.13+)

```go
if err != nil {
    return fmt.Errorf("repo: get user %d: %w", id, err)
}
```

| Верба | Unwrap для `Is`/`As` |
|-------|----------------------|
| `%w` | да — сохраняет цепочку |
| `%v` | нет — только текст |

```go
errors.Is(err, ErrNotFound)   // ищет sentinel в цепочке
errors.As(err, &target)       // первая ошибка assignable к *target
errors.Unwrap(err)            // следующий уровень
```

`err == ErrNotFound` после wrap **не сработает** — сравнивается верхний уровень.

`errors.Join(errs...)` (Go 1.20+) — несколько независимых ошибок в одной; `Unwrap` возвращает слайс.

## Собственные типы ошибок

Когда нужны поля (код, HTTP status, offset):

```go
type ValidationError struct {
    Field string
    Msg   string
}

func (e *ValidationError) Error() string {
    return fmt.Sprintf("validation: %s: %s", e.Field, e.Msg)
}
```

Извлечение из цепочки:

```go
var ve *ValidationError
if errors.As(err, &ve) {
    // ve.Field, ve.Msg
}
```

`switch err.(type)` работает только с **непосредственным** динамическим типом; для обёрнутых — `errors.As`.

---

## *На собесе:*

- `%w` vs `%v` — только `%w` сохраняет unwrap.
- `==` на обёрнутой ошибке не находит sentinel внутри.

---

## На практике

- Wrap с контекстом: `fmt.Errorf("service create order: %w", err)`.
- Sentinel снаружи: `if errors.Is(err, sql.ErrNoRows) { ... }`.
- Поля из ошибки: `var pe *os.PathError; errors.As(err, &pe)`.
