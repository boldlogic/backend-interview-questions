# C4-L3. Component - Storage Node

Generic component level diagram for a distributed file storage node (anonymized example).

## Overview

This diagram shows the internal architecture of the **Storage Node** container — a service responsible for storing and managing files in a distributed file storage system.

The Storage Node is responsible for:
- Receiving, storing, and serving files via HTTP API
- Registering disks in the cluster and monitoring their health
- Optimizing performance through caching and deduplication
- Managing rate limits for disk operations

## Architectural Layers

### API Layer
- **HTTP Server** — accepts incoming requests from API Gateway, Replication Service
- **HTTP Client** — sends requests to Cluster Manager for registration and reporting

### Business Logic Layer
- **File Manager** — coordinates file operations, applies business rules
- **File Repository** — low-level file system operations (CRUD)

### Performance Optimization
- **Cache Layer** — caches frequently accessed files in memory
- **Deduplication Buffer** — prevents duplicate write operations using hash buffer
- **Rate Limiter** — manages worker queues, controls request processing rate

### Cluster Integration
- **Node Registration** — registers Storage Node in cluster, manages device metadata
- **Health Monitor** — monitors disk health and node availability

## Request Flow

### Write Operation (POST)
1. **External Services** → HTTP Server: POST request with file
2. **HTTP Server** → File Manager: delegates operation
3. **File Manager** → Deduplication Buffer: checks file hash (deduplication)
4. **File Manager** → Rate Limiter: checks worker queue limits
5. **File Manager** → File Repository: performs disk write
6. **File Repository** → File System: system I/O call
7. **File Manager** → Cache Layer: invalidates cache for this path

### Read Operation (GET)
1. **External Services** → HTTP Server: GET request
2. **HTTP Server** → File Manager: delegates operation
3. **File Manager** → Cache Layer: checks if file is in cache
   - **Cache hit**: returns file from memory (bypasses disk)
   - **Cache miss**:
     - File Manager → Rate Limiter: checks limits
     - File Manager → File Repository: reads from disk
     - File Repository → File System: system I/O call
     - File Manager → Cache Layer: adds file to cache

## Technical Details

- **Implementation**: Generic storage service (language-agnostic)
- **Protocols**: HTTPS (REST API), System I/O
- **Optimizations**: In-memory cache, hash-based deduplication, worker queue rate limiting
- **Monitoring**: Disk health checks, cluster registration

## Design Patterns

- **Coordinator Pattern**: File Manager coordinates operations across multiple components
- **Repository Pattern**: File Repository abstracts file system access
- **Cache-Aside Pattern**: Cache Layer handles read-through caching
- **Throttling Pattern**: Rate Limiter prevents system overload
