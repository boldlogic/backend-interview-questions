# Уровень компонентов. Элементы и метаданные

Объём метаданных об объектах зависит от их наличия и задачи, которую выполняет диаграмма. Для каждого компонента обычно описываются:

| Элемент         | Метаданные                                                                                                                                                                         | Пример                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Компонент       | Наименование компонента<br>Технология – описание имплементации, например Java object, Django controller<br>Описание – короткое выражение основных функций                          | Component name<br>[Component e.g. Spring Service]<br>Description of component role/responsibility  |
| Пользователи    | Название пользователя<br>Описание – роль и основные задачи в системе                                                                                                               | Person name<br>Description of person<br><br>External person name<br>Description of external person |
| Контейнер       | Название контейнера<br>Технология – описание имплементации, например asp.net web app, PG DB schema<br>Описание – короткое выражение основных функций или хранимых данных           | Container name<br>[Container e.g. Spring Service]                                                  |
| Внешние системы | Для уровня компонентов важны только системы, с которыми они взаимодействуют<br>Название системы<br>Описание – ее функционал                                                        | External system name<br>[Software System]<br>Description of external software system               |
| Границы         | Границы, которые показывают рамки контейнера, в которую входят компоненты. Граница – есть контейнер.                                                                               | Container name<br>[Container]                                                                      |
| Взаимодействие  | Цели («читает данные из», «отправляет отчет в»)<br>Технология (REST, Kafka)<br>Стиль (синхронный, батчовый, двухфазный коммит, асинхронный)<br>Протокол и номер порта (HTTPS, FTP) | e.g. Makes API calls<br>[e.g. JSON/HTTP]<br><br>e.g. Visits pages                                  |
