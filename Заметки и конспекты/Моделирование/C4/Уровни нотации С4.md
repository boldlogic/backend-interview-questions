# Уровни нотации С4

Целью создателя нотации является предоставление иерархичного набора «карт», которые позволяют менять масштаб рассмотрения архитектуры программного обеспечения, используя следующие контексты:

* **Начать с рамок системы:** определить систему, ее пользователей и внешние зависимости.
* **Показать контейнеры:** детализировать систему, показывая веб-приложения, базы данных, файловые системы, шины данных и другие элементы, из которых она состоит. На этом уровне становится видно, как функции системы распределены между частями.
* **Использовать «увеличительное стекло»:** углубиться и рассмотреть, из каких компонентов состоят контейнеры.
* **При необходимости погрузиться в код:** изучить иерархию и зависимости между элементами кода.

| Уровень | Описание | Назначение |
|---------|----------|------------|
| System Context | The system plus users and system dependencies. | Overview first |
| Containers | The overall shape of the architecture and technology choices. | |
| Components | Components and their interactions within a container. | Zoom and filter |
| Code | Component implementation details. | Details on demand |

Обычно системе не требуются все контексты. Следует использовать только те, которые приносят выгоду. Автор рекомендует всегда прорабатывать первые два уровня, третий — если он действительно необходим, а четвертый — только при крайней необходимости (он может быть сгенерирован в IDE).
