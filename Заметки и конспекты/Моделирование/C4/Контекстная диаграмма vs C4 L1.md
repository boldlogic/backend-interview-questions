# Контекстная диаграмма (DFD) vs C4 L1 (System Context)

## Классическая контекстная диаграмма (Context Diagram)

### Что это
**Контекстная диаграмма** — это диаграмма из методологии **DFD (Data Flow Diagram)** структурного системного анализа (Yourdon/DeMarco). Это самый верхний уровень DFD.

### Назначение
- Показать систему как **"черный ящик"** (не показывать внутреннее устройство)
- Идентифицировать **внешние сущности** (External Entities)
- Показать **потоки данных** между системой и внешней средой
- Определить **границы системы**

### Элементы
1. **Система** — один элемент в центре (круг или прямоугольник), показана как единое целое
2. **Внешние сущности** (External Entities) — источники и приемники данных:
   - Пользователи
   - Другие системы
   - Организации
   - Внешние сервисы
3. **Потоки данных** — стрелки с подписями, показывающие:
   - **Входы** в систему (что система получает)
   - **Выходы** из системы (что система отдает)

### Особенности
- ✅ Фокус на **потоках данных**, а не на взаимодействиях
- ✅ Система — **один элемент** (не раскрывается внутренняя структура)
- ✅ Показывает **что** входит и выходит, а не **как** это происходит
- ✅ Внешние сущности — это **источники/приемники данных**, не обязательно пользователи
- ✅ Обычно используется в **структурном анализе** и **бизнес-анализе**

### Пример структуры
```
[Внешняя сущность 1] --> (Система) : Поток данных 1
(Система) --> [Внешняя сущность 2] : Поток данных 2
```

## C4 L1 (System Context)

### Что это
**System Context** — первый уровень моделирования в **C4 Model** (Simon Brown). Показывает систему и её окружение.

### Назначение
- Показать **одну систему** и её окружение
- Идентифицировать **пользователей** системы
- Показать **внешние системы**, с которыми взаимодействует система
- Определить **границы** и **ответственность** системы

### Элементы
1. **Система** — центральный элемент (прямоугольник), но может быть показана с границами
2. **Person** — пользователи системы
3. **System** / **System_Ext** — другие системы (внутренние/внешние)
4. **Enterprise_Boundary** — границы организации
5. **Rel** — отношения/взаимодействия (не обязательно потоки данных)

### Особенности
- ✅ Фокус на **взаимодействиях** и **отношениях**, а не только на данных
- ✅ Показывает **пользователей** явно (Person)
- ✅ Может показывать **границы** (Enterprise_Boundary, System_Boundary)
- ✅ Показывает **технологии** и **протоколы** взаимодействия
- ✅ Используется в **архитектурном моделировании** и **документировании**

### Пример структуры
```
Person(user) --> System(centralSystem) : "Взаимодействие", "HTTPS"
System(centralSystem) --> System_Ext(externalSystem) : "Взаимодействие", "API"
```

## Сравнительная таблица

| Аспект | Контекстная диаграмма (DFD) | C4 L1 (System Context) |
|--------|----------------------------|------------------------|
| **Методология** | DFD (Data Flow Diagram) | C4 Model |
| **Фокус** | Потоки данных | Взаимодействия и отношения |
| **Система** | Один элемент (черный ящик) | Один элемент (может быть с границами) |
| **Внешние элементы** | Внешние сущности (любые источники/приемники) | Person, System, System_Ext |
| **Связи** | Потоки данных (входы/выходы) | Отношения (Rel) с описанием |
| **Детализация** | Только потоки данных | Может включать технологии, протоколы |
| **Границы** | Неявные (через потоки) | Явные (Enterprise_Boundary) |
| **Применение** | Структурный анализ, бизнес-анализ | Архитектурное моделирование, документация |
| **Уровень детализации** | Очень высокий (только входы/выходы) | Высокий (система + окружение) |

## Визуальные различия

### Контекстная диаграмма (DFD)
```
┌─────────┐
│ Клиент │
└────┬────┘
     │ Запрос на загрузку
     ▼
  ┌──────┐
  │ Система │
  └──────┘
     │ Файл
     ▼
┌─────────┐
│ Мониторинг│
└─────────┘
```

### C4 L1
```
Person(Client) --> System(NutsBasket) : "Загружает файлы", "HTTPS"
System(NutsBasket) --> System_Ext(Monitoring) : "Отправляет метрики", "API"
```

## Когда использовать что

### Используйте контекстную диаграмму (DFD), когда:
1. ✅ Нужно показать **потоки данных** (что входит, что выходит)
2. ✅ Система рассматривается как **"черный ящик"**
3. ✅ Работаете в методологии **структурного анализа**
4. ✅ Нужно определить **границы** через потоки данных
5. ✅ Документируете **бизнес-процессы** с точки зрения данных

### Используйте C4 L1, когда:
1. ✅ Нужно показать **взаимодействия** и **отношения**
2. ✅ Важны **пользователи** системы
3. ✅ Нужно показать **технологии** и **протоколы**
4. ✅ Документируете **архитектуру** системы
5. ✅ Нужны **границы** организации/домена
6. ✅ Планируете детализацию на уровнях L2, L3

## Практические рекомендации

### Можно ли использовать оба?
**Да!** Они дополняют друг друга:
- **Контекстная диаграмма** — для понимания **потоков данных**
- **C4 L1** — для понимания **архитектуры** и **взаимодействий**

### Что выбрать?
- Если работаете в **структурном анализе** → контекстная диаграмма
- Если документируете **архитектуру** → C4 L1
- Если нужно и то, и другое → создайте обе

### Синергия
Контекстная диаграмма может быть **входом** для создания C4 L1:
1. Определите потоки данных (контекстная диаграмма)
2. Преобразуйте в взаимодействия (C4 L1)
3. Детализируйте на L2, L3 (C4)
