# C4-L1. System Context - File Storage System

Generic system context diagram for a distributed file storage system (anonymized example).

## Overview

This diagram shows the high-level system context for a **File Storage System** — a distributed system for storing and managing files with an HTTP API.

The system provides:
- File upload, retrieval, and deletion via REST API
- Integration with media processing services
- Cluster management and operations capabilities

## Users

- **User** — Internal users who upload, retrieve, and delete files
- **Operations** — System administrators who manage cluster configuration

## Systems

- **File Storage System** — Distributed file storage with API for file operations
- **Media Processing Service** — Service for converting and transforming media files

## Use Cases

### User Interactions
1. **Upload Files** — Users upload files to the storage system via REST API
2. **Retrieve Files** — Users retrieve previously uploaded files
3. **Delete Files** — Users delete files from their storage space
4. **Process Media** — Users submit media files to the processing service

### Operations Interactions
1. **Manage Cluster** — Operations team manages cluster configuration and topology

### System Interactions
1. **Store Results** — Media Processing Service stores processed files back to the storage system

## Technical Details

- **Protocol**: HTTPS (REST API)
- **Access Control**: Authentication and authorization for users
- **Architecture**: Distributed file storage with cluster management
