# Контексты и модели архитектуры ПО

Для разработки ПО обычно необходимы несколько ракурсов рассмотрения. Каждый отдельно отражает информацию, нужную для написания технического задания, разработки, тестирования, развертывания и поддержки. Практика показывает, что для консистентного взгляда на ПО нужны следующие ракурсы:

| Ракурс | Описание | Использование в С4 |
|--------|----------|-------------------|
| Контекст | Окружающая среда архитектурного ландшафта – какие системы в него входят и взаимодействуют с ним. | Описывается дополнительным уровнем – system landscape view. |
| Данные | Данные, которые использует система во время работы (runtime), а также как, где и в каких объёмах информация хранится в ней (persistent). | Не является ракурсом С4. Лучше использовать модели типа сущность-связь. |
| Процессы | Поведение системы во время выполнения программы, при выполнении ее функций. Может также показывать параллелизм выполнения и интеграции. | Не является ракурсом С4. Лучше использовать модели BPMN. |
| Разработка | Система с точки зрения разработчика – как ее отдельные части и пакеты соединяются в системы | Отражается на всех уровнях С4. |
| Развертывание | Физическая и виртуальная инфраструктура, на которой работает система – её размещение, коммуникации и развёртывание компонентов. | Не является ракурсом С4. Лучше использовать диаграмму развертывания UML. |
| Поддержка | Аспекты поддержания работы системы: обновления, миграция данных, конфигурирование, администрирование, мониторинг, поддержку, установку и т.д. | Не является ракурсом С4. |
| Функционал | Конечные пользователи системы и функциональность, которую система предоставляет для них. Функции также можно описывать в форме сценариев использования, которые показывают, как системы используют данные в процессе работы, и для которых они были разработаны, развернуты и поддерживаются в работоспособном состоянии. | Функции определяются для любого объекта на модель С4. Дополняется моделью вариантов использования (UML use case diagram). |
