# Нотация C4: Элементы диаграмм

Нотация C4 определяет набор стандартных элементов для визуализации архитектуры программного обеспечения на разных уровнях абстракции. Ниже представлены основные элементы и правила их использования.

## 1. Пользователи (People)

*   **Внутренние пользователи (синий)**: Представляют людей, которые являются частью организации и взаимодействуют с системой (обычно администраторы, менеджеры).
    *   Визуализация: Темно-синяя иконка человека с именем и описанием.
*   **Внешние пользователи (серый)**: Представляют людей, находящихся вне границ организации, взаимодействующих с системой (физические лица, пользователи из других компаний).
    *   Визуализация: Серая иконка человека с именем и описанием.

## 2. Программные системы (Software Systems)

Системы отображаются только прямоугольниками.

*   **Внутренние системы (синий)**: Системы, находящиеся внутри компании, домена, безопасной зоны или других границ.
    *   Визуализация: Темно-синий прямоугольник с именем системы и описанием.
*   **Внешние системы (серый)**: Системы, находящиеся вне границ рассматриваемой архитектуры.
    *   Визуализация: Серый прямоугольник с именем внешней системы и описанием.

## 3. Контейнеры (Containers)

Для контейнеров используются различные формы в зависимости от их типа:

*   **1. Горизонтальный бочонок**: Очереди сообщений (например, Apache Kafka).
    *   Визуализация: Горизонтальный синий цилиндр.
*   **2. Прямоугольник**: Приложения (например, SpringBoot, ElasticSearch).
    *   Визуализация: Синий прямоугольник.
*   **3. Интерфейс (прямоугольник с верхней панелью)**: Для пользовательских интерфейсов (UI), таких как веб-браузеры (например, JavaScript, Angular).
    *   Визуализация: Синий прямоугольник с верхней панелью, имитирующей окно браузера.
*   **4. Вертикальный бочонок**: Обычно для баз данных (например, Oracle Database 12).
    *   Визуализация: Вертикальный синий цилиндр.

## 4. Компоненты (Components)

*   **Описание**: Составляющие части контейнеров.
*   **Визуализация**: Отображаются в виде прямоугольников (например, Spring Service) с именем компонента и описанием его роли/ответственности.

## 5. Границы (Boundaries)

*   **Границы системы**: Описываются пунктиром, внутри которого указывается наименование системы.
*   **Границы контейнера**: Описываются пунктиром, внутри которого указывается наименование контейнера.

## 6. Взаимодействия (Relationships/Arrows)

*   **Описание**: Стрелки отображают взаимодействия между элементами.
*   **Детализация**: Обычно на стрелках указывается технология взаимодействия (например, "e.g. Makes API calls [e.g. JSON/HTTP]", "e.g. Visits pages").

## 7. Легенда (Legend)

*   **Рекомендация**: Рекомендуется использовать легенду для описания используемых элементов и их значений рядом с диаграммой.
*   **Пример элементов легенды**: Person, Software System, Container, Component, External Person, External Software System.
