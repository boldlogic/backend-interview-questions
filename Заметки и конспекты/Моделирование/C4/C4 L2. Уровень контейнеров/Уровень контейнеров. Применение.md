# Уровень контейнеров. Применение

На этом уровне детализируется архитектура системы, показывая ее основные технические компоненты (контейнеры) и их взаимодействие с пользователями и внешними системами. Ниже приведены правила для создания таких диаграмм и пример клиентской банковской системы.

## Правила отображения общих компонентов

При работе с общими компонентами на уровне контейнеров можно следовать следующим рекомендациям:

*   **Если контейнер использует общий компонент (например, компонент мониторинга):**
    *   Отображать его как компонент каждого контейнера, который его использует.
    *   Не отображать его, если эта информация не несет ценности для текущей диаграммы.

*   **Если все компоненты используют один общий компонент (часто, компонент логирования):**
    *   Отобразить его без связей с другими компонентами, но с аннотацией «используется всеми компонентами».
    *   Не отображать его, если эта информация не несет ценности для текущей диаграммы.

## Пример диаграммы уровня контейнеров: Клиентская банковская система

Диаграмма демонстрирует внутреннюю структуру "Клиентской банковской системы" (Программная система), состоящую из нескольких контейнеров и их взаимодействий.

### Контейнеры и их описание:

*   **health-check-service**
    *   [Контейнер: SpringBoot]
    *   Получает данные загрузки и работоспособности сервисов в системе. Взаимодействует со всеми сервисами системы.
*   **Single-page приложение**
    *   [Контейнер: JavaScript и Angular]
    *   Обеспечивает функциональность пользователя через UI веб-браузера.
*   **Мобильное приложение**
    *   [Контейнер: Flutter]
    *   Обеспечивает ограниченную функциональность в рамках мобильного приложения.
*   **API gateway**
    *   [Контейнер: Java и Spring MVC]
    *   Обеспечивает функциональность управления API-запросов.
*   **База данных**
    *   [Контейнер: Postgre]
    *   Хранит информацию о пользователях, логирует историю и т.д.

### Взаимодействия:

*   **Single-page приложение** делает запросы [JSON/HTTPS] к **API gateway**.
*   **Мобильное приложение** делает запросы [JSON/HTTPS] к **API gateway**.
*   **API gateway** читает и записывает данные [SQL, JDBC] в **Базу данных**.
*   **health-check-service** взаимодействует со всеми сервисами системы, хотя явные стрелки на диаграмме не показаны, это указано в его описании.
