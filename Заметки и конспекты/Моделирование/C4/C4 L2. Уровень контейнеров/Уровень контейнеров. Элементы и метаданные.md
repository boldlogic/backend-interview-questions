# Уровень контейнеров. Элементы и метаданные

Объём метаданных об объектах зависит от их наличия и задачи, которую выполняет диаграмма. На контексте контейнеров обычно отображаются:

| Элемент | Метаданные | Пример |
|---------|-----------|--------|
| Контейнер/база данных: | Название контейнера<br>Технология – описание имплементации, например asp.net web app, PG DB schema<br>Описание - короткое выражение основных функций или хранимых данных | Четыре синих прямоугольника/цилиндра, каждый с названием контейнера (например, Apache Kafka, Springboot, JavaScript/Angular, Oracle Database) и описанием его типа и ответственности. |
| Пользователи: | Название пользователя<br>Описание - роль и основные задачи в системе | Две иконки человека (темно-синяя и темно-серая), с именем и описанием роли (например, Person name, External person name). |
| Системы | Название системы<br>Описание – ее функционал | Два прямоугольника (темно-синий и темно-серый), с названием системы (например, System name, External system name) и описанием ее функционала. |
| Границы | Границы, которые показывают рамки системы, в которую входят контейнеры. Граница – есть система. | Пунктирный прямоугольник с названием системы (например, System name [Software System]). |
| Взаимодействия | Цели («читает данные из», «отправляет отчет в»)<br>Технология (REST, Kafka)<br>Стиль (синхронный, пакетный, двухфазный коммит, асинхронный)<br>Протокол и номер порта (HTTPS, FTP) | Две стрелки, описывающие взаимодействие (например, Makes API calls [JSON/HTTP], Visits pages). |
