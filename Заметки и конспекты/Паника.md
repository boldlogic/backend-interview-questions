Паника выбрасывается только тогда когда код попадает в нестандартную ситуацию которую невозможно обработать

Defer выполняется даже в случае паники. 
Есть функция recover

это аварийное прекращение нормального выполнения текущей горутины. Когда вызывается `panic`, Go начинает раскручивать стек: выполняются отложенные `defer`, потом управление поднимается выше по стеку вызовов. Если панику никто не восстановил через `recover`, программа падает.

`recover` работает только внутри `defer`. Просто вызвать `recover()` где-то в обычном коде почти бесполезно: он вернёт `nil`.


**`recover` может перехватить панику только в deferred-функции той же горутины, где эта паника произошла.**

`panic` уместна для ситуаций уровня “невозможное состояние”, ошибка программиста, нарушенная инварианта, критичная ошибка инициализации, без которой приложение не может жить.

“Можно ли recover поймать панику из другой goroutine?” Нет. Только в той же goroutine.

. По умолчанию паника будет идти вверх по стеку и завершать все функции, пока не завершит функцию `main`, а вместе с ней и весь процесс.

`recover` — функция, которая позволяет восстановить выполнение программы в случае паники. Если на момент вызова `recover` произошла аварийная ситуация, то `recover` завершает её и возвращает значение ошибки (аргумент при вызове `panic`). Если аварийной ситуации не было, `recover` ничего не делает и возвращает `nil`.
