# Go: эмбеддинг

## Шпаргалка

1. Нет наследования — **композиция**.
2. Встраивание = продвижение полей и методов.
3. Затенение, не переопределение.
4. Полиморфизм — через интерфейсы, не через embed.

---

## Композиция вместо наследования

В классическом ООП «утка — птица» строит иерархию **is-a**. В Go — **has-a**: утка *содержит* клюв, туловище, лапы; не наследует «птицу».

**Встраивание (embedding)** — синтаксис композиции: анонимное поле типа внутри struct. Поля и методы встроенного типа **продвигаются** — доступны как собственные у внешней struct.

```go
type Outer struct {
    Inner
    Name string
}
// o.Field — то же, что o.Inner.Field
```

Встраивание ≠ подкласс. Встроенный тип не «родитель»; внешний тип не заменяет внутренний в иерархии классов.

В Go нет классического наследования: композиция через embed, сокрытие — на уровне пакета, полиморфизм — через интерфейсы.

---

## Доступ, затенение, конфликты

```go
func (s *Student) Debug() {
    s.Print()         // продвинутый метод
    s.Person.Print()  // явный путь
    s.Name = "Mark"   // продвинутое поле
}
```

Метод внешней struct с тем же именем, что у встроенного типа, **затеняет** продвинутый метод — переопределения нет. Доступ к встроенному: `s.Person.Print()`.

Если у **нескольких** встроенных типов одинаковый метод — **неоднозначный selector**, код не компилируется, пока не вызвать явно через имя поля.

Встроенный тип из **другого пакета** — продвижение только для **экспортируемых** полей и методов.

---

## Ограничения

Встраивать можно именованный тип или указатель на него (`T` или `*T`). Нельзя `**T`.

**Расширение внешнего типа:** нельзя править чужой пакет — создают свой тип с embed внешнего и добавляют методы/поля.

---

## На практике

- Embed для **has-a**, не для имитации иерархии классов.
- Именованное поле `inner T` вместо анонимного embed, если нужен узкий публичный API.
- `embed sync.Mutex` / `sync.RWMutex` — мьютекс в struct без отдельного поля `mu`.
- Embed **interface** — делегирование: внешний тип реализует часть методов, остальное пробрасывает во встроенный интерфейс.
- Зависимости собирают в `main`, реализации — в `internal`.
