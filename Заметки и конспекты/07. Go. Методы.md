# Go: методы

## Шпаргалка

1. Метод = `func` + receiver.
2. Receiver объявляют в **том же пакете**, что и тип.
3. `*T` — менять состояние; `T` — копия, неизменяемые типы.
4. Один стиль receiver на тип — не смешивать без причины.

---

## Синтаксис и область видимости

Метод — функция, привязанная к именованному типу. После `func` идёт **receiver** — по сути ещё один параметр:

```go
func (b *Buffer) Write(p []byte) (int, error) { ... }
```

Метод объявляют в том же пакете, что и тип. Методы бывают не только у struct — у любого пользовательского типа (`type ID int`, `type State string`, …).

Методы **не** изолируют типы внутри пакета: неэкспортируемые поля одного типа видны методам другого типа в том же пакете. Сокрытие — на уровне **пакета** (экспорт заглавной буквой), не на уровне типа.

Пример методов у не-struct типа:

```go
type DeliveryState string

func (s DeliveryState) IsValid() bool { ... }
func (s DeliveryState) String() string { return string(s) }
```

## Receiver: value vs pointer

|                         | `(t T)`                                       | `(t *T)`                                           |
| ----------------------- | --------------------------------------------- | -------------------------------------------------- |
| В метод попадает        | копия значения                                | указатель                                          |
| Меняет поля вызывающего | нет (кроме полей-ссылок: slice, map, pointer) | да                                                 |
| Вызов `x.Method()`      | как есть                                      | для value `x` компилятор подставит `(&x).Method()` |
| Вызов через `*p`        | компилятор подставит `(*p).Method()`          | как есть                                           |

**Ссылочные поля.** Value receiver получает копию struct, но slice/map/pointer внутри указывают на те же данные — мутация через них видна снаружи.

**Nil receiver.** Вызов `(*T)(nil).Method()` **компилируется**. Паника — только если метод разыменует receiver.

---

## Когда `T`, когда `*T`

| Ситуация                                       | Receiver              |
| ---------------------------------------------- | --------------------- |
| Метод меняет состояние типа                    | `*T`                  |
| Struct больше пары машинных слов               | `*T` (избежать копии) |
| Маленький неизменяемый тип (`time.Time`, enum) | `T`                   |
| Только чтение, тип крошечный                   | `T`                   |

Если хоть один метод мутирует receiver — **все** методы этого типа обычно на `*T`. Pointer methods не обязывают хранить только `*T`: `var x T; x.Method()` работает.

---

## Функция как поле struct

Поле типа `func` вызывается как метод, но:

- нет неявного доступа к struct — receiver нужно передать явно;
- можно переприсвоить во время выполнения;
- nil-поле → panic при вызове.

**Значение метода** (`x.Method`) и **выражение метода** (`T.Method`) сохраняют привязку к экземпляру или типу — удобно передавать в обработчик.

---

## На практике

- `NewT() *T`, если API строится на методах с receiver `*T`.
- Неизменяемый API: value receivers и неэкспортируемые поля (или только методы без мутаторов).
- Значение метода (`obj.Do`) — для передачи в обработчик с уже привязанным экземпляром.
