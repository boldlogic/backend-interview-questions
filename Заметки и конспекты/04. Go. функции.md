# Go: функции

## Шпаргалка

1. Аргументы передаются **по значению**: функция получает копию, исходная переменная снаружи не меняется.
2. Функции — **first-class**: у них есть тип `func(...) ...`, значение можно хранить, передавать и возвращать.
3. **Замыкание** захватывает переменные внешней области; захват может увести данные на heap и продлить их жизнь.

---

## Что реально проверяют на собесе

Отдельный вопрос «расскажи про функции» встречается редко. Чаще тема всплывает в live-коде или follow-up:

- можно ли передать функцию параметром другой функции;
- захват переменной цикла в closure или goroutine;
- как работает closure: что захватывается и как захваченные данные связаны с GC.

---

## Сигнатура и передача аргументов

Декларация функции задаёт имя, параметры и возвращаемые значения. Вложенную `func` внутри другой `func` объявить нельзя — это ограничение компилятора.

Каждый аргумент передаётся по значению. Если параметр — slice, map, chan или interface, копируется дескриптор или заголовок, а не «данные целиком»; общий backing или объект за указателем сохраняется. Это не передача по ссылке в смысле C++.

```go
func add(a, b int) int {
    a += b // меняется только локальная копия a
    return a
}
```

---

## First-class functions и литералы

У функции есть тип и значение. Значение можно присвоить переменной, передать аргументом и вернуть из другой функции. Метод тоже можно использовать как значение функции.
```go
var cmp func(a, b int) bool
cmp = func(a, b int) bool { return a < b }

sort.Slice(users, func(i, j int) bool {
    return users[i].Age < users[j].Age
})
```

Типичные паттерны из корпуса: callback, `sort.Slice`, middleware `func(http.Handler) http.Handler`.

Частая ошибка: путать тип `func(int) int` и вызов `f(x)` — первое это значение, второе выполняет функцию.

## Замыкания

Go — язык с лексической областью видимости: внутренняя функция «видит» переменные внешних блоков по тексту программы, а не только на время одного вызова.

**Замыкание** — функция, которая захватывает переменные из окружающего scope. Захваченные переменные живут, пока живёт замыкание; между вызовами замыкания их состояние сохраняется.

```go
func Generate(seed int) func() {
    return func() {
        fmt.Println(seed)
        seed += 2
    }
}

func main() {
    it := Generate(0)
    it() // 0
    it() // 2
}
```

После выхода из `Generate` переменная `seed` не уничтожается: она привязана к возвращённому closure.

**Переменная цикла.** До Go 1.22 в `for range` одна переменная цикла переиспользовалась на все итерации. Closure или goroutine, созданные в цикле, часто видели финальное значение. С Go 1.22 на каждую итерацию создаётся новая переменная. В старом коде ловушку обходили копией: `i := i` или передачей аргумента в IIFE.

**Escape analysis.** Если closure возвращается наружу или захватывает переменную, которую компилятор не может оставить на stack, данные оказываются на heap. Отсюда связь замыкания с GC: захваченные переменные могут жить дольше, чем кадр внешней функции.

## Возвращаемые значения

Функция может вернуть несколько значений:

```go
func div(a, b int) (q, r int, err error) {
    if b == 0 {
        return 0, 0, fmt.Errorf("division by zero")
    }
    return a / b, a % b, nil
}
```

**Именованные результаты** объявляют переменные в сигнатуре. При входе в функцию они получают zero value своих типов. «Голый» `return` без списка возвращает текущие значения этих переменных.

Именованные returns удобны для коротких функций, но ухудшают читаемость в длинных.

## Справочно: variadic и рекурсия

**Variadic:** последний параметр с `...T` принимает ноль или больше аргументов; внутри функции это slice.

```go
func Sum(x ...int) (res int) {
    for _, v := range x {
        res += v
    }
    return
}
```

**Рекурсия** — вызов функцией самой себя. Нужна терминальная ветка, иначе stack overflow. На собесах рекурсию как отдельную тему почти не спрашивают; важнее понимать stack frame.

---

## Паттерны из корпуса

- Callback и `sort.Slice` — передача func-литерала.
- Middleware `func(http.Handler) http.Handler` — функция высшего порядка над handler.
- `sync.Once.Do(func() { ... })` — передать инициализацию как func-значение.

## Code review: типичные флаги

| Флаг                                         | Проблема                                  |
| -------------------------------------------- | ----------------------------------------- |
| Closure на loop var в goroutine (до Go 1.22) | Все goroutine видят одно и то же значение |
| Путаница `func` type и вызова `f()`          | Тип — значение, скобки — выполнение       |

## Идиомы

- Functional options — `NewServer(opts ...Option)` для конфигурации с дефолтами; для простых объектов избыточно.
- Итератор на closure (`Generate` выше) — генератор с состоянием без отдельного типа; захваченная переменная хранит состояние между вызовами.
