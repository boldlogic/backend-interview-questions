Каналы в Go — инструмент синхронизации и обмена данными между горутинами




Нулевое значение для канала — nil. Без `make` — непригоден.
- Запись в канал произойдёт, только когда другая горутина начнёт чтение из канала. До этого момента горутина будет находиться в ожидании;
- Чтение из канала произойдёт, только когда другая горутина что-то запишет в канал. В противном случае, горутина будет стоять в ожидании;
- Чтение и запись в канал равный `nil` приведёт к блокировке. Выполнение текущей горутины остановится;
- Запись в закрытый канал приведёт к панике, а при чтении из такого канала возвращается нулевое значение его типа. Например, для канала `chan int` будут возвращаться нули, для канала `chan string` — пустые строки.

## 1. Типы каналов


### 1.3. Однонаправленные каналы

- Создаются как двунаправленные, но можно сделать однонаправленными через приведение типа или объявление параметров функций.
  - `chan<-` — только для записи.
  - `<-chan` — только для чтения.
Если в функции писать данные в однонаправленный канал для чтения, то будет ошибка компиляции.

## 2. Состояния каналов



### nil

- Неинициализированный канал (nil) нельзя использовать; блокирует операции.
- Чтение/запись в nil-канал блокирует горутину.
- Закрытие nil-канала вызывает панику.

### Не nil и не закрыт

- Неиспользуемый канал автоматически закрывается, освобождая память.
- Если есть один «писатель», он должен закрыть канал после записи, чтобы избежать проблем.
- Чтение блокируется до получения значения.

### Закрыт (`close(ch)`)

- Запись в закрытый канал вызывает панику.
- Чтение возвращает нулевое значение типа канала (например, 0 для `chan int`).
- Закрытие уже закрытого канала вызывает панику.

### Поведение записи и чтения по типу канала (открытый канал)

| Операция   | Небуферизованный                                 | Буферизированный                                                                                             |
| ---------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| **Запись** | Нельзя записать значение без готового получателя | Если есть место — без блокировки; если нет места — блокируется до чтения хотя бы одного значения             |
| **Чтение** | Блокирует горутину до получения значения         | Если есть значения — получаются; если пуст — блокируется до поступления; отдаёт значения в порядке их записи |

## 3. Операции

### Чтение

- Полная запись `v, ok := <-ch` позволяет узнать, закрыт ли канал (`ok = false`).
- Небуферизованный канал блокирует горутину до получения значения.
- В буферизованном канале:
  - Если есть значения, они получаются.
  - Если пуст, блокируется до поступления.
  - Отдаёт значения в порядке их записи.

### Запись

- Используется `ch <- v`.
- В небуферизованный канал нельзя записать значение без готового получателя.
- В буферизованном канале:
  - Если есть место, значение записывается без блокировки.
  - Если нет места, блокируется до чтения хотя бы одного значения.
- Каждое значение может быть прочитано только один раз.

### Цикл `for ... range`

- Получает значения из канала до его закрытия.

### Передача в функции

- Передаётся ссылка на канал. Изменения видны вне функции.

### Закрытие канала

- Закрывает тот, кто записывает. Закрытие возможно только после завершения всех записей. Не влияет на уже находящиеся данные.
- Буферизированный канал на самом деле закроется только тогда, когда его емкость станет равной нулю
