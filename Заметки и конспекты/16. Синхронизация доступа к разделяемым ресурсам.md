Неконтролируемое использование горутин может привести к ошибкам в работе программы. В первую очередь это касается доступа к разделяемым ресурсам. В контексте многопоточности, **разделяемые (общие) ресурсы** — это ресурсы, которые могут использоваться несколькими горутинами. Это могут быть файлы, базы данных, глобальные переменные любых типов и даже локальные переменные, если к ним обращаются две и более горутины.

Если горутины только получают значения, это не нарушает целостность данных. Такая операция может выполняться одновременно несколькими горутинами и называется **потокобезопасной**. В данном случае, операция чтения — потокобезопасная, но этого нельзя сказать про операцию записи или изменения значения. В этом уроке вы узнаете, как правильно работать с разделяемыми ресурсами.

Прежде чем приступать к вопросам синхронизации, нужно познакомиться с одним полезным типом.

## Тип sync.WaitGroup

В прошлом уроке функция `time.Sleep()` использовалась, чтобы дождаться завершения всех горутин. Но на самом деле это плохой подход. Отведённого времени может не хватить для завершения всех горутин. Или наоборот, программа будет впустую простаивать, когда все горутины закончили свою работу.

Если вы запустили несколько горутин и хотите дождаться их завершения в основной функции, для этого следует использовать переменную типа `sync.WaitGroup`. Она содержит счётчик, который равен количеству ещё не завершённых горутин. Префикс `sync` указывает, что этот тип входит в состав пакета `sync` стандартной библиотеки, который необходимо импортировать.

Для работы с `WaitGroup` достаточно запомнить три метода:

- `(*WaitGroup) Add(delta int)` — изменяет значение счётчика на указанную величину. Перед тем как создать горутину, достаточно вызвать `Add(1)`.
- `(*WaitGroup) Done()` — уменьшает значение счётчика на единицу. Этот метод вызывается в конце горутины.
- `(*WaitGroup) Wait()` — ожидает, когда значение счётчика будет равно нулю. Этот метод используется в основной функции, где нужно ожидать завершения горутин.

Вот как выглядит использование `sync.WaitGroup` на практике:
```
package main

import (
    "fmt"
    "sync"
)

func main() {
    var wg sync.WaitGroup //инициализируем переменную WaitGroup
    const n = 3

    for i := 0; i < n; i++ {
        wg.Add(1) // инкрементируем счётчик перед запуском горутины

        go func(i int) {
            // уменьшаем счётчик, когда горутина завершает работу
            defer wg.Done()

            for j := 0; j < 10; j++ {
                fmt.Print(i)
            }
        }(i)
    }

    wg.Wait() // ждём завершения всех горутин
    fmt.Println("\nконец")
}
```

Конструкция `defer wg.Done()` вызовет метод `wg.Done()` при завершении горутины. Такой отложенный вызов будет выполнен при любом `return` в теле функции.

Если число горутин известно заранее, можно сразу вызвать метод `Add()` с нужным значением. Например, убрать `wg.Add(1)` из цикла и вставить перед ним `wg.Add(n)`. Самое главное, чтобы сумма параметров в вызовах `Add()` совпала с количеством вызовов метода `Done()`. Если количество `Done()` будет меньше, `Wait()` не даст продолжить работу программы. А если горутин будет больше, `Wait()` дождётся только завершения указанного в `Add()` количества.

## Мьютексы

Вернёмся к вопросам синхронизации. Чтобы решить проблему модификации разделяемых ресурсов, нужно дать горутине, которая должна что-то изменить, исключительный доступ к изменяемому ресурсу. В этом случае можно спокойно изменить данные, а после разблокировать доступ для других горутин. Механизмы, которые позволяют горутине на время получить эксклюзивный доступ к данным, называются **примитивами синхронизации**.

**Мьютекс** (англ. mutual exclusion — «взаимное исключение») — примитив синхронизации, который позволяет только одной горутине находиться в части кода, где необходим эксклюзивный доступ. Когда первый поток входит в критическую секцию, мьютекс блокируется до тех пор, пока поток не покинет её. Пока мьютекс заблокирован, другие горутины ждут его разблокировки. Как только он разблокирован, одна из ожидающих горутин успевает заблокировать его и получить эксклюзивный доступ к критической секции кода.

Проще разобрать это на примере из реальной жизни. Представьте себе школьный урок во время которого учитель задаёт вопрос классу. Если все знающие ответ ученики начнут говорить, то ничего не будет понятно. Получается, что критическая секция в данном случае — это выступление ученика. Поэтому принято поднимать руку, то есть «заблокировать мьютекс» и получить возможность единолично выступить. Учитель выбирает кого-то одного и все слушают его ответ. Как только ученик сел, он «освобождает мьютекс» и учитель может дать высказаться другому ученику с поднятой рукой. Уже ответивший ученик может заниматься своими делами, смотреть в окно, слушать ответы или снова поднять руку.

Тип `sync.Mutex` — примитив, реализующий мьютекс в Go. Для переменной этого типа можно вызвать два метода:

- `(m *Mutex) Lock()` — блокирует мьютекс. Заблокировать мьютекс может только одна горутина. Если другая горутина вызывает этот метод, а мьютекс уже заблокирован, то она будет ждать его освобождения.
- `(m *Mutex) Unlock()` — разблокирует мьютекс. Горутина должна освободить мьютекс сразу после того, как она закончила выполнение критической секции.

Вот самая простая схема использования мьютекса:
```
// определяем переменную-мьютекс
var mu sync.Mutex

// Action может быть вызвана из нескольких горутин
func Action() {
    // ...
    mu.Lock()
    // здесь должна быть критическая секция кода, которую нужно
    // выполнить в эксклюзивном режиме
    // ...
    mu.Unlock()
    // ...
} 
```

Переменную-мьютекс `mu` нет смысла описывать внутри функции `Action()` — так она будет своя при каждом вызове функции и не сможет защитить критическую секцию кода. Поэтому она определена как глобальная переменная. Иначе получится, как будто несколько учителей в классе проводят опрос.

Вспомним пример из прошлого урока, демонстрирующий состояние гонки, где из разных горутин увеличивалось значение общего счётчика. Получается, что эта операция инкремента и будет критической секцией, которую нужно выделить с помощью мьютекса. Вот как должна выглядеть новая, правильная версия программы:
```
package main

import (
    "fmt"
    "sync"
    "time"
)

// можно определить переменную в main() перед циклом
var mu sync.Mutex

func main() {
    sum := 0

    for i := 0; i < 10; i++ {
        go func() {
            for j := 0; j < 100000; j++ {
                mu.Lock()
                sum++
                mu.Unlock()
            }
        }()
    }
    time.Sleep(500 * time.Millisecond)
    fmt.Println(sum)
}
```

При использовании мьютексов нужно обязательно придерживаться трёх основных правил:

1. После блокировки мьютекса его всегда нужно разблокировать. Если этого не сделать, другие горутины так и будут ожидать своей очереди на выполнение критической секции.
2. Если вы применяете мьютексы для синхронизации доступа к общим данным, следите за тем, чтобы не было горутин, работающих с этими данными без мьютекса. Например, если значение общей переменной меняется горутинами в двух местах, а мьютекс применяется только в одном, то смысла в этом нет, так как ошибки всё равно будут.
3. В общем случае нужно стремиться сокращать продолжительность выполняемого кода внутри критической секции.

## Квиз 2/2

Программа запускает 8 горутин, в которых добавляются элементы в глобальный слайс `[]int`. К сожалению, программа работает не так, как ожидается. Одному стажёру было дано задание добавить мьютекс для критической секции кода и с помощью `WaitGroup` дождаться завершения всех горутин. Стажёр определил глобальные переменные типа `sync.Mutex` и `sync.WaitGroup`, а после этого не появляется на рабочем месте уже несколько дней. Закончите за него эту программу.
```
package main

import (
    "fmt"
    "sync"
)

var list []int
var wg sync.WaitGroup
var mu sync.Mutex

func do() {
	defer wg.Done()
	for i := 0; i < 100; i++ {
		mu.Lock()
		list = append(list, i)
		mu.Unlock()
    }
}

func main() {
// Pge
	for i := 0; i < 8; i++ {
		wg.Add(1)
        go do()
	}
	wg.Wait()
    // проверка содержимого у слайса
    sum := 0
    for _, v := range list {
        sum += v
    }
    fmt.Println(len(list), sum)
}
```
Отлично! Можно сколько угодно раз запускать этот пример, и он всегда будет выдавать один и тот же результат.
## Подводя итог

- Методы типа `sync.WaitGroup` позволяют дождаться завершения горутин. `Add()` определяет значение счётчика, `Done()` уменьшает счётчик на единицу, `Wait()` останавливает выполнение до тех пор, пока счётчик не станет равным 0.
- Примитивы синхронизации — это механизмы, которые дают возможность горутине получить эксклюзивный доступ к данным.
- Мьютекс — примитив синхронизации, который следует блокировать перед работой с общими данными и разблокировать после. Если мьютекс заблокирован, другие горутины будут ждать его освобождения.
- Мьютекс блокируется методом `Lock()`, а разблокируется методом `Unlock()`. Важно не забывать освобождать мьютекс.
- Нельзя для одних горутин ограничивать доступ к данным с помощью мьютекса, а для других — оставлять доступ свободным.
