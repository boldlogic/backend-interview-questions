Когда множество горутин работают с числами, мапами, слайсами, это может приводить к неверным результатам или к состоянию гонки. Это **не потокобезопасные** типы данных. Из-за этого приходится использовать каналы или примитивы синхронизации, такие как мьютексы. **Потокобезопасность** заключается в корректной работе алгоритмов, функций, структур данных при наличии множества горутин, выполняющих эти операции. Например, функции пакета `fmt` потокобезопасны, вы можете спокойно использовать `fmt.Println()` в разных горутинах. Выводы в консоли смешиваться не будут: `fmt.Println("AAA")` и одновременное выполнение `fmt.Println("BBB")` не приведёт к выводу `ABBAAB`. Вы получите вывод одной строки, а затем — другой, но их порядок не определён.

Потокобезопасность типа означает, что все операции с экземплярами данного типа будут потокобезопасными, то есть будет обеспечен правильный результат при работе множества горутин, выполняющих эти операции. Из предыдущих уроков вы уже поняли, что `int` и `map` нельзя считать потокобезопасными. В этом уроке вы узнаете, что может предложить Go для потокобезопасной работы с числовыми типами и мапами без применения примитивов синхронизации.
## Тип sync.Map

В пакете `sync` есть потокобезопасный тип `Map` с набором методов для работы с ним. К сожалению, нельзя обращаться к переменным типа `sync.Map`, как к обычной мапе. Всё делается только через методы; ниже перечислены основные:

- `(m *Map) Delete(key any)` — удаляет значение указанного ключа;
- `(m *Map) Load(key any) (value any, ok bool)` — возвращает значение ключа или `nil`, если оно отсутствует. В первом случае `ok` равно `true`, во втором — `false`;
- `(m *Map) LoadOrStore(key, value any) (actual any, loaded bool)` — функция возвращает значение ключа, если оно существует. В противном случае, сохраняется и возвращается значение `value`. Возвращаемый параметр `loaded` равен `true`, если значение существует, и `false`, если оно было добавлено;
- `(m *Map) Range(f func(key, value any) bool)` — перебирает все элементы мапы и для каждого вызывает функцию `f`. Если нужно прекратить перебор, то функция должна возвратить `false`;
- `(m *Map) Store(key, value any)` — присваивает значение ключу.

Проверьте, насколько потокобезопасна работа с типом `sync.Map`. Обратите внимание, что для начала работы достаточно создать переменную типа `sync.Map`, вызов `make()` не нужен. Изучите код ниже и запустите его:
```
package main

import (
    "fmt"
    "sync"
)

func main() {
    var (
        m  sync.Map
        wg sync.WaitGroup
    )

    for i := 0; i < 10; i++ {
        wg.Add(1)
        // все горутины делают одну и ту же работу
        go func() {
            defer wg.Done()
            for j := 1; j <= 10; j++ {
                // пишем данные
                m.Store(j, j*j)
            }
        }()
    }
    wg.Wait()
    m.Range(func(key, value any) bool {
        fmt.Printf("%v x %v = %v\n", key, key, value)
        return true
    })
}
```

Ключи и значения `sync.Map` могут иметь любой тип. С одной стороны, это даёт волю фантазии разработчика, а с другой требует привести значения к определённому типу. Если, например, нужно просуммировать все значения массива, то это будет выглядеть так:

Скопировать код

```

    if v, ok := value.(int); ok {
        sum += v
    }
    return true
```

Потокобезопасность типа `sync.Map` относится только к обращению с элементами мапы. Если мапа содержит какие-то объекты, например, слайсы, работа непосредственно с этими объектами требует отдельной синхронизации.

Как видите, тип `sync.Map` обеспечивает потокобезопасность, но при этом не допускает привычного обращения к мапам. Кроме этого, реализация `sync.Map` отличается от простой комбинации `map` и `sync.RWMutex`. В каких-то ситуациях `sync.Map` может быть быстрее, а в каких-то медленнее реализации потокобезопасных мап с использованием `sync.RWMutex`.

## Квиз 1/3

Необходимо реализовать потокобезопасный временный кэш, используя `sync.Map`. Метод `Get()` возвращает значение элемента и логическое значение, которое указывает, существует значение или нет. Метод `Set()` добавляет в мапу значение с указанным ключом и устанавливает время его существования. По истечении этого времени элемент должен автоматически удалиться.
```
package main

import (
	"fmt"
	"sync"
	"time"
)

/*
Необходимо реализовать потокобезопасный временный кэш, используя sync.Map.
Метод Get() возвращает значение элемента и логическое значение,
которое указывает, существует значение или нет.
Метод Set() добавляет в мапу значение с указанным ключом и устанавливает время его существования.
По истечении этого времени элемент должен автоматически удалиться.*/

type Cache struct {
	store sync.Map
}

func NewCache() *Cache {
	return &Cache{
		// подумайте, нужно ли сюда что-то добавлять
		// ...
		store: sync.Map{},
	}
}

func (c *Cache) Set(key string, value int, d time.Duration) {
	// добавить значение в мапу
	// ...
	c.store.Store(key, value)
	time.AfterFunc(d, func() {
		c.store.Delete(key)
	})
}

func (c *Cache) Get(key string) (any, bool) {
	val, ok := c.store.Load(key)
	if !ok {
		return 0, false
	}
	res, ok := val.(int)
	if !ok {
		return 0, false
	}
	return res, true
}

func main() {
	// функция main() не требует изменений

	cache := NewCache()

	cache.Set("1", 567, 100*time.Millisecond)
	cache.Set("2", 22, 200*time.Millisecond)
	cache.Set("3", 9, 300*time.Millisecond)

	// определяем локальную фукнцию
	print := func() {
		for _, key := range []string{"1", "2", "3"} {
			v, ok := cache.Get(key)
			if ok {
				fmt.Print(v, " ")
			}
		}
		fmt.Println()
	}

	print()
	time.Sleep(150 * time.Millisecond)
	print()
	time.Sleep(100 * time.Millisecond)
	print()
}

```

## Пакет sync/atomic

Чтобы было понятно, для чего нужен пакет `sync/atomic`, стоит познакомиться с понятием **атомарной операции**. **Атомарная операция** — это операция, которая выполняется за один шаг относительно других горутин. Горутина не может прервать своё выполнение во время такой операции, а кроме этого, другие горутины не могут начать эту же самую операцию. Это похоже на транзакции из темы про базы данных, только у атомарной операции не может быть отката.

Вспомните, как в одном из уроков про многопоточность вы пытались увеличивать значение счётчика. Увеличение числа — это не атомарная операция, поэтому требовалось использовать мьютексы. Но что если нужен очень быстрый счётчик, который должен обрабатывать сотни тысяч обращений в секунду? В такой ситуации мьютексы будут замедлять его работу. По сути требуется превратить некоторые базовые действия с числами в атомарные операции, чтобы можно было избавиться от мьютексов. Например, можно изменить числовую переменную на какую-то величину и присвоить ей новое значение. Для решения подобных задач и был написан пакет `sync/atomic`. В этом пакете реализованы атомарные операции для целочисленных типов: `int32`, `int64`, `uint32`, `uint64`.

Ниже описаны основные функции для типа `int64`. Аналогичные функции существуют и для остальных типов. Заметьте, что во всех функциях передаются указатели на числовые значения, для которых необходима атомарность.

`AddInt64(addr *int64, delta int64) (new int64)` — добавляет `delta` к значению `addr` и возвращает новое значение.

```
var addr int64
atomic.AddInt64(&addr, 1) // прибавляем 1 
```

`CompareAndSwapInt64(addr *int64, old, new int64) (swapped bool)` — сравнивает значение `addr` с `old` и заменяет на `new`, если они равны. Функция возвращает `true`, если значение `addr` было заменено.

```
var addr int64
atomic.CompareAndSwapInt64(&addr, 0, 48) 
```

`LoadInt64(addr *int64) (val int64)` — возвращает значение `addr`.

```
var addr int64
val := atomic.LoadInt64(&addr) 
```

`StoreInt64(addr *int64, val int64)` — устанавливает новое значение `addr`.

```
var addr int64
atomic.StoreInt64(&addr, 15) 
```

`SwapInt64(addr *int64, new int64) (old int64)` — устанавливает новое значение `addr` и возвращает предыдущее.

```
var addr int64
old := atomic.SwapInt64(&addr, 33) 
```

Испытайте счётчик с использованием атомарных операций:
```
package main

import (
    "fmt"
    "sync"
    "sync/atomic"
)

func main() {
    var wg sync.WaitGroup
    var counter int64

    for i := 0; i < 10; i++ {
        wg.Add(1)

        go func() {
            defer wg.Done()
            for j := 0; j < 100000; j++ {
                atomic.AddInt64(&counter, 1)
            }
        }()
    }
    wg.Wait()
    fmt.Println(counter)
}
```

1000000

В коде не используются мьютексы, но благодаря атомарной операции `Add()` счётчик в результате содержит правильное значение.

## Квиз 2/3

Какая функция пакета `sync/atomic` атомарно реализует то же, что функция `Foo`?

```
func Foo(i *int64, v int64) int64 {
    ret := *i
    *i = v
    return ret
} 
```

`StoreInt64`

`StoreInt64` только устанавливает значение.

`AddInt64`

`AddInt64` изменяет значение на указанную величину.

Правильный ответ

`SwapInt64`

`SwapInt64` присваивает новое значение и возвращает предыдущее.

`LoadInt64`

`LoadInt64` возвращает текущее значение.

В пакете `sync/atomic` определены типы-обёртки: `atomic.Bool`, `atomic.Int32`, `atomic.Int64` и так далее. Для начала работы с такими «обёртками» достаточно описать переменную нужного типа, например, `var i atomic.Int64`. Эти типы вместо функций имеют соответствующие методы. Вот, например, методы для типа `atomic.Int64`.

- `(x *Int64) Add(delta int64) (new int64)`,
- `(x *Int64) CompareAndSwap(old, new int64) (swapped bool)`,
- `(x *Int64) Load() int64`,
- `(x *Int64) Store(val int64)`,
- `(x *Int64) Swap(new int64) (old int64)`.

## Что в итоге

Операция потокобезопасная, если она корректно выполняется одновременно во многих горутинах. Тип называется потокобезопасным, если все операции для переменных этого типа потокобезопасны.

Тип `sync.Map` — потокобезопасная реализация мапы. Работа с такой мапой осуществляется через специальные методы.

Атомарная операция — это операция, которая выполняется за один шаг относительно других горутин. Пакет `sync/atomic` содержит атомарные операции для работы с целыми числами.

Помимо набора атомарных функций для типов `int32`, `int64`, `uint32`, `uint64`, существуют типы-обёртки, которые могут сделать код лаконичнее.

В этом уроке вы узнали, что такое потокобезопасность и атомарные операции. Научились использовать тип `sync.Map` и познакомились с пакетом `sync/atomic`, который реализует атомарные операции для целых чисел.
