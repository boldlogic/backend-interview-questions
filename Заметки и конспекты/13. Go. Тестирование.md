# Go: тестирование

## Шпаргалка

1. Тесты в `*_test.go`, сигнатура `func TestXxx(t *testing.T)`.
2. Table-driven: `[]struct{ name, ... }` + `t.Run(name, ...)`.
3. `go test ./...`; `-run Regexp`, `-cover`, `-race` на concurrent-код.
4. Mock = тип с теми же методами, что interface зависимости; inject в конструктор.
5. `package foo_test` — black-box тест и обход циклических импортов.

---

## Unit vs integration

**Unit** — функция/метод в изоляции; внешние зависимости подменяют mock/fake.

**Integration** — реальная БД, брокер, HTTP; медленнее, хрупче. Выносят в отдельный job или build tag:

```go
//go:build integration
```

На CI integration часто только с контейнером Postgres/Kafka.

---

## `testing.T`

| Метод | Поведение |
|-------|-----------|
| `Error` / `Errorf` | fail, тест продолжается |
| `Fatal` / `Fatalf` | fail + stop (panic внутри) |
| `Skip` / `Skipf` | пропуск (нет env, short mode) |
| `Log` / `Logf` | лог с привязкой к тесту |
| `Run(name, fn)` | subtest |
| `Helper()` | маркер helper — stack trace указывает на вызывающий тест |

Файлы `*_test.go` не попадают в бинарь приложения.

## Table-driven

Кейсы в слайсе; на каждый — subtest. Отдельные rows для error path, nil, границ.

```go
func TestDivide(t *testing.T) {
    tests := []struct {
        name    string
        a, b    int
        want    int
        wantErr bool
    }{
        {"ok", 4, 2, 2, false},
        {"zero denom", 1, 0, 0, true},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := Divide(tt.a, tt.b)
            if (err != nil) != tt.wantErr {
                t.Fatalf("err = %v, wantErr %v", err, tt.wantErr)
            }
            if got != tt.want {
                t.Errorf("got %d, want %d", got, tt.want)
            }
        })
    }
}
```

Тесты не должны зависеть от порядка выполнения и глобального состояния друг друга.

## Запуск и coverage

```bash
go test ./...
go test -run '^TestDivide$' ./pkg
go test -cover ./...
go test -coverprofile=coverage.out ./...
go tool cover -html=coverage.out
go test -race ./...
```

`-count 1` отключает кеш результатов `go test`. `-short` — `t.Short() == true`, длинные тесты можно Skip.

**`-race`:** race detector на concurrent-код; прогон медленнее и жрёт больше RAM. Ловит data race, **не** deadlock. В CI — на пакеты с goroutines; локально перед PR.

## Линтеры

| Инструмент | Назначение |
|------------|------------|
| [`go vet`](https://pkg.go.dev/cmd/vet) | Подозрительные конструкции: unreachable code, `Printf` с неверным verb, copy lock, … — встроен в toolchain |
| [golangci-lint](https://golangci-lint.run/) | Оркестратор множества analyzers + настраиваемый набор правил в CI |

`go vet ./...` — минимум перед коммитом; golangci-lint — типичный gate в CI вместе с `go test`.

## Testify (кратко)

[testify](https://github.com/stretchr/testify): `assert` — fail и идти дальше; `require` — fail и stop (аналог Fatal). Не замена `testing`, а sugar поверх.

## Моки через interface

Prod-код принимает interface; в тесте — struct с контролируемым поведением:

```go
type UserStore interface {
    Exists(ctx context.Context, email string) (bool, error)
}

type mockStore struct {
    emails map[string]bool
}

func (m *mockStore) Exists(_ context.Context, email string) (bool, error) {
    return m.emails[email], nil
}
```

Mock реализует тот же interface, что prod-зависимость. Счётчики вызовов и проверка аргuments — поля struct.

Не подменять транспорт, если цель — проверить бизнес-логику слоя выше.

## HTTP handler без порта

```go
req := httptest.NewRequest(http.MethodGet, "/users/1", nil)
rec := httptest.NewRecorder()
handler.ServeHTTP(rec, req)
if rec.Code != http.StatusOK { ... }
```

`httptest.NewRecorder` — `ResponseWriter`; запрос без listen.

## На практике

- В таблице — отдельный case на каждый error path.
- Helper-функции setup/assert — с `t.Helper()`.
- `package foo_test` + import `foo` — тест только публичного API.
- Concurrent-код — `go test -race` в CI на пакетах с goroutines.
