## Что такое Docker-образ

**Docker-образ** — это шаблон с инструкциями по созданию Docker-контейнера; он доступен только для чтения.

Часто бывает, что образ основан на другом образе с некоторой дополнительной настройкой. Например, можно создать образ, основанный на образе Ubuntu, но с установленным языком программирования Go.

Вы можете создавать собственные образы или использовать те, которые созданы другими и опубликованы в реестре Docker Hub.

## Официальные и неофициальные образы

В Docker Hub есть официальные и неофициальные образы.

**Официальные Docker-образы** — это кураторский набор репозиториев Docker, размещённых в Docker Hub. Компания Docker Inc. спонсирует специальную команду, которая отвечает за проверку и публикацию официальных образов, другими словами — курирует их. Официальные Docker-образы часто являются отправной точкой для создания пользовательских образов.

К официальным образам относятся операционные системы (Ubuntu, Alpine), языки программирования (Go, Rust, Python) и системы управления базами данных (MySQL, PostgreSQL, Redis).

Официальные образы — одни из самых безопасных в Docker Hub, они предоставляют хорошую документацию и иллюстрируют лучшие практики создания Dockerfile. Dockerfile — это текстовый файл со списком команд, нужных для создания образа. Подробнее об этом инструменте вы узнаете чуть позже.

Официальные образы отмечены на Docker Hub специальным значком:

![](https://code.s3.yandex.net/go/go1F/42.%D0%9E%D0%B1%D1%80%D0%B0%D0%B7%D1%8B.%D0%A1%D0%BA%D1%80%D0%B8%D0%BD3.png)

Любой пользовательский образ создаётся на основе уже существующего. Например, если вы написали проект на Go, базовым для этого проекта будет образ golang, где хранится язык программирования Go.

Причина, по которой отказываются от официальных образов чаще всего, — стремление оптимизировать размер образа. Например, образы многих операционных систем содержат полный перечень команд и программ. Возможно, не все они нужны для проекта. Но размер образа, построенного на основе такого официального образа, сильно увеличится.

И всё же начинающим программистам лучше использовать официальные Docker-образы. Во-первых, это безопаснее. Во-вторых, для официальных образов прописана чёткая документация. И в-третьих, такие образы содержат лучшие практики и предназначены для наиболее распространённых задач. А мысли об оптимизации придут с опытом, с этим торопиться не стоит.

## Другие команды Docker

Некоторые контейнеры недостаточно запустить простой командой, как вы это делали с командой `docker run hello-world`. У команды `docker run` довольно много опций, вот самые основные варианты:

1. Команда `docker run -it bash` — запускает контейнер официального образа bash. **Bash (Bourne again shell)** — это стандартная командная оболочка в большинстве дистрибутивов Linux и macOS, а также язык для этой оболочки. Опция `-it` — это сокращение от `--interactive` и `--tty`. Используя эти опции, вы как бы переноситесь «внутрь» контейнера. Чтобы стало понятней, попробуйте выполнить команду без этих опций. А потом — с ними. Некоторые образы ожидают, что вы будете взаимодействовать с их контейнером. К таким образам относятся, например дистрибутивы Linux, Bash, как в нашем случае. Поэтому надо как бы погрузиться в контейнер, чтобы там можно было с ним «общаться».
    
2. После запуска контейнера вы можете посмотреть, какие ещё контейнеры запущены. Команда `docker ps` выводит список всех запущенных контейнеров в виде таблицы. Если у вас уже запущен контейнер `bash`, откройте ещё одно окно (или вкладку) терминала и введите эту команду. Вот как всё выглядит:
    

Запущенный контейнер `bash`:

```
>docker run -it bash
bash-5.2# 
```

Если в другом окне или вкладке терминала выполнить команду `docker ps`, получится следующий результат:


```
>docker ps
CONTAINER ID   IMAGE     COMMAND                  CREATED              STATUS              PORTS     NAMES
b9914aa51b77   bash      "docker-entrypoint.s…"   About a minute ago   Up About a minute             inspiring_goldberg 
```

Самая важная информация — в первых двух столбцах. В столбце **CONTAINER ID** указан ID запущенного контейнера. В столбце **IMAGE** — имя образа, который вы запустили; сейчас это `bash`.

1. Команда `docker stop <CONTAINER ID>` останавливает контейнер. Давайте попробуем остановить запущенный контейнер. Для этого скопируйте ID контейнера. Будьте внимательны: у вас наверняка будет другой ID, не тот, который указан в тексте урока; это нормально. Теперь если вы снова выполните команду `docker ps`, таблица будет пустой, потому что не запущен ни один контейнер.


```
>docker stop b9914aa51b77
b9914aa51b77
>docker ps
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES 
```

1. Остановленный контейнер никуда не исчез. Он просто не выполняется. Это можно проверить с помощью уже знакомой команды с дополнительной опцией: `docker ps -a`. Опция '-a' говорит команде `ps` показать все контейнеры, в том числе неработающие в данный момент. Вот что покажет команда:


```
>docker ps -a
CONTAINER ID   IMAGE     COMMAND                  CREATED          STATUS          PORTS     NAMES
b9914aa51b77   bash      "docker-entrypoint.s…"   56 seconds ago   Up 55 seconds             competent_allen 
```

1. Команда `docker rm <CONTAINER ID>` удаляет контейнер по его ID. Попробуйте удалить свой контейнер.

А ещё можно запускать контейнер так, чтобы при его остановке он удалялся автоматически.

1. Команда `docker run --rm -it bash` запускает контейнер официального образа bash. Опция `--rm` автоматически удаляет контейнер, когда вы его останавливаете.

Теперь самостоятельно попробуйте остановить контейнер и вывести сначала список запущенных контейнеров, а потом список всех — и запущенных, и остановленных. Какой получился результат?
