Теперь, когда вы познакомились с реестром Docker Hub и научились запускать образы, которые создало сообщество Docker, настала пора присоединится к этому сообществу! В этом уроке вы научитесь создавать собственные Docker-образы.

Как правило, нет необходимости создавать всё с нуля: часто Docker-образ создаётся на основе другого Docker-образа. Но если вам интересно сделать всё самостоятельно, то вы сможете это делать, когда лучше освоитесь с Docker.

## Проект, для которого создаётся образ

Итак, прежде чем создавать образ, нужно определиться с проектом. В качестве проекта, для которого будет создаваться образ, в этом уроке выступит финальное задание из темы про REST API, написанное на Go.

Нет причин сейчас усложнять, поэтому проект уместился в одном файле. Как вы помните, это некая интерпретация приложения TODO-LIST. Вы уже выполняли это задание, поэтому сейчас просто приведём готовый код.

1. Первым делом создайте каталог для вашего проекта, войдите в него и создайте модуль Go. Скорее всего, вы уже знаете, о чём идет речь, и выполните эти шаги без дополнительных подсказок.
    
2. Теперь создайте файл main.go и добавьте в него код:
    

```
package main

import (
    "bytes"
    "encoding/json"
    "fmt"
    "net/http"

    "github.com/go-chi/chi/v5"
)

// Task ...
type Task struct {
    ID           string   `json:"id"`
    Description  string   `json:"description"`
    Note         string   `json:"note"`
    Applications []string `json:"applications"`
}

var tasks = map[string]Task{
    "1": {
        ID:          "1",
        Description: "Сделать финальное задание темы REST API",
        Note:        "Если сегодня сделаю, то завтра будет свободный день. Ура!",
        Applications: []string{
            "VS Code",
            "Terminal",
            "git",
  },
 },
    "2": {
        ID:          "2",
        Description: "Протестировать финальное задание с помощью Postman",
        Note:        "Лучше это делать в процессе разработки, каждый раз, когда запускаешь сервер и проверяешь хендлер",
        Applications: []string{
            "VS Code",
            "Terminal",
            "git",
            "Postman",
        },
    },
}

func getTasks(w http.ResponseWriter, r *http.Request) {
    resp, err := json.Marshal(tasks)
    if err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusOK)
    w.Write(resp)
}

func postTask(w http.ResponseWriter, r *http.Request) {
    var task Task
    var buf bytes.Buffer

    _, err := buf.ReadFrom(r.Body)
    if err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    if err = json.Unmarshal(buf.Bytes(), &task); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    tasks[task.ID] = task

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)
}

func getTask(w http.ResponseWriter, r *http.Request) {
    id := chi.URLParam(r, "id")

    task, ok := tasks[id]
    if !ok {
        http.Error(w, "задачи с таким ID не существует", http.StatusBadRequest)
        return
    }

    resp, err := json.Marshal(task)
    if err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusOK)
    w.Write(resp)
}

func deleteTask(w http.ResponseWriter, r *http.Request) {
    id := chi.URLParam(r, "id")

    task, ok := tasks[id]
    if !ok {
        http.Error(w, "задачи с таким ID не существует. Не могу удалить", http.StatusBadRequest)
        return
    }

    delete(tasks, task.ID)

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusOK)
}

func main() {
    r := chi.NewRouter()

    r.Get("/tasks", getTasks)
    r.Post("/tasks", postTask)
    r.Get("/tasks/{id}", getTask)
    r.Delete("/tasks/{id}", deleteTask)

    if err := http.ListenAndServe(":8080", r); err != nil {
        fmt.Printf("Ошибка при запуске сервера: %s", err.Error())
        return
    }
} 
```

1. Вы могли заметить, что в проекте используется сторонний роутер `chi`, который нужно добавить. Раньше вы уже добавляли сторонние пакеты и модули в проект. Проделайте это с `chi`.

Теперь всё готово для создания Docker-образа. Docker-образы создаются на основе файла Dockerfile и контекста.

**Контекст** — это все файлы и каталоги, которые должны войти в Docker-образ. А **Dockerfile** — это текстовый файл, с которого обычно начинают создавать образы Docker. Вот о нём стоит поговорить поподробнее.

## Dockerfile

Docker может создавать образы автоматически, считывая инструкции из Dockerfile.

В корне приложения, для которого создается Docker-образ, нужно создать Dockerfile. Этот текстовый файл содержит все команды, которые пользователь может выполнить в командной строке для сборки Docker-образа.

Основной формат Dockerfile такой:

Скопировать код

DOCKERFILE

```
# Комментарий
INSTRUCTION arguments 
```

Регистр инструкций не учитывается, но их принято писать ЗАГЛАВНЫМИ буквами. И выполняются инструкции в Dockerfile по порядку.

1. Создайте Dockerfile в корневом каталоге проекта.

Образы могут быть унаследованы от **родительского образа**, на основе которого вы создаете свой. Следовательно, вместо создания образа с нуля, вы можете использовать официальный образ Go, в котором уже есть все необходимые инструменты и библиотеки для компиляции и запуска приложений Go.

Dockerfile должен начинаться с инструкции `FROM`. В ней указывается родительский образ. Например, вам надо запустить проект, написанный на Go. Значит, инструкция `FROM` может выглядеть так:

Скопировать код

DOCKERFILE

```
FROM golang:1.20 
```

После двоеточия указана версия Go.

1. Чтобы упростить выполнение остальных команд, создайте каталог внутри создаваемого образа. Этот каталог указывает на то, что все последующие команды будут выполняться в нём. Для того чтобы указать рабочий каталог, используйте команду `WORKDIR`:


```
WORKDIR /app 
```

После команды `WORKDIR` указывается каталог `/app`, в котором будет размещаться ваше приложение.

Обычно при создании нового проекта первое, что нужно сделать, — создать модуль командой `go mod init`, который нужен для компиляции вашего проекта. А ещё существует команда `go mod download`, которая загружает все модули и пакеты, указанные в `go.mod` и `go.sum`. Но чтобы использовать `go mod download` внутри вашего образа, нужно скопировать в образ эти файлы. Для этого используется команда `COPY`.

1. Команда `COPY` может принимать несколько параметров. Первые параметры (кроме последнего) сообщают Docker, какие файлы скопировать в образ, а последний параметр — куда копировать эти файлы.

Чтобы скопировать файлы `go.mod` и `go.sum` в ваш созданный каталог `/app`, нужно выполнить команду `COPY` так:


```
COPY go.mod go.sum ./ 
```

Благодаря команде `WORKDIR` вы можете просто указать текущий каталог `./`, поскольку вы и так уже находитесь в `/app`.

1. Теперь, когда у вас есть файлы модуля внутри вашего нового образа, вы можете использовать команду `RUN` для запуска команды `go mod download`. Да-да, команда для запуска команды. Команда `RUN` запускает команды так, как будто вы делаете это в вашем терминале, только эти команды запускаются в Docker-образе.

```
RUN go mod download 
```

После выполнения команды `RUN go mod download` все модули Go, указанные в `go.mod` и `go.sum` будут установлены в каталог `/app`.

Ну вот. На данном этапе у вас есть набор инструментов Go версии 1.22 и все необходимые зависимости. И всё это уже внутри Docker-образа.

1. Далее нужно скопировать ваш исходный код в Docker-образ. Несложно догадаться, что для этой цели используется команда `COPY`.


```
COPY *.go ./ 
```

Здесь `*.go` означает все файлы с расширением `.go`, которые нужно скопировать в текущий каталог `./` внутри Docker-образа. Как вы помните, текущий каталог в Docker-образе у вас `/app`, благодаря `WORKDIR /app`. Подстановочный знак звездочка `*` используется для любого количества любых символов.

1. Теперь, чтобы скомпилировать ваше приложение, используйте знакомую команду `RUN`:

Скопировать код

DOCKERFILE

```
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o /my_app 
```

Разберём эту команду.

- Команда `RUN` запускает команды внутри Docker-образа.
    
- Далее идет `CGO_ENABLED=0`. Некоторые пакеты Go используют CGO «под капотом», используя распространенные библиотеки языка C для более широкой совместимости между средами и крайними случаями, которые могут встречаться во время выполнения программы. Эти распространенные библиотеки встречаются в большинстве дистрибутивов операционных систем, но могут быть не включены в ваш Docker-образ. По умолчанию `CGO_ENABLED=1`, поэтому его нужно отключать явно. Отключить эту поддержку можно как раз с помощью `CGO_ENABLED=0`, так как ваш образ, по сути, пуст.
    
- Для того, чтобы указать, что вы собираете ваш проект для Linux, вы указываете `GOOS=linux`. В Docker ваш пример можно собрать для разных ОС, но сейчас вам требуется собрать исполняемый файл для Linux, так как позже вы его будете запускать в контейнере. Если бы нужно было собрать ваш пример для Windows, то можно было написать `GOOS=windows`, для Mac OS X - `GOOS=darwin` и так далее.
    
- Также необходимо указать платформу, для которой будет компилироваться исполняемый файл вашего проекта. Здесь указано `amd64` — это обозначение 64-битной архитектуры центрального процессора, разработанной и внедренной компанией AMD.
    
- Следом идет команда `go build -o /my_app`, которая собирает ваше приложение в исполняемый файл `my_app`, расположенный в текущем каталоге `/app`.
    
- Теперь осталось сообщить, какую команду запускать, когда ваш Docker-образ используется для запуска контейнера.
    

Это делается с помощью команды `CMD`:

```
CMD ["/my_app"] 
```

В качестве аргумента для команды `CMD` выступает массив, в котором можно указать несколько команд для запуска. В этом случае ваш исполняемый файл приложения, который вы скомпилировали предыдущей командой `RUN`.

Вот полный файл Dockerfile:


```
FROM golang:1.20

WORKDIR /app

COPY go.mod go.sum ./

RUN go mod download

COPY *.go ./

RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o /my_app

CMD ["/my_app"] 
```

## Создаем Docker-образ

Теперь, когда у вас есть Dockerfile, создайте с помощью него Docker-образ. Для сборки Docker-образа используется команда `docker build`,которая использует Dockerfile и контекст. Контекст сборки — это набор файлов, расположенных по указанному пути. В вашем случае это все файлы вашего проекта.

Команда `docker build` может принимать необязательный флаг `--tag`. Этот флаг используется для строкового обозначения Docker-образа. Когда вы заходили в Docker Hub, вы могли видеть теги, связанные с Docker-образом. В случае если вы не обратили внимания на это, зайдите еще раз, посмотрите, какие теги используются в Docker-образе golang.

Если не указать тег с флагом `--tag`, то будет использоваться значение по умолчанию `latest`, т.е. "последний".

1. Итак, время создать ваш первый образ. В корневом каталоге вашего проекта выполните команду:

```
docker build --tag my-app:v1 . 
```

Здесь аргумент `my-app` - это имя Docker-образа, который вы создали. Через двоеточие `:` вы указали тег. Если его не указывать, то тег будет `latest`, что тоже неплохо. Далее вы указали, поставив точку, что контекстом будет всё, начиная с текущего каталога. Все файлы и папки будут включены в Docker-образ.

После выполнения команды сборки образа, Docker создаст Docker-образ. Вы будете видеть, как он выполняет команды, которые вы прописали в Dockerfile.

1. Когда образ будет создан, вы сможете посмотреть список всех локальных Docker-образов, выполнив команду в терминале:


```
docker image ls 
```

1. Протестируйте ваш новый образ и запустите контейнер из него. Чтобы запустить контейнер в фоновом режиме, выполните такую команду:


```
docker run -d -p 8080:8080 my-app:v1 
```

Обратите внимание, что при запуске контейнера через двоеточие нужно указать тег, иначе Docker будет искать тег `latest`, не найдет его и начнет ругаться. Поэтому укажите тег, который вы задали при сборке образа.

Опция `-d` здесь для того, чтобы после запуска контейнера, вы могли вернуться к командной строке, а контейнер продолжил выполняться в фоне.

Когда вы запустите контейнер из созданного вами образа, вы можете проверить, работает ваше приложение или нет. Зайдите в браузер и перейдите по `localhost:8080/tasks`. Программа должна будет вывести несколько задач из to-do листа.
