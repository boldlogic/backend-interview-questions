# Настройка автоматического деплоя с помощью GitHub

В прошлом уроке вы узнали как настраивать рабочие процессы (workflow). В этом уроке вы научитесь настраивать рабочий процесс для деплоя приложения с помощью GitHub Actions.

## О непрерывном развертывании с помощью GitHub Actions

**Непрерывное развертывание(CD)** — это автоматизация публикации и развертывания обновлений программного обеспечения.

Как в случае настройки рабочих процессов (workflow) для непрерывной интеграции(CI), вы можете настроить рабочий процесс для развертывания вашего приложения. Ваш рабочий процесс также может создать код и запустить тесты перед развертыванием.

Чтобы разобраться, в этом уроке вы на практике создадите рабочие процессы (workflow) для интеграции (CI) и развертывания (CD). Такой подход поможет увидеть весь процесс CI/CD от создания проекта до его развертывания. Вы также будете использовать Docker для создания и публикации Docker-образа в Docker Hub. Это поможет вам сложить пазл из всех знаний, которые вы получили в предыдущих уроках и в теме про Docker.

Чтобы пример не был слишком сложным, вы напишете простое приложение `Hello Go`. Когда вы освоитесь с GitHub Actions и Docker, и почувствуете уверенность в своих знаниях, вы можете попробовать настроить CI/CD и Docker для более сложных приложений.

## Создайте проект Go

1. Создайте каталог для вашего проекта и войдите в него:

Скопировать код

BASH

```
mkdir hello-golang
cd hello-golang 
```

2. Теперь создайте модуль Go:

Скопировать код

BASH

```
go mod init github.com/<ваше имя в GitHub>/hello-golang 
```

3. Создайте файл `main.go`:

Скопировать код

BASH

```
touch main.go 
```

Откройте `main.go` и вставьте код:

Скопировать код

GO

```
package main

import "fmt"

func main() {
    fmt.Println(hello())
}

func hello() string {
    return "Hello go"
} 
```

4. Теперь создайте файл тестов `main_test.go`, чтобы посмотреть, как запускать тесты при развертывании приложения.

Скопировать код

BASH

```
touch main_test.go 
```

5. Вставьте в `main_test.go` следующий код:

Скопировать код

GO

```
package main

import "testing"

func TestHello(t *testing.T) {
    want := "Hello Go"

    got := hello()

    if want != got {
        t.Fatalf("want %s, got %s\n", want, got)
    }
} 
```

Если вы заметили, строка, возвращаемая функцией `hello()`, не совпадает со строкой `Hello Go`. Это сделано намеренно, чтобы продемонстрировать, как пайплайн CI/CD ловит ошибки, когда тесты не проходят. Позже вы исправите это недоразумение.

6. Убедитесь, что тесты не проходят:

Скопировать код

BASH

```
go test
--- FAIL: TestHello (0.00s)
    main_test.go:11: want Hello Go, got Hello go
FAIL
exit status 1 
```

7. Проверьте, работает ли приложение:

Скопировать код

BASH

```
go run main.go
Hello go 
```

## Создайте репозиторий на GitHub

Чтобы работать с GitHub Actions, нужно создать репозиторий для вашего приложения на Github. Зайдите в свою учетную запись GitHub и создайте новый репозиторий. Вы можете дать ему такое же имя, как имя приложения `hello-golang`, и сделать репозиторий публичным.

Прежде чем продолжить, нужно узнать кое-что о секретах.

## По секрету о секретах

Секреты (secrets) позволяют хранить конфиденциальную информацию. Созданные вами секреты доступны для использования в рабочих процессах GitHub Actions. GitHub Actions могут прочитать секрет, когда вы его явно включите в рабочий процесс.

Вы будете разворачивать свой проект в Docker Hub, поэтому вам нужен будет токен доступа к Docker Hub, который вы добавите в секреты GitHub Actions.

Вот как создать токен доступа к Docker Hub для своего репозитория:

## Создаем рабочий процесс (workflow)

Вы готовы к созданию рабочего процесса Github:

1. Создайте каталог `.github/workflows` и добавьте файл `push.yaml`:

Скопировать код

BASH

```
mkdir -p .github/workflows
touch .github/workflows/push.yaml 
```

2. Теперь добавьте конфигурацию в файл `push.yaml`:

Скопировать код

YAML

```
name: golang-pipeline
on: push
jobs:
  test:
    runs-on: ubuntu-latest
    container: golang:1.22
    steps:
      - uses: actions/checkout@v4

      - name: Run Unit Tests
        run: GOOS=linux GOARCH=amd64 go test

      - name: Vet
        run: |
          go vet ./... 
```

Отдельно о каждом ключе в файле:

- `name: golang-pipeline`. Имя рабочего процесса, которое будет отображаться на вкладке Actions репозитория.
    
- `on: push`. Указывает, какие события могут вызывать запуск рабочего процесса. Запуск рабочего процесса происходит каждый раз, когда кто-то отправляет изменение в репозиторий или объединяет запрос на извлечение. Это происходит при отправке в любую ветку.
    
- `jobs:`. Группирует все задания, которые выполняются в рабочем процессе `golang-pipeline`.
    
- `test:`. Определяет задание `test`. Дочерние ключи будут определять свойства этого задания.
    
- `runs-on: ubuntu-latest`. Настраивает задание `test` для запуска в последней версии Ubuntu Linux runner. Задание будет выполняться на новой виртуальной машине GitHub.
    
- `container: golang:1.22`. Добавляет и запускает Docker-контейнер `golang:1.22` для запуска тестов.
    
- `steps:`. Шаги задания.
    
- `- uses: actions/checkout@v4`. Это действие проверяет ваш репозиторий, чтобы ваш рабочий процесс мог получить к нему доступ. Используйте последнюю версию 4. [Ссылка](https://github.com/marketplace/actions/checkout) на страничку этой версии в маркетплейсе GitHub.
    
- `- name: Run Unit Tests`. Имя шага.
    
- `run: GOOS=linux GOARCH=amd64 go test`. Команда для запуска. Она запускает Go тесты, которые вы написали.
    
- `- name: Vet`. Первый шаг будет запускать команду `go vet`, чтобы проверить код на наличие ошибок. Шаг так и будет называться - `Vet`.
    
- `- run: go vet`. Запускает команду `go vet`.
    

Пора запушить ваш проект на GitHub и проверить, запустится ли рабочий процесс. Если вы помните, в самом начале вы специально сделали ошибку, чтобы тесты не прошли. Посмотрите, как это будет выглядеть — исправите потом.

Для того, чтобы запушить свой проект на GitHub, перейдите на главную страницу (вкладка `Code`) вашего репозитория. Там вы можете увидеть команды `git`. Некоторые из них вам нужно будет ввести в своем терминале в каталоге вашего проекта.

3. Подтвердите изменения — в кавычках введите сообщение, кратко описывающее коммит, например "first commit":

Скопировать код

Скопировать код

Если все успешно, значит пора переходить к настройке вашего файла рабочего процесса `push.yaml` для публикации проекта на DockerHub. Но сначала нужно создать `Dockerfile`, с помощью которого вы соберете Docker-образ.

## Dockerfile для Docker-образа

1. Создайте `Dockerfile` в корневом каталоге проекта:

Скопировать код

BASH

```
touch Dockerfile 
```

2. Добавьте в него следующие строки:

Скопировать код

DOCKERFILE

```

COPY . .

```

Теперь соберите образ, чтобы убедиться, что всё работает:

Скопировать код

```

```

Скопировать код

BASH

```
docker run golang-hello:v1.0.0

```

Вы убедились, что образ Docker собирается и из него успешно запускается контейнер. Можно переходить к созданию задания по деплою вашего проекта.

## Новое задание

Откройте в редакторе файл `push.yaml` и добавьте новое задание `deploy`:

Скопировать код

YAML

```
name: golang-pipeline
on: push
jobs:
  test:
    runs-on: ubuntu-latest
    container: golang:1.22
    steps:
      - uses: actions/checkout@v4

      - name: Run Unit Tests
        run: GOOS=linux GOARCH=amd64 go test

      - name: Vet
        run: |
          go vet ./...

  deploy:
    name: Push Docker image to Docker Hub
    runs-on: ubuntu-latest
    needs: test
    if: startsWith(github.ref, 'refs/tags')
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Docker buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_ACCESS_TOKEN }}

      - name: Extract metadata (tags, labels) for Docker
        id: meta
        uses: docker/metadata-action@v5.5.1
        with:
          images: <Docker ID>/hello-golang

      - name: Build and push Docker Image
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }} 
```

Вот что нужно знать о конфигурации задания `deploy`:

- `deploy:`. Как вы уже догадались, это название задания.
    
- `name: Push Docker image to Docker Hub`. Эта строка будет выводиться как заголовок задания в GitHub Actions.
    
- `needs: test`. Задание `deploy` запустится только после успешного завершения задания `test`.
    
- `if: startsWith(github.ref, 'refs/tags')`. Задание `deploy` запустится только в случае указания тега для коммита, который вы пушите в GitHub. Чуть ниже будет наглядный пример.
    
- `uses: docker/setup-buildx-action@v3`. Действие GitHub для настройки Docker Buildx. Это действие создаст и загрузит конструктор, который можно использовать на следующих этапах вашего рабочего процесса, например, для сборки образа Docker. Версия 3 - самая последняя. Вот [ссылка на документацию действия](https://github.com/marketplace/actions/docker-setup-buildx).
    
- `uses: docker/login-action@v3`. Действие GitHub для входа в DockerHub. Используем последнюю 3 версию. [Ссылка в Маркетплейсе GitHub](https://github.com/marketplace/actions/docker-login).
    
- `username: ${{ secrets.DOCKER_USERNAME }}`. Имя пользователя DockerHub, которое вы добавляли в секреты. Теперь вы получаете значение секрета, обращаясь к нему по имени `DOCKER_USERNAME`.
    
- `password: ${{ secrets.DOCKER_ACCESS_TOKEN }}`. Токен, который вы генерировали в DockerHub, а потом сохранили в секретах репозитория.
    
- `uses: docker/metadata-action@v5.5.1`. Действие GitHub для получения метаданных для DockerHub, например тегов или меток. Это нужно для того, чтобы добавить тег к имени образа вашего приложения в DockerHub. Вспомните ваше приложение `todo-list:v1`. Используем последнюю версию 5.5.1. [Посмотреть документацию по этому действию можно здесь](https://github.com/marketplace/actions/docker-metadata-action).
    
- `images: <Docker ID>/hello-golang`. Имя вашего Docker-образа, который вы будете пушить в DockerHub. Вместо `<Docker ID>` вам нужно вставить ваш Docker ID.
    
- `uses: docker/build-push-action@v5`. Действие GitHub для сборки Docker образа и отправки его в DockerHub. Последняя версия 5. [Ссылка на страницу действия в Marketplace GitHub](https://github.com/marketplace/actions/build-and-push-docker-images).
    
- `context: .`. Контекст для сборки образа. В данном случае текущий каталог. Вспомните урок по Docker, когда вы собирали Docker-образы.
    
- `push: true`. Говорит о том, что при успешной сборке образа, нужно будет запушить его в DockerHub.
    
- `tags: ${{ steps.meta.outputs.tags }}`. Из шага выше, которому присвоен id meta, получает тег, чтобы добавить его к имени вашего образа.
    
- `labels: ${{ steps.meta.outputs.labels }}`. Из шага выше, которому присвоен id meta, получает метку, чтобы добавить её к вашему образу. Но у вас меток нет.
    

Давайте сначала запушим изменения без тега, чтобы убедиться, что задача `deploy` не запустится. Для этого в вашем терминале выполните следующие команды:

Скопировать код

BASH

```
git add .
git commit -m "finish push.yaml"
git push 
```

И сразу переходите в репозиторий проекта на GitHub во вкладку `Actions`. Там нажмите на `finish push.yaml`. Вы увидите, что задание `test` уже запустилось.

Но задание `deploy` так и не было запущено, хоть тесты прошли успешно. Так было задумано. Пока вы не добавите тег с версией, который в последствии добавится к имени вашего Docker-образа, задание `deploy` запускаться не будет.

Прежде чем добавлять тег с версией, нужно создать репозиторий на DockerHub. Зайдите в свой аккаунт Docker Hub и создайте репозиторий. Назовите его `hello-golang`. Когда вы добавите тег к вашему коммиту, вы cможете публиковать свой проект в DockerHub.

Давайте добавим тег с версией, чтобы автоматически создался образ и запушился в DockerHub.

В терминале введите следующие команды:

Скопировать код

BASH

```
git tag v1.0.0
git push --tags 
```

Первая команда добавляет тег с версией в текущий коммит. А вторая пушит его в GitHub.

Откройте репозиторий проекта на GitHub, вкладку `Actions`. Вы можете увидеть, что снова запустился `test`, так как без него `deploy` запуститься не может. Когда `test` завершился успешно, сразу же запустилось задание `deploy`. Вы можете нажать на это задание, чтобы посмотреть все процессы.

Когда задание `deploy` завершится, перейдите на страницу вашего репозитория `hello-golang` в DockerHub и обновите ее. Вы можете увидеть, что появилась новая версия вашего Docker-образа в DockerHub.

## Запуск контейнера из DockerHub

Не лишним будет проверить и запустить контейнер из вашего репозитория на DockerHub. Для этого введите команду ниже:

Скопировать код

BASH

```
docker pull --platform linux/x86_64 <Ваш Docker ID>/hello-golang 
```

Скачается последняя версия вашего образа. Если у вас несколько версий образа `hello-golang`, вы можете указать, которая вам нужна, например:

Скопировать код

BASH

```
docker pull --platform linux/x86_64 <Ваш Docker ID>/hello-golang:1.0.0 
```

Флаг `--platform linux/x86_64` указывает для какой платформы вы скачиваете образ. Если не указать платформу, некоторые пользователи, особенно пользователи Mac на процессорах M1, M2 и т.д. могут столкнуться с такой ошибкой:

Скопировать код

BASH

```
docker: no matching manifest for linux/arm64/v8 in the manifest list entries.
See 'docker run --help'. 
```

Теперь запустите контейнер из образа:

Скопировать код

BASH

```
docker run --platform linux/x86_64 <Ваш Docker ID>/hello-golang
Hello Go 
```

Вывелось ожидаемое сообщение. Значит все работает.
