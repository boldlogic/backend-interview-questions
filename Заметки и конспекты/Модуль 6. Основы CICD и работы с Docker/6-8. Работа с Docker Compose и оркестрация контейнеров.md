## Создание проекта

1. Создайте каталог там, где у вас находятся проекты на Go. Обычно путь до проектов на Go выглядит так: `github.com/<ваше имя на GitHub>/<имя проекта Go>`. Создайте каталог проекта и войдите в него:

Скопировать код

```

```

Эта команда добавит файл `go.mod` в каталог проекта.

3. Добавьте файлы `Dockerfile` и `compose.yaml` в корень проекта:

Скопировать код

BASH

```

touch compose.yaml 
```

#### **Развитие Dockerfile**

4. Добавьте информацию в `Dockerfile`. Укажите:
    
    - версию Go с помощью команды `FROM`. Вы будете создавать контейнер из официального образа `golang` версии Go 1.21.0. Указание версии гарантирует, что среда разработки будет всегда одинаковой;
    - рабочий каталог приложения с помощью команды `WORKDIR`. Контейнеры докер работают в Linux, поэтому этой командой вы говорите, что ваше приложение будет находиться в каталоге файловой системы Linux `/usr/src` в папке проекта `app`.

Вот как указать всю нужную информацию:

Скопировать код

DOCKERFILE

```

```

Позже вы продолжите развивать `Dockerfile`, но пока этого достаточно.

#### **Начальная конфигурация файла compose.yaml**

Если бы приложению требовалась только одна служба, можно было бы обойтись только файлом `Dockerfile`. Однако, вы собираетесь добавить службу для базы данных Postgres. Поэтому для управления коллекцией контейнеров нужен файл `compose.yaml`.

5. Настройте службу `web`. В этой службе будет настроено веб-приложение, которое вы запускали на прошлых уроках:

Скопировать код

YAML

```
services:
  web:
    build: .
    ports:
      - "3000:3000"
    volumes:
      - .:/usr/src/app 
```

Вспомните, что означает каждый из ключей в файле `Compose`:

- `services` — за этим ключом следуют описания служб;
- `web` — название службы, где находится веб-приложение TODO-LIST;
- `build` — здесь указан путь к `Dockerfile` для текущей службы. Так как ваш `Dockerfile` находится в той же папке, что и файл `compose.yaml`, вы указываете точку `.`;
- `ports` — этот ключ сопоставляет порт контейнера с портом вашего компьютера. Пусть ваше приложение будет работать на порту 3000;
- `volumes` — в тома сохраняются данные, которые генерирует ваша служба; ваш веб-сервис будет сохранять все данные в каталоге проекта `/usr/src/app`.

Здесь вы можете вводить различные команды так, как будто вы находитесь в терминале Linux. Например, можете проверить версию Go, которая установлена в контейнере:

Запомните разницу между Dockerfile и compose.yaml

`Dockerfile` содержит набор команд для настройки контейнера. Этот процесс похож на настройку нового компьютера для разработки, где вы будете использовать опредёленные языки программирования и технологии. Файл `compose.yaml` — это файл конфигурации, который управляет всеми вашими контейнерами. Это единый менеджер для всех контейнеров в проекте.

## Добавление кода веб-сервиса в проект

Если приложение небольшое, для работы с базой данных иногда удобно использовать библиотеки для ORM. **ORM** — (англ. Object Relational Mapping — «объектно-реляционное отображение») комплекс программ, позволяющих работать с базами данных, как с объектами языка программирования. Если упростить, то вместо запросов к базе данных, например, таких: `SELECT * FROM users ORDER BY id LIMIT 1;`, можно использовать готовые методы для языка Go; они могут выглядеть так `db.First(&user)`, где `user` — это экземпляр структуры языка Go, которые будут представлять сущности (объекты) вашей базы данных. Так как наш урок посвящен Docker Compose, мы не будем погружать вас в эту тему слишком глубоко. Сейчас главное, чтобы был работающий код и понимание, как настроить приложение для запуска в Docker Compose.

1. Создайте папку `models` в корне вашего проекта и файл `models.go`:

Скопировать код

Пояснения к коду:

```
// database/database.go
package database

import (
    "fmt"
    "log"
    "os"

    "github.com/<ваше имя на GitHub>/todo-list/models"
    "gorm.io/driver/postgres"
    "gorm.io/gorm"
    "gorm.io/gorm/logger"
)

type Dbinstance struct {
    Db *gorm.DB
}

var DB Dbinstance

func ConnectDB() {
    // создаём URL для соединения с базой данных. 
    // Имя пользователя базы данных, пароль и имя базы данных
    // берутся из переменных окружения,
    // они описаны в файле .env
    dsn := fmt.Sprintf(
        "host=db user=%s password=%s dbname=%s port=5432 sslmode=disable TimeZone=Europe/Moscow",
        os.Getenv("DB_USER"),
        os.Getenv("DB_PASSWORD"),
        os.Getenv("DB_NAME"),
    )
    // создаём подключение к базе данных.
    // В &gorm.Config настраивается логер,
    // который будет сохранять информацию
    // обо всех активностях с базой данных.
    db, err := gorm.Open(postgres.Open(dsn), &gorm.Config{
        Logger: logger.Default.LogMode(logger.Info),
    })

    if err != nil {
        log.Fatal("Failed to connect to database.\n", err)
        os.Exit(1)
    }

    log.Println("connected")
    db.Logger = logger.Default.LogMode(logger.Info)

    log.Println("running migration")
    db.AutoMigrate(&models.Task{})

    DB = Dbinstance{
        Db: db,
    }
} 
```

Пояснения к коду:

- создана структура `Dbinstance` для представления базы данных:

Скопировать код

GO

```
type Dbinstance struct {
    Db *gorm.DB
} 
```

- создана новая переменная уровня пакета для базы данных, чтобы была возможность получить к ней доступ везде в вашем приложении:

Скопировать код

GO

```

```

- создана функция `ConnectDb()` для подключения вашего приложения к базе данных.

```
import (
    "fmt"
    "net/http"

    "github.com/go-chi/chi/v5"
    "github.com/<ваше имя на GitHub>/todo-list/database"
    "github.com/<ваше имя на GitHub>/todo-list/handlers"

    r.Get("/tasks", handlers.GetTasks)
    r.Post("/tasks", handlers.PostTask)
    r.Get("/tasks/{id}", handlers.GetTaskByID)
```

- в основном файле приложения импортированы пакеты `database` и `handlers`. Замените `<ваше имя на GitHub>` на своё имя каталога, чтобы путь к пакетам был правильным:

В редакторе добавьте следующий код в файл `handlers.go`.

Скопировать код

GO

```
// handlers/handlers.go
package handlers

import (
    "bytes"
    "encoding/json"
    "errors"
    "log"
    "net/http"
    "strconv"

    "github.com/<ваше имя на GitHub>/todo-list/database"
    "github.com/<ваше имя на GitHub>/todo-list/models"
    "github.com/go-chi/chi/v5"
    "gorm.io/gorm" 
)

func GetTasks(w http.ResponseWriter, r *http.Request) {
    tasks := []models.Task{}

    resultDB := database.DB.Db.Find(&tasks)
    if resultDB.Error != nil {
        http.Error(w, resultDB.Error.Error(), http.StatusBadRequest)
        return
    }

    resp, err := json.Marshal(tasks)
    if err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusOK)
    w.Write(resp)
}

func PostTask(w http.ResponseWriter, r *http.Request) {
    task := new(models.Task)
    var buf bytes.Buffer

    _, err := buf.ReadFrom(r.Body)
    if err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    if err = json.Unmarshal(buf.Bytes(), &task); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    log.Println(task)

    resultDB := database.DB.Db.Create(&task)
    if resultDB.Error != nil {
        http.Error(w, resultDB.Error.Error(), http.StatusBadRequest)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)
}

func GetTaskByID(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(chi.URLParam(r, "id"))
    if err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    task := new(models.Task)

    resultDB := database.DB.Db.First(&task, id)
    if resultDB.Error != nil {
        http.Error(w, resultDB.Error.Error(), http.StatusBadRequest)
        return
    }

    resp, err := json.Marshal(task)
    if err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusOK)
    w.Write(resp)
}

func DeleteTask(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(chi.URLParam(r, "id"))
    if err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    resultDB := database.DB.Db.Delete(&models.Task{}, id)
    if resultDB.Error != nil {
        http.Error(w, resultDB.Error.Error(), http.StatusBadRequest)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusOK)
}
```

В коде выше описано четыре обработчика:

1. `GetTasks()` — запрашивает все задачи, которые были созданы.
2. `PostTask()` — добавляет задачу.
3. `GetTaskByID()` — запрашивает задачу по её ID.
4. `DeleteTask()` — удаляет задачу по её ID.

Все обработчики взаимодействуют с базой данных с помощью методов `Find()`, `Create()`, `First()` и `Delete()`.
